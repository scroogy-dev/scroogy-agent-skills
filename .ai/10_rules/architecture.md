# 아키텍처

## 디자인 원칙

### 원칙

결정적으로 표현할 수 있는 로직은 AI 추론에 맡기지 않고 스크립트로 옮긴다.

근거는 네 가지다.

- **재현성**: 같은 입력에 같은 출력이 나온다. 추론 결과는 세션·모델·문맥에 따라 흔들린다.
- **검증 가능성**: 결과를 명령으로 판정할 수 있어 이슈 완료 기준을 `[D]`로 쓸 수 있다.
- **토큰 비용**: 스크립트 호출은 컨텍스트를 소비하지 않는다. 같은 판정을 매번 추론으로 하면 호출마다 비용이 든다.
- **실패 지점의 국소화**: 스크립트가 틀리면 그 파일만 보면 된다. 추론이 틀리면 원인이 프롬프트·컨텍스트·모델에 흩어진다.

### 역할 분담

스킬 디렉토리의 각 위치가 담는 것을 아래로 고정한다.

| 위치 | 담는 것 | 담지 않는 것 |
|------|---------|--------------|
| `scripts/` | 같은 입력에 같은 출력이 나와야 하는 로직. 판정은 종료 코드(exit code)나 표준 출력으로 낸다 | 자연어 해석, 맥락 판단 |
| `SKILL.md` | 호출 순서 조율과 판단. 어떤 스크립트를 언제 부르고 결과를 어떻게 해석할지 | 스크립트로 옮길 수 있는 반복 판정 로직 |
| `references/` | 조회용 데이터. 절차 상세, 분류표, 예시 | 실행 로직 |
| `templates/` | 산출물 골격 | 실행 로직 |
| `tests/` | `scripts/`의 회귀 검증. 배치는 ADR 0001을 따른다 | 배포 대상 파일 |

### 판단 체크리스트

아래 네 문항으로 스크립트 분리 여부를 정한다.

1. 같은 입력에 같은 출력이 보장돼야 하는가 (**필수**)
2. 한 세션에서 여러 번 반복 호출되는가
3. 결과를 기계로 검증할 수 있는가
4. 실패했을 때 명확한 오류가 나와야 하는가

- **통과 기준**: 1번을 만족하고 2~4번 중 두 문항 이상을 만족하면 `scripts/`로 분리한다.
- **임계 수치**: 반복 호출 횟수나 조건 분기 개수를 숫자로 고정하지 않는다. 스킬마다 호출의 단위와 분기의 무게가 달라 같은 숫자가 다른 뜻이 되고, 숫자를 두면 기준을 넘기려고 로직을 쪼개거나 기준 아래로 눌러 회피하는 형식 충족이 생긴다. 위 통과 기준의 문항 수는 판정을 재현하기 위한 값이며, 대상 로직의 규모를 재는 수치와 별개다.

### 예외

아래는 체크리스트를 적용하지 않고 `SKILL.md`의 추론에 남긴다.

- 자연어 해석
- 모호성 해소
- 맥락에 따른 우선순위 판단

조건 분기가 과하게 늘어나는 경우도 예외다. 분기를 전부 코드로 옮기면 유지 비용이 추론 비용을 넘어선다. 이때는 스크립트를 만들지 않고 판단 근거만 `SKILL.md`에 남긴다.

### 기존 체계와의 관계

- **ADR 0001** ([결정적 헬퍼의 테스트 동일 위치 배치 규칙](../50_adr/active/0001-skill-deterministic-helper-test-convention.md)): 헬퍼가 도입될 때의 배치·러너·배포 제외를 정하는 조건절 규칙이다. 본문은 그대로 두고, 이 섹션이 그 위에 도입 여부를 정하는 규칙을 얹는다. 체크리스트로 분리를 결정하면 배치는 ADR 0001을 따른다.
- **검증 레벨 `[D]`·`[QD]`·`[ND]`**: `issue-work` 템플릿이 이슈 완료 기준의 검증 강도를 나누는 축이다. 체크리스트를 통과한 절차는 완료 기준을 `[D]`로 쓸 수 있다. 통과하지 못한 절차는 `[QD]` 또는 `[ND]`로 두고 강등 사유를 함께 적는다.

두 체계는 적용 대상이 다르다. ADR 0001과 이 섹션은 스킬 구현 방식을 정하고, 검증 레벨은 이슈 완료 기준의 검증 방식을 정한다. 같은 축에 놓되 적용 지점을 섞지 않는다.
