# K-0055: issue-work의 바뀌었는지 판별이 일반 Task가 고친 원장 파일이면 다른 행의 변경까지 구현 변경으로 센다

- **유형**: known issue
- **등재일**: 2026-11-28
- **출처**: 이슈 #150 / 3회차 Task N 들어가기 전 판별 (사용자 판단으로 예외 처리)
- **위험도**: 낮음(LOW)
- **수용 사유**: 판별 결과를 보여 주면 사용자가 예외로 볼지 정할 수 있어 잘못된 마무리로 이어지지 않는다. 판별을 행 단위로 바꾸려면 issue-work SKILL.md의 `바뀌었는지의 판별`과 그 조항 검사를 함께 고쳐야 해 이슈 #150 범위 밖이다.
- **재검토 조건**: 같은 원인으로 감사를 다시 받거나 예외 판단을 다시 하게 된 사례가 또 관측될 때, 또는 issue-work `### 구현 검증`의 `바뀌었는지의 판별` 조항을 고칠 때
- **상태**: 수용

## 내용

issue-work `### 구현 검증`의 `바뀌었는지의 판별`은 `.ai/70_ledger/` 아래 변경을 이슈 작업 기록으로 보고 세지 않는다. 다만 plan 일반 Task가 고친다고 적은 파일은 이 예외에서 뺀다. 판별이 파일 단위라, 일반 Task가 `.ai/70_ledger/index.md`처럼 여러 항목이 함께 쓰는 파일을 고친 이슈에서는 마지막 교차 감사 뒤 `--response`로 다른 원장 항목의 행을 더하기만 해도 구현이 바뀐 것으로 판별된다. 이때 규칙을 그대로 따르면 감사를 한 번 더 받아야 한다.
