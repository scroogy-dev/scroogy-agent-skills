# K-0024: git-review-quiz 브랜치 모드 산출 파일 이름이 치환 뒤 같아지는 두 브랜치를 구분하지 못한다

- **유형**: known issue
- **등재일**: 2026-11-03
- **출처**: 이슈 #132 계획 감사 발견 F-4
- **위험도**: 중간(MEDIUM)
- **수용 사유**: 이름이 같아지는 두 브랜치(`feature/a`·`feature-a`)가 한 저장소에 함께 있고, `--clear` 전에 둘 다 브랜치 모드로 퀴즈를 만들 때만 생긴다. 덮어써지는 것은 다시 만들 수 있는 `99_workspace` 임시 산출물이다. 고치려면 치환이 일어난 이름에 원래 브랜치 이름의 해시를 붙여야 하는데, `feature/x`처럼 `/`가 든 흔한 브랜치 이름마다 접미어가 붙어 파일 이름을 읽기 어려워진다.
- **재검토 조건**: 브랜치 모드 산출물이 다른 브랜치의 산출물을 덮어쓴 사례 관측 시, 또는 git-review-quiz 산출 파일 이름 규칙(브랜치 이름 치환 문자 집합·접두어) 변경 시
- **상태**: 수용

## 내용

git-review-quiz 브랜치 모드는 산출 이름 `temp_review_quiz_branch-<브랜치 이름>.md`(HTML은 확장자만 `.html`)를 쓰며, 브랜치 이름에서 `[A-Za-z0-9._-]` 밖의 문자를 `-`로 바꾼다. 이 치환은 일대일이 아니어서 `feature/a`와 `feature-a`가 모두 `temp_review_quiz_branch-feature-a`가 되고, 뒤에 실행한 대상이 앞선 대상의 md·HTML을 덮어쓴다. 이 경우는 "다른 대상을 실행해도 앞선 대상의 파일이 남는다"(이슈 #132 AC10)는 보장에서 빠진다.

## 재검토 이력

- **영향**: 스펙·기능 달성 차단. 충돌하는 두 브랜치 사이에서는 AC10의 대상별 보존이 성립하지 않는다.

- **위험도 산출**: `classify-risk.sh --impact '스펙·기능 달성 차단' --likelihood '특수 조건·엣지'` → 중간(MEDIUM).
- **채택하지 않은 대안**: 치환이 일어난 이름에만 `printf '%s' "<브랜치 이름>" | git hash-object --stdin`의 앞 7자를 붙이는 안. 충돌은 사실상 사라지지만 위 수용 사유대로 이름 가독성을 잃는다. 퍼센트 인코딩은 일대일이지만 파일 URL에서 `%2F`가 `/`로 풀려 HTML을 열 때 경로가 깨진다.
- 이슈 #132 spec 전제 `산출 파일 이름`에 이 한계를 적었다.
