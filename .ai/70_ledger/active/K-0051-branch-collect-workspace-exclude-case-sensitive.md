# K-0051: 브랜치 모드 수집 헬퍼의 작업공간 제외가 대소문자를 구분해 대소문자가 다른 작업공간 디렉토리의 미추적 파일을 모은다

- **유형**: known issue
- **등재일**: 2026-11-28
- **출처**: 이슈 #150 / audit 발견 F-1 (최종 감사 1차, GPT-6.2)
- **위험도**: 낮음(LOW)
- **수용 사유**: 저장소의 스킬은 모두 작업공간 디렉토리를 소문자 `.ai/99_workspace`로 만들어, 사용자가 대소문자를 다르게 직접 만든 저장소에서만 나타난다. 퀴즈와 리뷰는 수행되고 이전 산출 파일이 입력에 더 섞이는 정도다. 고치려면 git-review 원본 헬퍼의 코드를 바꿔야 해서, 원본은 주석만 바꾸기로 한 이슈 #150 범위(D6)를 넘는다.
- **재검토 조건**: 작업공간 디렉토리 이름의 대소문자가 달라 이전 퀴즈·리뷰 산출물이 수집된 사례 관측 시, ai-workspace 등 스킬이 작업공간 디렉토리를 만드는 이름을 바꿀 때, 또는 `collect-branch-changes.sh`의 `git add -A` 경로 조건(`:(top,exclude).ai/99_workspace`)을 바꿀 때
- **상태**: 수용

## 내용

git-review와 git-review-quiz 브랜치 모드의 수집 헬퍼 `collect-branch-changes.sh`(두 스킬에 바이트 단위로 같은 사본)는 `git add -A`의 경로 조건 `:(top,exclude).ai/99_workspace`로 작업공간의 미추적 파일을 뺀다. 이 경로 조건은 대소문자를 구분하므로, macOS처럼 대소문자를 구분하지 않는 볼륨에서 디스크의 디렉토리가 `.ai/99_WORKSPACE`처럼 다른 표기이면 스킬이 `.ai/99_workspace/`로 쓴 파일이 Git의 실제 표기로 목록과 patch에 들어간다. 디렉토리가 소문자이면 정상으로 빠진다.

- **관측**: 2026-11-28 임시 저장소(Apple Git 2.50.1, `core.ignorecase=true`)에서 `.ai/99_WORKSPACE`를 만들고 `.ai/99_workspace/temp_review_quiz_branch-feat.md`로 파일을 쓴 뒤 `--base`로 수집했다. 목록에 `A	.ai/99_WORKSPACE/temp_review_quiz_branch-feat.md`가, patch에 파일 내용이 들어갔다. 소문자 디렉토리에서는 빠졌다.
