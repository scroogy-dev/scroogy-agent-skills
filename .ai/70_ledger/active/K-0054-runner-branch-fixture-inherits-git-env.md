# K-0054: 퀴즈·리뷰 러너의 브랜치 수집 fixture가 물려받은 Git 환경 변수로 호출한 쪽 저장소의 인덱스에 쓴다

- **유형**: known issue
- **등재일**: 2026-11-28
- **출처**: 이슈 #150 / audit 발견 F-8 (최종 감사 4차, GPT-6.2)
- **위험도**: 중간(MEDIUM)
- **수용 사유**: 호출한 쪽 환경에 `GIT_INDEX_FILE`·`GIT_DIR`·`GIT_WORK_TREE`가 있을 때만 나타난다. Git 훅 안에서 러너를 부르는 경우가 그 예다. 이 저장소에는 훅도 러너를 부르는 CI도 없고, 러너는 사람이나 AI가 셸에서 직접 실행한다. 같은 준비 코드가 이슈 #150 전부터 git-review 러너에 있어 퀴즈 러너만 고치면 한쪽이 남는다. 두 러너를 함께 고치는 일은 이슈 #150 범위 밖이다.
- **재검토 조건**: 두 러너 가운데 하나를 Git 훅·CI 등 Git 환경 변수가 설정되는 곳에서 부르게 될 때, 러너 실행 뒤 인덱스나 스테이징 상태가 바뀐 사례 관측 시, 또는 두 러너의 Git 준비 절(`GIT_CONFIG_NOSYSTEM`·`GIT_CEILING_DIRECTORIES`를 내보내는 곳)을 고칠 때
- **상태**: 수용

## 내용

`git-review-quiz/tests/run-tests.sh`와 `git-review/tests/run-tests.sh`의 브랜치 수집 절은 전역·시스템 설정과 상위 저장소 탐색만 막는다. `GIT_INDEX_FILE`·`GIT_DIR`·`GIT_WORK_TREE`는 비우지 않는다. fixture를 만드는 `newrepo`·`g`는 `git -C <임시 저장소>`로 부르지만, `-C`는 작업 디렉토리만 바꾸고 이 변수들은 그대로 따른다. 그래서 이 변수가 넘어온 상태로 러너를 실행하면 fixture의 `git add -A`가 바깥 인덱스에 기록되고, 러너는 실패 없이 끝난다.
