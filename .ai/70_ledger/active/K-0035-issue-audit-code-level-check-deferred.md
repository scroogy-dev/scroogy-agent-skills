# K-0035: issue-audit 2단계에 git-review의 코드 레벨 검증 보강이 없다

- **유형**: 기술부채
- **등재일**: 2026-11-22
- **출처**: 이슈 #142 (spec 제외 보류 항목)
- **위험도**: 중간(MEDIUM)
- **수용 사유**: 이슈 #142가 만든 코드 레벨 검증(변경 줄을 빠짐없이 읽기, 확인 관점 목록, 실패 시나리오, 인용 위치 재확인)을 git-review에서 먼저 써 본 뒤 판단하기로 했다. issue-audit는 스펙 대조가 주된 역할이라 보강의 효과와 비용을 git-review 사용 결과로 먼저 본다.
- **재검토 조건**: git-review의 코드 레벨 검증을 실제 PR 리뷰에 여러 번 써 본 뒤, issue-audit 최종 감사가 놓친 코드 결함이 git-review나 다른 리뷰에서 나온 사례 관측 시, 또는 issue-audit 2단계(비판적 검증) 절차를 실질 변경할 때
- **상태**: 수용

## 내용

issue-audit 최종 감사 2단계에는 git-review 테크 리뷰 2단계의 변경 줄 읽기와 확인 관점 목록, 발견 처리의 실패 시나리오와 인용 위치 재확인이 없다. 같은 브랜치를 두 스킬로 보면 코드 결함을 찾는 기준이 다르다.

## 재검토 이력

- 2026-11-25 이슈 #145 최종 감사 1차 F-6: 재검토 조건(2단계 절차의 실질 변경)에 닿아 이번 이슈에서 반영하기로 했다(R27). issue-audit 2단계에 변경 줄 읽기·확인 관점·인용 위치 재확인·실패 시나리오를 두어 원인이 사라졌다. 해소는 PR 번호를 알 때 git-pr 원장 대조로 적는다.
