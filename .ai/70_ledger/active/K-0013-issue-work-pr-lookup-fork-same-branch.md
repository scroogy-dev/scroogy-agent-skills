# K-0013: issue-work 원장 해소 기재의 PR 조회가 head 저장소를 대조하지 않아 같은 브랜치명의 포크 PR을 고를 수 있다

- **유형**: known issue
- **등재일**: 2026-10-10
- **출처**: PR #111 코멘트 스레드
- **위험도**: 낮음(LOW)
- **수용 사유**: 같은 브랜치명의 포크 PR이 열려 있고 그 시점에 자기 PR은 아직 없어야 발생하므로 개인 저장소에서 발생확률이 낮다. 두 PR이 모두 열려 있으면 2건이라 번호를 고르지 않는 경로로 처리된다. 잘못 적힌 번호는 원장 이관과 함께 같은 PR diff에 드러나 리뷰에서 확인할 수 있다. 고치려면 issue-work 소스와 code-map 흐름 3개(`start`·`clear`·`response`)의 `source_hash`를 함께 바꿔야 해, 이미 최종 감사를 마친 이슈 #110 범위를 넘는다.
- **재검토 조건**: issue-work `## 이슈 완료 시`의 원장 해소 기재(PR 유무 확인 절차)를 실질 변경할 때. 또는 저장소에 포크 PR이 들어오기 시작하거나, 원장 `해소(PR #N)`에 다른 저장소의 PR 번호가 적힌 사례 관측 시.
- **상태**: 수용

## 내용

issue-work 이슈 완료 시의 원장 해소 기재는 `gh pr list --repo '<대상 저장소>' --head '<작업 브랜치>' --state open --json number`로 PR 유무를 확인한다. `--head`는 브랜치 이름만 비교하고 head 저장소는 구분하지 않으므로, 이름이 같은 포크 PR이 유일한 결과로 나오면 그 번호를 `해소(PR #N)`에 적고 항목을 `archive/`로 옮긴다. `--clear`·`--response`의 원장 종결도 같은 규칙을 따른다.

## 재검토 이력

없음

<details>
<summary>근거·배경 펼치기</summary>

- **발생확률**: 낮음. 개인 저장소에 포크 PR이 들어오는 경우가 드물고, 들어와도 작업 브랜치와 이름이 같아야 하며 자기 PR이 아직 없어야 한다.
- **영향도**: 낮음. 잘못된 번호와 `archive/` 이관이 작업 브랜치 커밋에 포함되어 PR diff에 드러나고, 머지 전에 되돌릴 수 있다.
- **채택하지 않은 대안**: `--json`에 `isCrossRepository`(또는 `headRepositoryOwner`·`headRepository`)를 더해 head 저장소가 대상 저장소와 같은 PR만 세는 안. 수정 문장은 짧지만 issue-work 소스 변경에 따른 code-map 동기화가 함께 필요해 별도 작업으로 다루는 편이 맞다. git-pr-feedback의 대상 PR 식별은 이미 head 저장소 필드를 보관해 대조한다.

</details>
