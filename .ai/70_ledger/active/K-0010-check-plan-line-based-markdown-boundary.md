# K-0010: issue-audit 추적성 헬퍼가 행 단위 파서라 여러 행 코드 스팬 등 그 밖의 마크다운 구성을 구분하지 않는다

- **유형**: known issue
- **등재일**: 2026-09-09
- **출처**: 이슈 #100 (audit 발견 F-6 처리, `--response` 승인)
- **위험도**: 낮음(LOW)
- **수용 사유**: `check-plan.sh`는 issue-work 템플릿이 만드는 spec·plan의 앵커만 읽는 행 단위 헬퍼다. 코드 펜스·HTML 주석·인라인 코드 세 구성 요소의 상호작용을 이슈 #100 최종 감사 1~4차(F-2~F-6)에서 패치로 덧붙이는 동안 보정 두 건이 다음 결함을 만들었다. CommonMark 전체를 awk 헬퍼에 구현하면 같은 반복이 이어지므로, F-6에서 "먼저 시작한 쪽이 이긴다"는 좌→우 스캔으로 구조를 바꾼 시점의 경계를 여기서 고정한다. 실제 spec·plan에서 오판정된 사례는 0건이다.
- **재검토 조건**: 실제 spec·plan이 이 경계 때문에 오판정된 사례 관측 시, 또는 issue-work spec·plan 템플릿에 여러 행 코드 스팬·들여쓰기 코드 블록을 쓰는 구조가 도입될 때
- **상태**: 수용

## 내용

`check-plan.sh --trace`는 행마다 코드 펜스·HTML 주석·인라인 코드를 구분해 앵커를 읽으며, 행 안에서는 먼저 시작한 구성 요소가 이긴다. 여러 행에 걸친 코드 스팬, 들여쓰기 코드 블록, HTML 블록의 세부 규칙 같은 그 밖의 마크다운 구성은 구분하지 않아, 그런 구성 안에 놓인 앵커나 주석 구분자는 오판정될 수 있다. 오판정의 방향은 대부분 감사인이 바로 보는 거짓 위반 출력이며, 조용한 통과가 되려면 건너뛴 Task의 R을 다른 Task가 전부 덮는 우연이 더 겹쳐야 한다.
