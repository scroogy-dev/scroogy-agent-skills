# K-0029: ai-workspace 규칙 표 알파벳순이 이름 속 숫자의 비교 방식을 정하지 않는다

- **유형**: 기술부채
- **등재일**: 2026-11-09
- **출처**: 이슈 #138 (spec 제외 보류 항목)
- **위험도**: 낮음(LOW)
- **수용 사유**: 기준으로 삼는 디렉토리 트리 정렬 규칙에도 숫자 비교 정의가 없어, 규칙 표만 따로 정하면 두 정렬이 어긋난다. 규칙 파일 이름에 숫자가 들어가는 경우가 드물어 지금 정할 근거가 부족하다.
- **재검토 조건**: 규칙 파일 이름에 든 숫자 때문에 알파벳순 자리 삽입이나 순서 검사 결과가 사용자 기대와 다른 사례 관측 시, 또는 `ai-workspace/SKILL.md` `## 디렉토리 트리 정렬 규칙`에 숫자 비교 정의가 생길 때
- **상태**: 수용

## 내용

`## 프로젝트 규칙` 표의 알파벳순 자리와 `check-context.sh` 행 순서 검사는 `파일` 셀 경로를 소문자로 바꿔 `LC_ALL=C` 바이트 순으로 비교한다. 이름 속 숫자도 문자 하나씩 비교하므로 `rule-10.md`가 `rule-2.md`보다 앞에 온다. 숫자 크기 순으로 행을 둔 표는 순서 어긋남으로 보고되고, 정렬을 승인하면 바이트 순으로 다시 놓인다.

## 재검토 이력

없음

<summary>근거·배경 펼치기</summary>

- **영향**: 기능 저하. 표의 행 내용은 바뀌지 않고, 사용자가 기대한 순서와 다른 자리에 행이 들어가거나 정렬 권유가 한 번 더 뜬다. 권유는 승인할 때만 정렬하므로 거절하면 표가 그대로 남는다.
- **발생확률**: 특수 조건·엣지. 2026-11-09 기준으로 표준 규칙 파일 이름에는 숫자가 없고, 사용자가 숫자를 넣은 규칙 파일을 두 개 이상 추가해야 나타난다.
- **채택하지 않은 대안**: 이슈 #138에서 숫자 구간을 수 크기로 비교하는 자연 정렬을 규칙 표에만 적용하는 안. 디렉토리 트리 정렬 규칙과 기준이 갈라져 보류했다.
