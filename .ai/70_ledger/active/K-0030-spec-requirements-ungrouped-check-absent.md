# K-0030: 기준 수 이상인데 묶지 않은 spec 요구사항을 결정적 검사로 잡지 않는다

- **유형**: 기술부채
- **등재일**: 2026-11-13
- **출처**: 이슈 #140 (spec 제외 보류 항목)
- **위험도**: 낮음(LOW)
- **수용 사유**: 묶음 규칙이 생긴 직후라 규칙이 지켜지지 않은 사례를 아직 보지 못했다. 묶지 않은 spec도 추적성 검사와 구조 검사를 그대로 통과하므로, 생기는 문제는 읽기 불편뿐이다.
- **재검토 조건**: 포함 또는 제외 항목이 5개 이상인데 묶지 않은 spec이 실제로 나왔을 때, 또는 issue-work spec 템플릿의 5개 기준 묶음 규칙이 바뀔 때
- **상태**: 수용

## 내용

issue-work spec 템플릿은 포함·제외 항목이 5개 이상이면 포함은 내용별 `#### ` 묶음으로, 제외는 사유별 묶음으로 나눠 쓰게 한다. 이 규칙은 템플릿 안내와 SKILL.md 3-1 승인 요청 제시로만 지켜지며, 실제 spec의 묶음 여부를 판정하는 헬퍼는 없다. 규칙을 어긴 spec은 승인 요청이나 감사에서 사람이 읽을 때만 드러난다.

## 재검토 이력

없음

- **발생확률**: 통상 사용. 특별한 입력 조건 없이, 포함·제외가 5개 이상인 spec을 쓸 때 작성자가 규칙을 빠뜨리면 생긴다.
