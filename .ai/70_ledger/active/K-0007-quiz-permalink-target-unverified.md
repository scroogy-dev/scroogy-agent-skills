# K-0007: git-review-quiz 댓글 permalink 검사가 확정 저장소·위치 행의 경로·줄 범위를 대조하지 않는다

- **유형**: known issue
- **등재일**: 2026-08-30
- **출처**: 이슈 #92 / audit 발견 F-4 (2차 잔여)
- **위험도**: 낮음(LOW)
- **수용 사유**: 헬퍼 `--comment` 모드는 URL 형태(`https://`·`blob/<40자 SHA>`·경로 존재·줄 앵커)와 `--head`/`--base` 기준 SHA만 본다. AI가 1단계에서 보관한 불변값(호스트/소유자/저장소·SHA)과 위치 행 값으로 URL을 직접 조립하므로 불일치는 자기 값을 잘못 옮길 때만 생기고, 생겨도 댓글의 위치 텍스트는 남아 링크만 어긋난다 (기능 저하 × 특수 조건·엣지). 저장소 대조는 `--repo` 인자 신설이라 SKILL.md 6단계·spec 헬퍼 사용법·DoD 5 명령까지 함께 바뀐다.
- **재검토 조건**: `git-review-quiz/scripts/check-quiz.sh` `--comment` 모드의 인자 또는 permalink 판정 규칙을 실질 변경할 때. 또는 게시된 퀴즈 댓글의 permalink가 다른 저장소·경로·줄 범위를 가리킨 사례 관측 시.
- **상태**: 수용

## 내용

`check-quiz.sh --comment`는 위치 행의 permalink URL이 확정 저장소(호스트/소유자/저장소)를 가리키는지, URL의 경로·줄 앵커가 같은 행의 `위치: `<경로>:<줄 범위>`` 값과 일치하는지 대조하지 않는다. 다른 저장소·다른 경로·다른 줄 앵커를 가진 URL도 SHA 형식과 기준 SHA만 맞으면 통과한다. 게시 전 검사가 이 불일치를 잡지 못하면 댓글의 링크가 변경 위치와 다른 곳을 연다.

- **발생확률**: 낮음. SKILL.md 1단계가 저장소·`headRefOid`·`baseRefOid`를 불변값으로 보관하고 5단계가 그 값과 위치 행 값으로 URL을 조립하므로, 불일치는 조립 시 자기 값을 잘못 옮길 때만 생긴다.

- **채택하지 않은 대안**: `--repo '<호스트>/<소유자>/<저장소>'` 인자를 신설해 URL 앞부분을 대조하고, 위치 행의 경로·줄 범위를 URL 경로·앵커와 대조하는 안. 저장소 대조는 헬퍼 인터페이스 변경이라 SKILL.md·spec·DoD 명령이 함께 번진다. 경로·줄 범위 대조는 인터페이스 변경 없이 가능하나 발생확률이 같은 수준이라 함께 수용했다.
- **경위**: 이슈 #92 audit 1차 F-4(permalink 전수 검사 부재)는 `--comment` 모드 신설로 닫혔다. 2차 잔여로 저장소·경로·줄 범위·scheme 대조가 올라와 `--response` 검토에서 `http` 허용만 spec 문언 위반으로 보정하고 나머지는 이관하기로 확정했다.
