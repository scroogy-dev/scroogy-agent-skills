# K-0052: 원장 링크 검사 헬퍼가 코드 스팬·코드 블록 안의 링크 문자열도 끊긴 링크로 보고한다

- **유형**: known issue
- **등재일**: 2026-11-28
- **출처**: 이슈 #150
- **위험도**: 낮음(LOW)
- **수용 사유**: 헬퍼 머리 주석에 "코드 블록·코드 스팬 안의 링크 문법도 구분하지 않고 검사하고, 오탐은 호출한 쪽이 건별로 판정한다"고 적은 설계다(이슈 #120). 오탐이 나오는 곳은 다른 위치에 적을 링크를 인용한 문서(감사 리포트의 완료 기준 등)로 드물다. 고치려면 바이트 단위로 같은 사본 3개(issue-work·git-pr·git-pr-feedback)와 각 러너를 함께 바꿔야 한다.
- **재검토 조건**: 코드 스팬·코드 블록 안의 링크 문자열 오탐 때문에 맞는 경로를 고치거나 끊긴 링크를 놓친 사례가 다시 관측될 때, 또는 `check-ledger-links.sh`의 링크 추출 구간을 바꿀 때
- **상태**: 수용

## 내용

`check-ledger-links.sh`는 각 줄의 `](<대상>)`를 모두 링크로 읽고, 대상을 그 문서 위치에서 풀어 파일이 있는지 본다. 백틱으로 감싸 인용한 링크 문자열이 다른 위치에서 쓸 상대 경로이면, 검사하는 문서 위치에서는 파일이 없어 끊긴 링크로 나온다. 보고를 그대로 믿고 경로를 고치면 인용한 링크가 틀린 경로가 된다.

## 재검토 이력

| 일자 | 계기 | 판단 | 결과 |
|------|------|------|------|
| 2026-11-28 | 이슈 #150 `--response` 뒤 원장 링크 검사 | 등재 | 최종 감사 리포트의 완료 기준이 도메인 명세에 적을 링크(`../../70_ledger/…`)를 코드 스팬으로 인용했고, 헬퍼가 리포트 위치(`.ai/99_workspace/`) 기준으로 풀어 끊긴 링크로 보고했다. 구현 AI가 이 보고를 믿고 경로를 고쳤다가 되돌렸다 |

<summary>근거·배경 펼치기</summary>

- **영향**: 기능 저하. 검사의 0건 판정은 오탐 때문에 실패하고, 호출한 쪽이 건별로 판정해야 한다. 판정을 잘못하면 맞는 인용 경로를 틀린 경로로 바꾼다.
- **발생확률**: 특수 조건·엣지. 원장 항목 파일 이름이 든 링크를 다른 위치 기준의 상대 경로로 코드 스팬·코드 블록 안에 인용한 문서에서만 나타난다.
- **위험도 산출**: `classify-risk.sh --impact '기능 저하' --likelihood '특수 조건·엣지'` → 낮음(LOW).
- **채택하지 않은 대안(지금 고치지 않은 이유)**:
  - 코드 스팬과 코드 블록을 건너뛰는 안: 이슈 #120에서 오탐을 호출한 쪽의 판정으로 남긴 설계를 바꾸는 일이고, 사본 3개와 러너를 함께 고쳐야 한다. 줄 단위 awk로 여러 줄 코드 블록과 여러 백틱 코드 스팬을 가리려면 경계 판정을 새로 설계해야 한다(같은 종류의 경계 문제: K-0010, K-0026).
- **우회**: 보고된 줄이 코드 스팬·코드 블록 안의 인용이면 고치지 않고, 인용 경로를 그 링크를 쓸 문서 위치 기준으로 확인한다.
