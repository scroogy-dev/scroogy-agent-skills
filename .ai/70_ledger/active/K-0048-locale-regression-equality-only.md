# K-0048: 로케일 회귀 케이스가 두 실행의 결과가 같은지만 보고 기대 판정은 보지 않는다

- **유형**: known issue
- **등재일**: 2026-11-27
- **출처**: 이슈 #147 (독립 비교 감사 F-1 처리, `--response` 승인)
- **위험도**: 낮음(LOW)
- **수용 사유**: 회귀 케이스의 목적은 로케일 독립성이며, 입력을 잘못 만들어 두 실행이 같은 오류를 내는 경우는 테스트 먼저의 실패 확인 단계에서 걸린다. 정상 fixture의 기대 판정은 같은 러너의 기존 케이스가 이미 단언한다. 남는 위험은 뒤의 헬퍼 변경으로 두 로케일이 같은 오판을 내는 경우뿐이고, 계획 단계에서 고치면 `설계 결정`이 바뀌어 계획 감사를 다시 받아야 한다.
- **재검토 조건**: 로케일 회귀 케이스가 두 로케일의 같은 오판을 통과시켜 결함을 놓친 사례 관측 시, 또는 로케일 회귀 케이스의 비교 방식을 바꿀 때
- **상태**: 수용

## 내용

이슈 #147의 로케일 회귀 케이스는 같은 입력을 `C.UTF-8`과 `en_US.UTF-8`로 실행해 합친 출력(`2>&1`)과 종료 코드가 같으면 통과로 본다. 기준 로케일 쪽 결과가 기대 판정(예: ai-workspace `profile_state` 경계 입력의 ``질의: 안내도에 `profile` 행이 없음``·종료 코드 1)과 맞는지는 보지 않아, 두 실행이 똑같이 틀리면 통과한다. 영향 범위는 git-review-quiz·ai-workspace 러너의 `로케일:` 케이스다.
