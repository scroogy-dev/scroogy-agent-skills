# K-0023: issue-audit 추적성 헬퍼가 행 끝에 닫힌 주석이 붙은 `**포함**` 라벨을 인식하지 못한다

- **유형**: known issue
- **등재일**: 2026-11-01
- **출처**: PR #131 코멘트 스레드 (`### 공통` 헤더 판정 지적에 대응하다 같은 유형을 확인)
- **위험도**: 낮음(LOW)
- **수용 사유**: 오판정이 나면 `추적 불가` 행이 출력되어 감사인이 바로 알아본다. 조용히 통과하는 경로는 없다. issue-work spec 템플릿의 `**포함**` 행에는 주석이 없고, 실제 spec에서 관측한 사례도 0건이다. PR #131 리뷰 지적 범위 밖이고 PR 이전부터 있던 `--trace` 코드라, 최소 변경 원칙에 따라 그 PR에서 고치지 않았다.
- **재검토 조건**: 실제 spec에서 이 경계 때문에 `추적 불가`로 오판정된 사례 관측 시, 또는 `check-plan.sh --trace`의 spec 앵커 판정(`**포함**` 라벨·포함 목록 경계) 변경 시, 또는 issue-work spec 템플릿의 `**포함**` 행에 주석을 두는 구조가 도입될 때
- **상태**: 수용

## 내용

`check-plan.sh --trace`는 `**포함**` 라벨을 `/^\*\*포함\*\*[[:space:]]*$/`로 판정한다. 그래서 `**포함** <!-- 메모 -->`처럼 행 끝에 닫힌 주석이 붙으면 포함 목록을 시작하지 않고, `추적 불가: spec 포함 목록에 R<n> 항목이 없습니다`와 DoD 그룹마다 `R 없는 DoD 그룹`을 출력한다. 스크립트 주석의 "앵커 행 끝의 짧은 메모를 앵커 누락으로 만들지 않는다"는 원칙과 어긋나며, PR #131에서 고친 `--ac`의 `### 공통` 헤더 판정과 같은 유형이다.

## 재검토 이력

없음
