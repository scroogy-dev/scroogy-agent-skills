# K-0018: ai-workspace update-4에서 규칙 섹션·표를 프로파일이 어긋난 템플릿으로 복구하면 그 실행에서 `testing-principles.md` 행이 빠진다

- **유형**: known issue
- **등재일**: 2026-10-27
- **출처**: PR #125 코멘트 스레드
- **위험도**: 낮음(LOW)
- **수용 사유**: dev 선언 repo를 doc 프로파일로 update하고, 동시에 `## 프로젝트 규칙` 섹션이나 표가 없어야 생겨 발생확률이 매우 낮다. 빠진 행은 다음 update에서 헬퍼가 누락으로 보고해 보강되고, `context-loading.md`의 테스트 라우팅은 그대로 남아 영향도 낮다. 고치려면 이미 긴 `## 프로젝트 규칙` 검사 행에 조건 문장을 더하고 프로파일 불일치 fixture 2종과 테스트를 함께 늘려야 해 비용이 이득보다 크다.
- **재검토 조건**: ai-workspace update-4 멱등 보강 검사의 `## 프로젝트 규칙` 섹션·표 복구 조치나 `testing-principles.md` 행 검사 조건을 실질 변경할 때. 또는 dev 선언 repo의 update 결과에서 이 행이 빠진 사례 관측 시.
- **상태**: 해소(PR #137)

## 내용

`check-context.sh`는 `## 프로젝트 규칙` 섹션이나 표가 없으면 표준 행 검사를 건너뛴다. 이때 update-4는 선택한 프로파일의 템플릿 골격으로 섹션·표를 복구하는데, dev 선언을 보존한 채 doc 프로파일로 update하면 doc 템플릿에는 `testing-principles.md` 행이 없다. 헬퍼를 한 번만 실행하므로 그 실행에서는 이 행이 보고되지 않아 보강이 누락된다.

<details>
<summary>근거·배경 펼치기</summary>

- **발생확률**: 매우 낮음. 세 조건이 모두 겹쳐야 한다(dev 선언 repo, 프로파일을 어긋나게 doc으로 선택, 규칙 섹션 또는 표 부재). 섹션·표 부재는 오래된 안내도이거나 사용자가 직접 지운 경우다.
- **영향도**: 낮음. 행 하나가 한 실행 동안 빠질 뿐이고 다음 update에서 수렴한다. doc 프로파일 update는 dev 전용 파일 쌍을 배포하지 않으므로, 이 경우 파일이 없는 repo가 대부분이다.
- **채택하지 않은 대안**: 섹션·표를 복구했으면 헬퍼 보고와 별개로 최종 SSoT 선언이 dev 문구일 때 `testing-principles.md` 행을 함께 넣는 문장을 더하고, 두 복구 경로에 프로파일 불일치 fixture를 추가하는 안. 리뷰어가 제안한 방향이며, 재검토 조건이 충족되면 이 안부터 검토한다.

</details>
