# issue-work 템플릿 개선 요청: 결정적 하네스 기반 DoD + 교차모델 audit

> 이 파일은 `issue-work`로 별도 이슈를 떠서 작업하기 위한 **요청 프롬프트**입니다.
> 이슈 생성 시 이 문서를 입력으로 주고, 스펙·계획을 확정한 뒤 진행하세요.

## 배경 (Why)

생성형 AI는 출력이 비결정적이므로, 변경 범위를 통제하고 결과를 검증하려면
**테스트·컴파일러·린터·검증 게이트 같은 결정적 하네스**가 필요하다
(참고: https://news.hada.io/topic?id=30711 — "예측 불가능한 출력을 안정적인 시스템 안에 묶는 능력").

현재 `issue-work` 템플릿은 방향은 맞지만(스펙 `완료의 정의` 주석 = "AI가 스스로 판정",
계획 Task = "독립적으로 검증 가능") **"명령어로 환원하라"는 강제가 약하다.**
완료 기준이 산문으로 남으면 비결정적 생성기를 길들이는 하네스 역할을 못 한다.

이 repo는 SSoT를 소스코드로 못 박아 둔 덕에(`/.ai/AI-CONTEXT.md` 상단) 문서성 산출물도
"SSoT와의 일관성"을 결정적으로 검사할 수 있는 좋은 조건이며,
`scripts/` 결정적 헬퍼에 대한 테스트 규칙은 이미 ADR로 정립되어 있다
(`.ai/50_adr/active/0001-skill-deterministic-helper-test-convention.md`).

## 핵심 규율 (이번 개선이 박아야 할 한 줄)

> **각 완료 항목(DoD)을 가능한 한 가장 낮은(=자동으로 검증되는) 단계로 내리되,
> 항목 하나하나를 잘게 쪼개고, 단계를 내릴 때는 그 사유와 단계 태그를 함께 적는다.**

검증 사다리 — 단계가 낮을수록 좋다(가능한 한 1단계로 끌어내리는 게 목표):

| 단계 | 태그 | 누가/무엇이 합격을 판정하나 | 예 |
|------|------|------------------------------|----|
| 1 | `[결정적]` | **명령어가 통과/실패로 답한다.** 사람 판단이 끼지 않음 | 빌드 성공, 테스트 통과, 린터 무경고, 링크 안 깨짐, 필수 항목 누락 없음(형식 검사), 문서 내용이 실제 소스코드와 어긋나지 않는지 대조 |
| 2 | `[준결정적]` | **다른 AI나 기준 체크리스트로 채점한다.** 기계만큼 확정적이진 않지만 사람보다는 일관됨 | "안내도만 보고 원하는 스킬을 찾을 수 있나"를 다른 모델이 채점 |
| 3 | `[비결정적]` | **사람이 직접 읽고 판단한다.** 기계로 거를 수 없는 순수 주관 | 문장이 매끄러운가, 톤이 기존 문서와 어울리나 |

**약어 범례** — 정의·설명엔 한국어로 풀어 쓰고, 실제 체크리스트 기록엔 약어로 적어도 된다.

| 한국어 | 영어 원문 | 약어 |
|--------|-----------|------|
| 결정적 | Deterministic | `[D]` |
| 준결정적 | Quasi-deterministic | `[QD]` |
| 비결정적 | Non-deterministic | `[ND]` |

**분류 기준은 "출력이 boolean이냐 수치냐"가 아니라 "판정이 재현되고 사람 판단이 안 끼느냐"다.**
- **결정적**: 같은 입력 → 같은 판정, 사람 판단 없음. 판정 형태는 **합/불(boolean)**. *테스트 케이스·테스트 스크립트·컴파일러·린터·커스텀 검증 스크립트가 모두 여기 포함*된다. 커버리지 83%·p99 12ms 같은 **수치도 고정 임계값(≥80%, ≤20ms)을 걸어 합/불로 환원**하면 결정적이다(측정은 수치, 게이트는 boolean).
- **준결정적**: 판단(AI·기준 체크리스트 채점)이 개입해 **매번 결과가 달라질 수 있다.** 결과는 보통 **점수(정량, 예: 7/10)나 정성 평가**지만 그게 정의는 아니다 — *AI가 true/false를 내도 재현이 안 되면 준결정적*. 가능하면 **통과 기준(예: 4/5 이상)을 함께 정의**해 재현성을 결정적 쪽으로 끌어올린다.
- **비결정적**: 사람의 주관 서술·승인.

- 기본값은 항상 1단계(`[결정적]`). 한 단계 내려갈 때마다 **"왜 결정적으로 검증 못 하는가"** 사유를 함께 적는다.
- 태그는 **이슈/문서 단위가 아니라 완료 항목 하나하나에** 붙인다. 한 이슈 안에 `[결정적]`·`[준결정적]`·`[비결정적]`이 섞이는 게 정상이다. 애매한 항목 하나가 결정적으로 검증 가능한 항목까지 덮어버리지 않도록 항목을 잘게 쪼갠다.
- 빠지기 쉬운 함정 둘:
  - **가짜 `[결정적]`** — 검사는 통과하는데 정작 중요한 걸 안 잡는 경우. 1단계로 분류하기 전에 *"이게 틀렸을 때 검사가 실제로 실패하나?"*를 물어본다.
  - **과한 자동화** — 자동 검사기를 만드는 데도 선투자 비용이 든다. **자주 반복되고 중요한** 항목만 1단계로 만들고, 한 번 쓰고 버릴 항목은 2단계(`[준결정적]`)가 비용 대비 낫다.

## 요청 작업 (What — 변경 대상)

### 1. `issue-work/templates/issue-spec-template.md` — `완료의 정의` 섹션 보강
- 위 3단 사다리(`[결정적]`/`[준결정적]`/`[비결정적]`, 약어 `D`/`QD`/`ND`)와 핵심 규율을 주석으로 설명.
- 각 체크리스트 항목에 **단계 태그 + 검증 수단(명령어/테스트/스크립트 또는 판정 주체)**을 함께 적는 예시 추가.
- 예시 형식 (실제 기록은 약어 사용):
  ```
  - [ ] [D]  <검사할 불변 조건>  (검증: <명령어/테스트/스크립트>)
  - [ ] [QD] <대신 확인할 기준>  (검증: 다른 AI가 채점, 별도 세션)  ← 강등 사유: <…>
  - [ ] [ND] <순수 주관 항목>    (검증: 사람 리뷰)                  ← 강등 사유: <…>
  ```

### 2. `issue-work/templates/issue-plan-template.md` — 두 가지
- (a) 각 Task의 **완료 기준을 자연어 대신 실행 명령 + 임계값**으로 적도록 주석·예시 보강.
- (b) **마지막 Task로 `issue-audit`(교차모델) 검증을 의무화**한다. 고정 Task 블록을 템플릿에 포함:
  - 내용: ① 1단계(`[결정적]`) 검사가 전부 통과했는지 확인 → ② **계획·구현을 수행한 모델과 다른 모델**로 `issue-audit` 실행.
  - 검증 방향은 칭찬이 아니라 **허점을 찾는 쪽으로**("스펙 위반·누락·소스코드와의 모순을 찾아라"), audit 모델은 **최소 동급 이상 역량**.
  - audit은 **2단계(`[준결정적]`) 검증 = 1단계 결정적 게이트의 대체가 아니라 보완**임을 주석에 명시.

### 3. `issue-work/templates/issue-summary-template.md` — 모델 기록
- **계획·구현에 쓴 모델 이름**과 **audit에 쓴 모델 이름**을 적는 칸 추가.
- 목적: "audit 모델 ≠ 구현 모델"이라는 조건을 **나중에 결정적으로(명령어로) 확인** 가능하게 (모델 전환은 사람이 직접 하는 일이라 기계로 강제하기 어려움 → 기록으로 검증).

### 4. (선택) `issue-work/SKILL.md`
- 위 규율을 워크플로우 설명에 1~2줄 반영(템플릿이 SSoT, 본문은 포인터만).

## 비포함 (Out) — 별도 이슈 후보
- 실제 검사기 구현(예: SKILL.md 형식 검사, AI-CONTEXT 스킬 목록이 실제 디렉토리와 어긋나는지 검사, 링크 무결성 `scripts/`)과 CI 게이트 구성은 **이번 범위가 아니다.** 본 이슈는 **템플릿·규율 문서화**까지만.
- 검사기 도입 시에는 ADR 0001(`scripts/` + `tests/` 동일 위치, 배포 제외)을 따른다.

## 완료의 정의 (이 이슈 자체에 적용 — 자기참조 예시)
- [ ] [D]  변경된 3개 템플릿이 마크다운으로 정상 표시됨 (렌더 확인)
- [ ] [D]  plan 템플릿에 "마지막 Task = 교차모델 issue-audit" 고정 블록이 있음 (grep)
- [ ] [D]  summary 템플릿에 구현 모델 / audit 모델 기록 칸이 있음 (grep)
- [ ] [QD] 새 `완료의 정의` 예시가 3단 사다리를 오해 없이 전달하는가 (다른 AI가 채점, 별도 세션)
- [ ] [ND] 기존 템플릿 톤·간결성과 일관됨 (사람 리뷰)
