현재 "라이선스·개인 저작물 고지 옵션"(158~238행) 약 80줄 중, Q1=(a) 오픈소스 분기에서만 필요한 세부 사양이 항상 적재됩니다. Q1=(b)/(c)는 회사 업무에서 흔한 경로라 실사용 다수가 불필요 토큰을 부담합니다.

**수정 방안**:

1. `readme-sync/references/license.md` 신설 — "LICENSE 파일 생성 규칙", "`--force-license` 플래그"(가드 3종·결과 보고), "라이선스 헤더 파일명 가드"(Licensee 문제 설명·명명 규칙·감지 권유) 3개 절 이동 (약 65줄).
2. 본문에는 항상 필요한 것만 유지: "라이선스 표시 3분기" 표, "개인 저작물 고지 토글", "말미 블록 조합표" (init-3단계 템플릿 적용에 직접 사용).
3. 본문 인라인 앵커 3곳(인자 표의 `--force-license` 설명, Q1-2, init-4단계)을 `references/license.md` 포인터로 교체하고 "Q1=(a) 분기 진입 시에만 읽습니다" 조건 명시 — code-map의 모드별 분리와 동일 패턴.
4. 예상 효과: 268줄 → 200줄 안팎, (b)/(c) 경로 토큰 약 25% 절감.

### 2. git-pr — 98행 호출 흐름 지침 과밀 문단 (1차 심각도 최하)

한 문단에 색인 참조 + SSoT 원칙 + 색인 갱신 의견 + 다이어그램 형식 규칙 4가지가 응집되어 있습니다.

**수정 방안**: 같은 저장소의 git-review-context 5단계가 동일 내용을 이미 불릿 구조로 표현하고 있으므로 그 형식을 그대로 차용 —

```markdown
* **호출 흐름:**
  - `.ai/60_codebase/index.md`에 내용이 있으면 참고하되, SSoT는 소스코드이므로 반드시 실제 코드를 확인하여 작성합니다.
  - 색인과 실제 코드가 다르면 참고사항에 "코드베이스 색인 갱신이 필요해 보입니다 (`/code-map`)" 의견을 남깁니다.
  - 기능(엔트리 포인트)별로 나누어 디렉토리 트리 형태의 ASCII 다이어그램으로 도식화합니다.
    - 각 노드에 `ClassName#methodName` 명시, 트리 기호(`├──`, `└──`)로 호출 계층 표현, 핵심 로직은 `# 설명` 주석.
  - 하나의 이슈에 여러 기능이 있으면 기능별로 각각 작성합니다.
```

토큰 변화는 거의 없고 가독성만 개선되는 항목이므로, 다른 수정과 묶어 처리해도 충분합니다.

### 3. (신규 권장) ai-workspace-directory/references/examples.md — 목차 추가

이번 수정에서 신설된 파일이 386줄로, skill-creator 가이드의 "300줄 초과 참조 파일은 목차(TOC) 포함" 기준에 걸립니다. 회귀가 아닌 신규 파일에 대한 개선 권장입니다.
