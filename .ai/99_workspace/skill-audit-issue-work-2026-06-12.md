## 개선 제안 (모두 경미)

### 1. GitHub 이슈 번호 매핑 규칙 누락 (우선순위: 중)

설계 문서의 결정 사항 "디렉토리명 `issue-<번호>`에서 앞자리 0을 제거한 번호를 GitHub 이슈 번호로 사용 (issue-0015 ↔ #15)"이 SKILL.md에 반영되지 않음. `--clear` 3단계(이슈 댓글 등록)에서 어느 이슈에 댓글을 달지 추론에 의존하게 됨.

**수정안**: `--clear` 3단계에 한 줄 추가.

```markdown
  3. **이슈 댓글 질의**: ... 승인 시에만 등록한다.
     대상 이슈 번호는 디렉토리명 `issue-<번호>`에서 앞자리 0을 제거해 사용한다 (예: issue-0015 → #15).
```

### 2. issue-workflow-template.md에 `--clear` 미반영 (우선순위: 중)

이 템플릿은 컨텍스트 초기화 후 절차 복구용인데, `이슈 완료 시` 섹션이 `--clear` 추가 이전 상태 그대로임. SKILL.md에는 안내 줄이 추가됐지만 템플릿에는 없어, 컨텍스트가 초기화된 AI는 `--clear` 존재를 알 수 없음.

**수정안**: 템플릿의 `## 이슈 완료 시` 끝에 SKILL.md와 동일한 안내 1줄 추가.

```markdown
> 위 절차에 더해 `99_workspace` 정리와 이슈 댓글 요약 등록까지 한 번에 수행하려면 issue-work `--clear` 옵션을 사용한다.
```

### 3. 99_workspace 정리 범위 모호 — context-save와 회색지대 (우선순위: 하)

`--clear` 5단계의 "`.ai/99_workspace/` 하위 파일 목록"이 재귀 탐색인지 불명확함(`--resume`은 "재귀 탐색"을 명시). 재귀라면 context-save가 저장하는 `99_workspace/notes/`의 노트까지 정리 대상이 되는데, 노트는 이슈 단위 산출물이 아닐 수 있어 일괄 삭제 제안은 부적절할 수 있음. 목록 제시 후 사용자 확인을 거치므로 실해는 없으나, 서술 명확화 권장.

**수정안**: 5단계에 범위와 notes/ 취급을 명시.

```markdown
  5. **99_workspace 정리**: `.ai/99_workspace/` 하위 파일 목록을 재귀로 보여주고
     (`.gitkeep`은 항상 보존, `notes/`는 context-save 산출물이므로 기본 보존 — 사용자가 요청할 때만 정리 대상에 포함),
     보존할 파일은 `archive/issue-<번호>/`로 이동을 제안한다. 나머지는 삭제 확인 후 삭제한다.
```

## 변경분 외 참고 (이번 변경과 무관, 직전 감사 기준선에 이미 존재)

`issue-plan-template.md`·`issue-summary-template.md` 상단 링크가 `./issue-spec.md` 형태로, 실제 파일명 규칙(`issue-<번호>-spec.md`)과 표기가 다름. 생성 시 AI가 번호를 채워 넣는 플레이스홀더로 해석될 수 있으나, 다른 자리에는 `<번호>` 표기를 쓰므로 `[issue-<번호>-spec.md](./issue-<번호>-spec.md)`로 통일하면 일관성이 높아짐. 필요 시 별도 이슈로 처리 권장.
