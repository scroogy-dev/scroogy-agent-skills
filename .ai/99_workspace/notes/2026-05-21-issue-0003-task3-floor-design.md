## 1. 설계 원칙 (Task 2와 정렬)

- **층별 안내도는 라우터다.** 코드/문서로 가는 라우팅 정보를 담되, 도메인 본문·코드 스니펫은 `.ai/30_contract`~`.ai/60_codebase`로 보낸다.
- **SSoT는 소스 코드.** 층별 안내도도 라우터일 뿐.
- **코드 진입은 `.ai/` 라우터를 거친다.** `## 디렉토리 구조`는 코드 트리 개관일 뿐 라우팅이 아니다. 코드 색인 진입(`60_codebase/index.md`)은 `## 에이전트 운영 지침 > 진입 절차`에서만 명시한다. 같은 이유로 `## 디렉토리 구조`에서 `.ai/`는 한 줄로만 표시하고 내부는 `## .ai 디렉토리 구조` 섹션이 다룬다.
- **컨벤션 우선 (CoC).** 상위 워크스페이스 디렉토리 바로 아래 각 repo가 위치하고, 상위 워크스페이스의 `.ai/AI-CONTEXT.md`가 안내도다. 멀티 repo 일부 여부는 `<repo>/..의 .ai/AI-CONTEXT.md` 존재로 자동 판정한다 — 메타 필드로 명시하지 않는다. 이 컨벤션을 벗어나는 구조는 지원하지 않는다 (YAGNI).
- **로비와 양방향 메타.** floor 메타 블록의 필드명은 로비 `Repos` 컬럼명(`domain`/`keywords`)과 **동일 어휘**로 정한다. 로비 단방향 drift 검사가 동작 가능해야 함.
- **`.ai/` 부재 repo는 강제 대상이 아니다.** 층별 안내도가 없는 repo도 로비의 `placeholder` 분기로 정상 등록·라우팅된다 (Task 2 §1).
- **YAML frontmatter 사용 금지.** 로비와 동일 패턴 (마크다운 본문 메타).
- **프로파일 호환.** dev / doc 두 프로파일 모두에 공통 적용되는 보강과 dev 전용 보강을 분리.

## 6. `ai-workspace` update 모드 멱등 보강 (신규 단계)

기존 `update-1/2/3/4/5`단계는 유지하고, AI-CONTEXT.md 갱신 단계(`update-4단계`)에 **신규 4개 항목**을 추가한다.

### update-4단계 추가 작업

| 본문 두 번째 줄 SSoT 선언 | `> SSoT: 소스 코드. ...` 존재? | 표준 문구로 삽입 |
| `## 프로젝트 도메인` 섹션 | 섹션 존재? | 2행 표 골격을 빈 값(`<...>`)으로 삽입. `domain`/`keywords`만 사용자 입력 요청 (멀티/단독 여부는 묻지 않음 — CoC 자동 판정) |

| `## 에이전트 운영 지침` 섹션 + 전제 컨벤션 한 줄 | 섹션 존재? 전제 한 줄 존재? | 표준 골격(전제 한 줄 + 진입 절차 3단계 + 작성 규칙)을 삽입. 사용자가 별도 운영 지침을 추가했다면 그 아래 보존 |
| 구버전 `## 워크스페이스 위치`(4행) → `## 프로젝트 도메인`(2행) 마이그레이션 | 구버전 섹션 존재? | 섹션명을 `## 프로젝트 도메인`으로 변경, `building`/`lobby` 행 삭제, `domain`/`keywords` 행만 유지 |

### 멀티/단독 repo 식별 (CoC — 메타 입력 수집 불필요)

`init` 모드와 `update` 모드 모두 다음 자동 판정만 수행한다.

1. `<repo>/..`에서 한 단계 상위로 올라가 `<상위>/.ai/AI-CONTEXT.md` 존재 여부를 확인.
2. 존재 → 멀티 repo 워크스페이스의 일부. 존재 안 함 → 단독 repo. **사용자에게 묻지 않는다 (컨벤션 우선).**
3. 결과를 안내 메시지로만 보고 — *"이 repo는 멀티 워크스페이스 일부입니다 — 상위 안내도: `../.ai/AI-CONTEXT.md`"* 또는 *"이 repo는 단독 repo입니다."*
4. `domain`/`keywords`는 사용자에게 입력 요청. 멀티 repo면 *"상위 워크스페이스 AI-CONTEXT.md의 `Repos` 표와 일치시켜 주세요"* 안내 출력.

## 7. 로비와의 단방향/양방향 호환

| 시나리오 | 동작 |
|---------|------|
| 층별 안내도 메타 블록 부재 + 상위 워크스페이스 `Repos`에 등록 | 상위는 단방향으로 라우팅. 층별 안내도 자체 메타가 없으면 drift 메타 검사(Task 2 §5) 스킵 |
| 층별 안내도 메타 블록 존재 + 상위 워크스페이스 `Repos`에 미등록 | 상위 `update`가 drift("`Repos`에 없음 + 디스크 안내도 있음")로 검출 → 등록 권고 |
