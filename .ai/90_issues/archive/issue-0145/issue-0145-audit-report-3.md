<details>
<summary>근거와 실패 시나리오 펼치기</summary>

계획 수립 단계에서 빈 목록을 받는 AC의 테스트 계획을 바로잡는 예를 실행했다. `빈 목록을 받는다`는 AC에 필요한 단위 검사와, 빈 목록이면 오류를 내야 한다는 잘못 지정한 검사가 함께 있었다. 뒤의 줄만 지우면 diff는 plan 한 파일에 추가 0행·삭제 1행이다. 두 검사의 실제 종료 코드는 각각 0과 1이었고, 삭제 뒤 남은 검사의 종료 코드는 0이었다. 이 계획은 변경 전후 모두 `check-plan.sh --trace`가 무출력·종료 0이다. 테스트 소스·AC 문장에는 변경이 없고, 일반 구현 Task가 이 plan 파일을 산출물로 지정하지 않은 경우다. 추가·필드 변경만 열거한 구현 검증 조건에 해당하지 않아, 첫 감사가 잘못 지정한 검사 때문에 남긴 미충족 판정이 다음 회차에도 남는다.

반대로 AC2의 유일한 검증 줄을 지운 예에서는 `--trace`가 `테스트 계획 없는 AC: AC2`와 종료 1을 냈다. 계획 감사를 생략한 이슈라면 구현 검증도 생략할 수 있고, 완료 확인에서는 AC1 한 줄만 남아 `1/1`이 된다. 이 경우 이전 AC2 충족을 그대로 쓸 수 있다.

- **실패 시나리오**: 검증 근거의 삭제에 따라 판정이 바뀌어야 하는 AC가 이전 회차 상태로 완료 확인과 PR에 전달된다.
- **검토 위치**: issue-work/SKILL.md 167~171행·179~191행, issue-audit/SKILL.md 98~104행, git-pr/SKILL.md 264~269행. #145 스펙의 `지난 검증 뒤에 바뀌었다` 판별도 추가·수정만 열거하므로 1단계 감점에는 넣지 않았다.

</details>
