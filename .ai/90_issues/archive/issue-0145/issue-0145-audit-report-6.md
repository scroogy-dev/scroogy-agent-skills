- **영향 축**: 기능 저하
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 기능
- **관점**: 암묵적 가정
- **계보**: 신규
- **권장 조치**: git-pr이 이슈 번호별 최신 리포트를 찾는 순서를 issue-audit의 결과 저장·회전 규칙과 맞춘다.
- **완료 기준**
  1. archive에 이전 회차 번호 파일, workspace에 새 기본 이름 리포트가 있는 경우 PR은 새 문장·번호·판정을 사용한다.
  2. 이관 직후 archive에만 기본 이름 리포트가 있으면 그 리포트를 쓰고, 두 위치 모두에 없으면 미검증을 유지한다.

<details>
<summary>실패 시나리오와 근거 펼치기</summary>

임시 디렉토리에서 정렬 예시 AC1의 1차 리포트를 archive에 두고 issue-audit 332~336행의 재감사 보존 규칙을 적용했다. archive에는 `issue-0099-audit-report-1.md`만 남고, 새 충족 판정은 `.ai/99_workspace/issue-0099-audit-report.md`에 있었다. 이는 사용자가 `--clear` 후 PR을 다시 작성하기 전에 해당 이슈를 재감사하면 생기는 배치다.

git-pr 264행은 `--clear` 뒤에는 archive의 기본 이름을 찾게 하고, 268행은 찾지 못하면 미검증을 선택한다. PR의 판정을 보수적으로 낮추지만 독자가 최신 검증 결과를 전달받지 못한다. R22와 AC18에 결속된다.

</details>
