  1. 테스트 계획에 줄이 없는 AC를 후속 이슈로 넘기면 PR 표가 해당 AC를 이관으로 표시하고 목적지를 추적할 수 있다.
  2. 결정적 검사가 실패하고 사용자 확인이 끝난 혼합 AC를 이관하면 PR 표에 이관 상태와 기존 확인 날짜가 함께 남는다. 이관한 줄은 완료 확인 분자에서 제외된다.

<details>
<summary>실패 시나리오와 근거 펼치기</summary>

정렬 예시에서 AC1의 유일한 테스트 줄을 삭제하자 `--trace`가 `테스트 계획 없는 AC: AC1`로 종료 1을 냈다. 최종 감사 104행은 이 상태를 N/A로 처리한다. 사용자가 완료 확인에서 후속 이슈로 넘겨도 194행이 이관 번호를 쓸 AC1 줄은 0개다. PR 상태 규칙을 적용하면 이관 표지가 없어 N/A가 미검증으로 표시된다.

줄이 있는 예에서도 충돌한다. AC2에 결정적 검사 한 줄과 날짜가 기록된 사용자 확인 한 줄을 두고 194행에 따라 두 칸에 예시 값 `이관 #900`을 적었다. 변경 전후의 추적성 검사는 모두 통과했지만 사용자 확인 날짜가 사라졌다. git-pr 271행과 #145 스펙의 Task 9 결정은 사용자 확인 날짜를 PR 근거로 요구한다.

</details>

#### F-17: AC 원문을 유지하고 판정에 쓰는 결정만 완화하면 PR에 옛 판정이 남는다

- **위험도**: 🟢 낮음(LOW)
- **영향 축**: 기능 저하
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 기능
- **관점**: 암묵적 가정
- **계보**: F-3 잔여. F-13의 두 완료 기준에 해당하는 AC 원문 비교는 닫혔다.
- **권장 조치**: 완료 확인에서 승인한 결정 변경이 어떤 AC의 판정 근거를 바꾸는지 기록하고, 그 AC에는 변경 전 판정을 재사용하지 않도록 한다.
- **완료 기준**
  1. AC 번호·문장을 유지하고 그 AC가 참조하는 허용 범위만 완화해도 PR에는 이전 범위 기준의 판정이 새 결과로 표시되지 않는다.
  2. 판정 의미가 같은 AC의 체크박스·확인 칸만 바꾸면 기존 결과를 유지한다.

<details>
<summary>실패 시나리오와 근거 펼치기</summary>

AC1이 “허용 범위 안의 모든 정수 입력을 승인한다”이고, 허용 범위를 결정 D1이 정하는 예다. 0~90을 승인하는 구현을 고정하고 D1을 0~100에서 0~90으로 완화하자 미충족 입력은 91~100의 10개에서 0개로 줄었다. 두 spec의 AC 행은 글자 단위로 같았다. 이 사례의 판정은 감사인이 채점하며 테스트 파일 수정은 필요 없다.

issue-work 193·217·220행은 완료 확인 중 결정의 완화를 승인할 수 있게 한다. 195행과 git-pr 268~270행의 판정 재사용 검사는 AC 원문을 비교한다. 따라서 완료 확인 뒤 곧바로 PR로 가면 예전 D1을 적용한 판정이 복사된다. 별도 회차에서 D1을 바꾸면 167행이 재감사를 요구하므로 그 경로는 정상이다.

</details>
