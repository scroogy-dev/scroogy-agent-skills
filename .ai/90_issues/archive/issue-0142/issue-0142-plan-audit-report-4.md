- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 기능
- **관점**: 범위와 검증
- **계보**: F-14 잔여
- **권장 조치**: 승인된 작업 트리 기준을 이슈 범위·AC2와 일치시키고, Task 7의 브랜치 모드 점검에 인덱스에만 남은 변경을 추가한다.
- **완료 기준**:
  - 이슈 범위와 AC2에서 작업 트리 기준과 인덱스에만 남은 변경의 처리 방식이 드러난다.
  - Task 7이 스테이징한 파일의 작업 트리 내용만 원래대로 되돌린 사례를 만들고, 그 파일의 수집 여부를 승인된 기준에 따라 판정한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

스펙 528~531행과 Task 2는 인덱스에만 남은 변경을 제외하는 결정을 기록한다. 현재 GitHub 본문은 여전히 “커밋하지 않은 변경 포함”이라고 적는다. Task 7에는 일반 미커밋 변경·미추적 파일·워크스페이스 산출물 사례가 있으며 인덱스에만 남은 변경은 점검하지 않는다. [GitHub Issue #142](https://github.com/scroogy-dev/scroogy-agent-skills/issues/142) · [Task 7](./issue-0142-plan.md#L565)

임시 저장소에서 파일을 스테이징하고 작업 트리만 되돌리면 상태가 `MM entry.txt`로 남는다. 계획의 merge-base 기준 diff는 비어 있고 `git diff --cached`에는 파일이 나온다. 인덱스에만 남은 변경을 포함하는 구현도 현재 Task 7의 기대값을 통과할 수 있다.

</details>

#### F-18: 16진수 브랜치 이름이 동기화 표지로 통과한다

- **위험도**: 🟢 낮음(LOW)
- **영향 축**: 기능 저하
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 테스트
- **관점**: 모호성과 검증
- **계보**: F-16 잔여
- **권장 조치**: 두 검사에서 입력이 실제 커밋 객체 ID 또는 유일한 축약형인지 확인한다. 유일성을 검사한 뒤 확정한 객체 ID로 선후 관계를 대조한다.
- **완료 기준**:
  - 최신 소스 커밋의 실제 전체 해시 및 허용하는 유일한 축약 해시는 통과한다.
  - `HEAD`와 객체 ID의 접두사에 해당하지 않는 16진수 브랜치 이름은 두 검사에서 위반으로 처리한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

임시 저장소에서 최신 소스 커밋을 가리키도록 `deadbee` 브랜치를 만들었다. R11과 Task 8의 명령은 같은 커밋의 실제 해시와 `deadbee` 모두에 위반을 출력하지 않았고, `HEAD`에는 위반을 출력했다. 형식 검사와 `git cat-file -e "${h}^{commit}"`는 커밋을 가리키는 16진수 브랜치 이름을 통과시키므로, 모델이 기록한 동기화 표지가 후속 커밋을 따라 움직일 수 있다.

</details>
