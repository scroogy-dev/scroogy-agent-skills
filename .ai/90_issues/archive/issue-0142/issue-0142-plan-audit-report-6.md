### 상세 분석

#### F-20: 브랜치 모드가 인덱스에서 빠진 파일의 실제 변경을 놓친다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 범위 및 누락된 검증
- **계보**: 신규. F-19의 완료 기준 세 가지는 일반 파일의 존부와 내용 비교다. 이번에 재현한 이름 변경 판정과 실행 권한 변경은 기존 점검에 없던 경우다.
- **권장 조치**: Task 2의 변경 목록과 변경 줄을 merge-base와 실제 작업 트리 상태로 확정한다. Task 7에 아래 두 재현 사례를 더해 경로별 변경 종류와 내용 또는 모드를 대조한다.
- **완료 기준**:
  - 기준의 `a.txt`를 인덱스에서만 지우고 같은 내용의 `b.txt`를 추가한 뒤 작업 트리의 `a.txt`를 수정하면, `a.txt`의 수정 줄과 `b.txt`의 추가를 각각 한 번 수집한다.
  - 실행 권한을 추적하는 저장소에서 인덱스에서만 지운 파일의 실행 권한을 바꾸면, 본문이 같아도 작업 트리의 모드 변경을 한 번 수집한다.
  - Task 7이 두 사례의 준비 상태와 실제 수집 결과를 기록하고 F-19의 기존 세 사례도 계속 확인한다.

<summary>근거·상세 설명 펼치기</summary>

- 임시 저장소의 기본 설정에서 `a.txt`를 인덱스에서만 지운 뒤 같은 내용의 `b.txt`를 복사해 스테이징하고 `a.txt`에 줄을 추가했다. Task 2의 두 조회는 각각 `R100 a.txt b.txt`와 미추적 `a.txt`를 출력했다. 삭제 경로만 재검사하는 분기는 적용되지 않는다. 이때 patch에는 이름 변경 메타데이터만 있고 `b.txt`의 추가 줄은 없다. 별도 인덱스로 실제 작업 트리와 비교하면 `M a.txt`와 `A b.txt`가 나왔다.
- `tool.sh`를 인덱스에서만 지운 뒤 실행 권한을 추가하니 Task 2가 비교하는 두 내용 해시는 같았다. 해당 분기는 경로를 제외하지만, 작업 트리의 모드를 비교하면 `100644 → 100755` 변경이 있다.
- 두 경우 모두 AC2에 해당하는 작업 트리 변경이다. Task 7의 기존 세 사례는 개별 일반 파일의 삭제·수정·유지를 다뤄 두 분기를 재현하지 않는다. [GitHub Issue #142](https://github.com/scroogy-dev/scroogy-agent-skills/issues/142) · [Task 2](./issue-0142-plan.md#L215) · [Task 7](./issue-0142-plan.md#L569)
