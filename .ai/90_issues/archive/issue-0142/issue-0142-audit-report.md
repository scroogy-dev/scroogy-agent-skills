### 상세 분석

#### F-14: URL 오류 메시지가 입력 원문을 표준 오류에 기록한다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단. 유효한 자격 증명이 기록되면 해당 자격 증명의 기밀성이 깨진다.
- **발생확률 축**: 특수 조건·엣지. 입력에 자격 증명이 있고 URL 해석에도 실패해야 한다.
- **카테고리**: 보안
- **관점**: 부작용
- **계보**: 신규
- **권장 조치**: 형식 오류 메시지에는 잘못된 인자 이름과 기대 형식만 기록한다.
- **완료 기준**
  - [ ] 원격 URL과 PR 입력 각각의 형식 오류에서 종료 코드 2, 빈 표준 출력, 원인을 설명하는 표준 오류 1행을 유지한다.
  - [ ] 가상 식별 문자열을 넣은 테스트에서 진단 출력에 사용자 정보나 원본 URL이 남지 않는다.

<details>
<summary>코드 근거 펼치기</summary>

80행은 정규화 실패 시 원본 `remote_url`을, 94·99행은 입력 오류 시 원본 `pr`을 `fail`에 전달한다. `fail`은 메시지를 표준 오류에 그대로 쓴다. 실행 로그를 보관하는 환경에서는 입력 URL에 들어 있던 인증 정보도 함께 보관될 수 있다. 이 판단은 코드 경로를 읽은 결과이며 실제 자격 증명의 노출을 관측한 것은 아니다.

</details>

#### F-15: 트리 응답에서 읽는 필드를 바꿔도 조회 테스트가 통과한다

- **위험도**: 🟢 낮음(LOW)
- **영향 축**: 기능 저하. 회귀가 들어와도 테스트가 알려 주지 않는다.
- **발생확률 축**: 특수 조건·엣지. 필드 선택이 잘못 바뀌고 로컬에 PR head가 없는 경로를 쓸 때 드러난다.
- **카테고리**: 테스트
- **관점**: 누락된 검증
- **계보**: 신규. F-7의 고정 SHA, F-13의 링크 종류 구분은 각각 닫혔다.
- **권장 조치**: 일반 파일과 링크가 함께 든 트리 응답에서 실제 조회 필터가 반환한 값을 기준으로 Contents 호출 여부를 검증한다.
- **완료 기준**
  - [ ] 현재 필터는 일반 파일의 모드를 읽어 Contents를 호출하고 링크는 건너뛴다.
  - [ ] 필터의 마지막 선택을 `.mode`에서 `.sha`로만 바꾼 사본이 Task 2의 해당 검사에서 실패한다.

<details>
<summary>변형 사본 대조 펼치기</summary>

대역은 인자에 경로 비교 문자열이 있는지만 보고 미리 지정한 모드를 반환한다. 로컬 JSON 예제에서 원본 필터를 평가하면 `100644`, 필드만 바꾼 필터는 `abc123`을 반환했다. 구현의 분기는 해시를 일반 파일 모드로 인정하지 않아 Contents를 건너뛴다. 그 변형을 적용한 임시 사본에서 스펙 711행은 종료 코드 0·위반 0행이었다. 같은 사본의 git-review 러너도 221건 통과·0건 실패였다. 로컬 JSON 응답을 실제 필터로 처리하는 대조군에서는 원본이 일반 파일 두 종류를 조회했고 변형 사본은 두 파일을 모두 읽기 실패로 처리했다.

</details>
