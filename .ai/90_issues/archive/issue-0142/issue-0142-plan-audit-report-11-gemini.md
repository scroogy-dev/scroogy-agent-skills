### 상세 분석

#### F-29: 표시한 경로 조회의 `tr '\0' '\n'` 선행 변환이 줄바꿈 파일명에서 오탐·경로 잘림을 일으킨다

- **위험도**: 🟢 낮음(LOW)
- **영향 축**: 기능 저하
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스 · 모호성
- **계보**: 신규
- **권장 조치**: 등급별 기본 처리 기준에 따라 원장(`.ai/70_ledger/`)에 이관하거나, 구현 전 승격해 NUL 레코드 단위로 표지를 먼저 판정하는 명령(`while IFS= read -r -d '' rec`)으로 바꾼다.
- **완료 기준**:
  - 원장 이관 시: 수용 사유와 재검토 조건을 적은 원장 항목이 등재된다.
  - 보정 승격 시: 이름에 줄바꿈이 든 일반 추적 파일(`foo\nh bar.txt`)은 출력에 나오지 않고, `skip-worktree`로 표시한 줄바꿈 파일(`line\nfeed.txt`)은 경로 앞부분만 잘려 나오지 않도록 Task 2 3단계 명령과 spec 10차 전제를 맞춘다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 10차 보정에서 Task 2 3단계 표시한 경로 조회를 `git ls-files -v -z | tr '\0' '\n' | grep '^[a-zS] '`로 바꿨다. 같은 10차에서 `collect-branch-changes.sh`는 줄바꿈이 든 경로(`line\nfeed.txt`)를 명시적으로 다루지만, `tr '\0' '\n'`은 표지 검사 전에 NUL 경계를 없애 파일명 안의 줄바꿈을 새 레코드 시작으로 만든다.
- **재현**: 로컬 Git 2.50.1 임시 저장소에서 일반 추적 파일 `foo\nh bar.txt`(표시 없음)와 `skip-worktree` 파일 `line\nfeed.txt`를 두고 계획의 명령을 실행하자 `h bar.txt`(미표시 파일 오탐)와 `S line`(경로 잘림) 두 행이 출력됐다.
- **영향**: 줄바꿈이 든 추적 파일이 없는 저장소에서는 재현되지 않으며, 발견 재확인은 최종적으로 merge-base 커밋과 patch를 따르므로(Task 2·Task 4 안전망) 스펙의 네 보장을 직접 차단하지는 않는다. 다만 줄바꿈 파일이 있는 저장소에서는 존재하지 않거나 표시하지 않은 경로가 표시한 경로 목록에 섞여 탐색 시 잘못된 출처를 읽을 수 있다.
