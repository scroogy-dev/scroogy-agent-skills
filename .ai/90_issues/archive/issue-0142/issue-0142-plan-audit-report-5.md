### 상세 분석

#### F-19: 인덱스에만 남은 삭제가 브랜치 모드 리뷰에 들어간다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 범위 및 누락된 검증
- **계보**: 신규. F-17에서 요구한 수정 후 되돌림 사례와 별개인 스테이징 삭제 경로다.
- **권장 조치**: Task 2에서 merge-base에 있던 경로는 실제 작업 트리의 존부와 내용으로 변경을 확정한다. Task 7에 스테이징한 삭제의 확인 사례를 추가한다.
- **완료 기준**:
  - 추적 파일을 인덱스에서만 삭제하고 작업 트리에 기준 내용으로 남기면 수집 목록에 그 경로가 없다.
  - 같은 경로의 작업 트리 내용이 바뀌면 수정으로 한 번 수집하고 실제로 파일이 사라지면 삭제로 한 번 수집한다.
  - Task 7이 인덱스와 작업 트리의 상태를 확인하고 각 사례의 변경 파일 목록과 변경 유형을 대조한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

임시 저장소에서 `entry.txt`를 커밋하고 `git rm --cached -- entry.txt`를 실행했다. 작업 트리의 내용은 그대로였고 상태는 `D  entry.txt`와 `?? entry.txt` 두 줄이었다. Task 2의 첫 명령인 merge-base 기준 `git diff`는 `D entry.txt`를, 두 번째 명령인 `git ls-files --others --exclude-standard`는 미추적 `entry.txt`를 출력했다.

작업 트리 파일의 내용을 바꿔도 두 목록에는 각각 같은 삭제·미추적 항목이 나왔다. 실제로 파일을 지우면 diff의 삭제 항목만 남았다. Task 7은 추적 파일을 수정하고 내용을 되돌린 `MM` 상태만 재현하므로 이 분기를 확인하지 못한다. [Task 2](./issue-0142-plan.md#L213) · [Task 7](./issue-0142-plan.md#L565)

</details>
