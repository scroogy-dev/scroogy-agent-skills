### 상세 분석

#### F-24: 변경 줄과 인용 위치를 서로 다른 내용에서 읽는다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 모호성 · 누락된 검증
- **계보**: 신규. K-0031은 인덱스 내용을 수집하는 동작을 수용했다. 이 발견은 수집한 내용을 재확인하는 단계에 관한 것이다.
- **권장 조치**: 브랜치 모드의 주변 코드 읽기와 인용 위치 재확인에서 수집한 스냅샷과 일치하는 내용을 사용하도록 Task 2·4에 명시한다. 같은 내용을 확보하지 못하면 확인하지 못한 이유를 남긴다.
- **완료 기준**:
  - `assume-unchanged`와 `skip-worktree`를 각각 쓴 경로에서 인덱스와 작업 트리 내용이 다를 때 주변 코드와 인용 위치를 수집 대상에 맞춰 읽는다.
  - 변경 줄에 있는 발견 후보가 작업 트리에 해당 줄이 없다는 이유로 누락되지 않는지 확인하는 사례가 계획에 있다.

<details>
<summary>근거·상세 설명 펼치기</summary>

임시 저장소에서 두 파일에 `indexed`를 스테이징하고 작업 트리를 `base`로 되돌린 뒤 `assume-unchanged`와 `skip-worktree`를 각각 설정했다. Task 1의 명령으로 수집한 patch에는 두 파일 모두 `+indexed`가 나왔다. Task 2가 지시하는 작업 트리 읽기는 두 파일 모두에서 `base`를 반환했다. Task 4는 재확인에서 성립하지 않는다고 판단한 발견을 기록하지 않으므로 이 차이가 AC9의 인용 검증과 결과에 영향을 준다. [Task 2](./issue-0142-plan.md#L268) · [Task 4](./issue-0142-plan.md#L365)

</details>

#### F-25: 무시 설정이 하위 모듈의 커밋 변경도 숨긴다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 범위 · 누락된 검증
- **계보**: 신규
- **권장 조치**: 목록과 patch를 만드는 두 diff에서 하위 모듈의 커밋을 비교하도록 옵션을 명시하고 Task 1 러너에 사례를 둔다.
- **완료 기준**:
  - `.gitmodules`에서 `ignore = all`을 사용해도 기준과 스냅샷의 하위 모듈 커밋이 다르면 변경 목록에 한 번 나오고 patch에 두 커밋의 차이가 나온다.
  - 하위 모듈이 같은 커밋을 가리키고 내부의 미커밋 파일만 달라졌을 때는 목록에 나오지 않는다.

<details>
<summary>근거·상세 설명 펼치기</summary>

임시 저장소에서 하위 모듈이 새 커밋을 가리키게 한 뒤 Task 1의 두 `git add` 명령을 실행했다. `git ls-tree HEAD`와 임시 인덱스의 `git ls-files -s`에서 서로 다른 커밋을 확인했다. 계획의 diff 명령은 빈 목록을 냈고, `--ignore-submodules=dirty`를 지정하자 `M` 표지가 붙은 `modules` 한 행이 나왔다. 같은 옵션으로 patch에 두 커밋이 나타났고 실제 커밋에도 포인터 변경이 들어갔다. 하위 모듈 내부에만 미커밋 파일을 추가한 경우에는 출력이 비었다. [스펙 전제](./issue-0142-spec.md#L637) · [Task 1](./issue-0142-plan.md#L173)

</details>
