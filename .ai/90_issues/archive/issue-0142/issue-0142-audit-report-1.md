### 상세 분석

#### F-1: 스테이징 필터가 원본 `.git`에 파일을 쓴다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 부작용
- **계보**: 신규
- **관련 범위**: R1 · AC2
- **권장 조치**: 필터의 스테이징 결과와 원본 저장소 무변경을 함께 보장하도록 수집 방식을 보정한다.
- **완료 기준**
  - [ ] 캐시를 쓰는 필터로 수집한 전후에 원본 `.git` 파일 목록과 내용이 같다.
  - [ ] 필터가 만든 스테이징 내용은 실제 커밋과 일치하고, 기존 방식에서는 회귀 테스트가 실패한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

임시 인덱스와 객체 디렉토리를 지정해도 `git add`의 clean 필터는 원본 작업 디렉토리에서 실행된다. 임시 저장소에서 입력을 그대로 통과시키면서 `.git/filter-last-input`에 캐시하는 필터를 설정했다. 헬퍼는 종료 코드 0과 `A sample.txt`를 반환했고 실행 전에 없던 캐시 파일이 원본 `.git`에 남았다. K-0031도 저장소 무변경을 수용 범위 밖의 보장으로 명시한다.

</details>

#### F-2: 텍스트를 바이너리로 표시하는 Git 설정에서 변경 줄이 사라진다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스
- **계보**: 신규
- **관련 범위**: R1·R5 · AC2·AC6
- **권장 조치**: Git의 표시 설정 때문에 생략된 텍스트 변경을 복원해 읽을 수 있게 한다.
- **완료 기준**
  - [ ] 낮은 `core.bigFileThreshold`에서도 텍스트 파일의 추가·삭제 줄을 확인하고 해당 patch로 스테이징 트리를 재구성할 수 있다.
  - [ ] 실제 바이너리는 기존 사유로 집계하고 텍스트 반례와 구분하는 테스트가 통과한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

`core.bigFileThreshold=8`인 임시 저장소에 ASCII 한 줄짜리 `job.py`를 추가했다. 헬퍼는 성공하고 파일 목록에도 올렸지만 patch에는 `Binary files /dev/null and b/job.py differ`만 있었다. 기준 트리에서 `git apply --cached`가 종료 코드 1을 냈고 실제 `git add`의 blob에는 `print(123456789)`가 있었다. 새 파일이어서 merge-base에서도 해당 줄을 읽을 수 없다. 스펙이 사례에서 제외한 실제 바이너리와 달리 입력은 텍스트 소스였다.

</details>

#### F-3: Contents API가 파일 이름의 `#` 뒤에 있는 경로와 고정 SHA를 잃는다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스
- **계보**: 신규
- **관련 범위**: R3·R9 · AC4·AC9
- **권장 조치**: 경로 구성 요소를 URL 인코딩하고 고정 SHA를 독립된 쿼리 값으로 전달한다.
- **완료 기준**
  - [ ] 로컬 객체가 없고 `app/a`와 `app/a#b.py`의 내용이 다를 때, 후자의 PR head 내용으로 인용을 확인한다.
  - [ ] 예약 문자가 있는 경로의 요청에서 서버가 받은 경로와 `ref` 값이 각각 원래 파일 이름과 고정 SHA다.

<details>
<summary>근거·상세 설명 펼치기</summary>

로컬에 고정 커밋이 없을 때 예시는 파일 경로를 URL에 그대로 넣는다. `app/a#b.py`를 대입해 URL을 분해하면 HTTP 경로가 `…/contents/app/a`에서 끝나고 쿼리가 비었다. 이 조건에서 `app/a`가 기본 브랜치에 있으면 다른 파일을 정상 응답으로 읽을 수 있다. `gh` 2.88.1은 전달받은 경로를 API 접두사에 이어 붙이며, Contents API는 `ref` 생략 시 기본 브랜치를 사용한다. 실제 원격 응답은 호출하지 않았다. [GitHub CLI 2.88.1 소스](https://github.com/cli/cli/blob/v2.88.1/pkg/cmd/api/http.go) · [GitHub Contents API](https://docs.github.com/en/rest/repos/contents#get-repository-content)

</details>

#### F-4: 기존 대체 객체 디렉토리를 덮어쓰면 기준 커밋을 잃는다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 암묵적 가정
- **계보**: 신규
- **관련 범위**: R1 · AC2
- **권장 조치**: 호출 환경이 참조하던 객체 디렉토리를 임시 스냅샷에서도 조회할 수 있게 한다.
- **완료 기준**
  - [ ] 기준 커밋이 기존 대체 객체 디렉토리에만 있어도 수집이 성공한다.
  - [ ] 목록과 patch가 실제 스테이징 결과와 일치하고 원래 객체 저장소의 내용이 보존된다.

<details>
<summary>근거·상세 설명 펼치기</summary>

`GIT_ALTERNATE_OBJECT_DIRECTORIES`로 공유 객체 저장소를 연결한 임시 작업 트리에서 `git rev-parse HEAD^{tree}`와 실제 `git add`가 성공했다. 헬퍼는 같은 환경에서 기준 커밋을 처음에는 해석했으나 임시 객체 경로를 설정한 뒤 목록을 만드는 `diff-index`에서 `fatal: bad object`로 종료했다. 기존 환경 변수의 객체 경로가 사라졌다.

</details>

#### F-5: Git이 경로를 문자 그대로 받는 환경에서 브랜치 수집이 중단된다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 암묵적 가정
- **계보**: 신규
- **관련 범위**: R1 · AC2
- **권장 조치**: 헬퍼가 작성한 제외식의 의미를 호출 셸의 Git 경로 해석 설정과 독립시킨다.
- **완료 기준**
  - [ ] 기본 환경과 `GIT_LITERAL_PATHSPECS=1`에서 같은 일반 변경과 patch를 얻는다.
  - [ ] 두 환경 모두 작업공간의 미추적 파일은 제외하고 그 경로에 이미 추적된 파일의 수정은 수집한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

일반 파일과 제외 대상인 `.ai/99_workspace/excluded.md`가 있는 임시 저장소에서 `GIT_LITERAL_PATHSPECS=1`을 설정했다. `git add -A`는 내부 제외식을 실제 파일명으로 해석했다. 헬퍼는 `pathspec ':(exclude).ai/99_workspace' did not match any files`, 빈 표준 출력, 종료 코드 1을 내고 리뷰를 중단했다.

</details>

- **관점**: 누락된 검증
