- **완료 기준**
  - 변경 줄이 참조하는 주변 파일이 변경 목록에 없어도, Git 내용 변환 필터로 작업 트리와 스냅샷 내용이 다를 때 수집한 스냅샷과 일치하는 값을 읽는다. 그 값을 확인할 수 없으면 확인하지 못한 사유를 남긴다.
  - 주변 파일의 값이 발견 성립 여부를 결정하는 사례를 모의 실행 또는 실제 실행 점검에 두어, 작업 트리의 값으로 판단하면 실패하게 한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

임시 저장소에서 `settings.txt`의 작업 트리 값을 `enabled=false`로 두고, Git `clean` 필터가 스테이징할 때 `enabled=true`로 변환하게 했다. 이를 기준 커밋에 넣은 뒤 `main.txt`에만 `settings.txt`를 참조하는 줄을 추가했다. Task 1 명령으로 임시 인덱스를 만든 결과, `git show ':settings.txt'`는 `enabled=true`를 반환했다. `settings.txt`는 변경 목록과 patch에 없었고, Task 2가 지정한 작업 트리 읽기는 `enabled=false`를 반환했다. Task 4에서 주변 파일을 다시 읽어도 작업 트리의 같은 값이 나온다. patch 불일치 분기는 그 파일에 대응하는 hunk가 없어 작동하지 않는다. 이 사례에서는 변경 목록에 없는 주변 파일의 blob을 merge-base에서 읽으면 스냅샷과 같은 값을 얻을 수 있다. [Task 1 스냅샷](./issue-0142-plan.md#L166) · [Task 2 읽기](./issue-0142-plan.md#L282) · [Task 4 재확인](./issue-0142-plan.md#L386)
