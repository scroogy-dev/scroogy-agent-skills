#### F-12: 작업 트리 안에 놓인 Git 실행기 캐시가 변경 파일로 집계된다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 부작용
- **계보**: F-9 잔여. 기존에 새던 임시 인덱스·객체는 제외된다. 이번에는 그 상위 경로에 호출 과정에서 생긴 파일이 남는다.
- **권장 조치**: 첫 Git 호출부터 자식 프로세스가 만드는 임시 파일을 격리하고, 실행 전부터 있던 사용자 파일은 수집한다.
- **완료 기준**
  - [ ] 작업 트리의 빈 `scratch/`를 TMPDIR로 둔 깨끗한 저장소에서 `--base`가 종료 코드 0·빈 출력을 내며 호출 때문에 새로 남은 파일도 없다.
  - [ ] 같은 경로에 사용자가 `user.txt`를 미리 두면 그 파일만 추가로 나오고 patch에 사용자 내용이 있다. 시스템 Git과 Git 본체 양쪽에서 확인한다.

<details>
<summary>macOS 대조 실험 펼치기</summary>

스펙 412행 그대로 실행하면 첫 호출 목록에 `A scratch/xcrun_db`가 나오고, 두 번째 호출에는 사용자 파일과 캐시가 함께 잡힌다. 최초 `git rev-parse --show-toplevel`는 헬퍼가 전용 임시 디렉토리를 만들기 전인 87행에서 실행된다. 별도 빈 임시 디렉토리에 TMPDIR를 지정해 `/usr/bin/git rev-parse --show-toplevel`만 실행해도 같은 파일이 생겼다. 내용 변환 필터는 사용하지 않았다.

같은 샌드박스에서 Xcode Git 본체를 PATH 앞에 두면 412행은 위반 0행이다. 샌드박스 밖 기본 Git에서도 412행이 통과했다. git-review 러너는 샌드박스 안에서 208건 통과·2건 실패, 밖에서 210건 통과였다. 이번 판정은 샌드박스와 작업 트리 내부 TMPDIR를 함께 사용한 관측에 한정한다.

#### F-13: 이름만 바뀐 심볼릭 링크에는 Contents 조회를 거를 모드 행이 없다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스
- **계보**: F-11 잔여. 모드가 표시되는 추가·수정 경로에는 2차 보정이 적용된다.
- **권장 조치**: 이름 변경으로 파일 모드를 알 수 없고 head 객체도 로컬에 없으면 고정 SHA의 트리에서 종류를 확인한다. 링크 객체를 읽을 수 없으면 인용에 확인 필요를 표시한다.
- **완료 기준**
  - [ ] 서로 다른 디렉토리 사이에서 링크 대상 문자열을 유지한 채 이동한 파일도 로컬 읽기와 폴백이 같은 링크 문자열을 확인하거나, 폴백에서 확인할 수 없음을 표시한다.
  - [ ] 이동한 링크가 가리키는 일반 파일 본문을 링크 자체의 인용 근거로 쓰지 않는다. 일반 파일 이동은 계속 고정 SHA에서 정상 조회한다.

<details>
<summary>링크 이동 재현과 API 근거 펼치기</summary>

임시 저장소에 `old/target.txt`와 `new/target.txt`를 서로 다른 내용으로 만들고, `old/link → target.txt`를 `new/link`로 옮겨 커밋했다. 다음은 그 두 커밋 사이의 diff 전부다.

```diff
diff --git a/old/link b/new/link
similarity index 100%
rename from old/link
rename to new/link
```

`git ls-tree HEAD new/link`의 모드는 `120000`, `git show HEAD:new/link`의 값은 `target.txt`, 새 위치에서 링크를 따라간 파일의 본문은 `new payload`였다. 스펙이 범위 밖으로 둔 ‘diff에 나오지 않은 링크’와 달리 이 링크는 변경 목록에 있다. 상대 경로라 이동으로 가리키는 파일도 바뀌었지만 diff 머리 행에는 모드가 없다. 경로 문자도 모두 허용되므로 139행의 제외 요건이 성립하지 않는다. 이 경우 GitHub가 저장소 안 일반 파일을 가리키는 링크의 Contents 요청에 대상 파일 본문을 돌려준다는 계약을 적용하면 폴백의 인용 대상이 달라진다. 이동 diff는 로컬에서 재현했으며 원격 PR에 게시하거나 이 예제의 Contents API를 실호출하지 않았다. [GitHub Contents API](https://docs.github.com/en/rest/repos/contents#get-repository-content)

</details>
