### Task 1: summary 템플릿에 effort 열·수행 effort 필드·값 규칙 추가

- [x] 완료
- **목표**: `issue-summary-template.md`가 모델 기록 표와 Task 블록에 effort를 담고, 값 규칙을 주석으로 안내한다.
- **대상 요구사항**: R1, R2, R3
- **작업 내용**:
  1. `## 모델 기록` 표를 `| 구분 | 모델 | effort |` 3열로 바꾸고, 4행의 effort 셀에 주석 placeholder(도구가 기록한 표기 그대로, 확인 불가면 `-`)를 둔다. 주석에 `|`를 쓰지 않는다.
  2. 표 위 주석에 effort 규칙을 더한다. 도구가 기록한 표기(`high`, `xhigh` 등) 그대로, 벤더가 다르면 비교하지 않음, 확인 불가 시 `-` 허용, effort는 벤더 교차 조건 등 게이트에 쓰지 않음.
  3. Task 0·Task 1·Task 2 블록의 `- **수행 모델**: -` 바로 다음 행에 `- **수행 effort**: -`를 추가한다. Task N 블록에는 두지 않고, 그 블록 주석에 `수행 effort`도 `최종 audit 모델` 행이 SSoT라는 한 줄을 더한다.
  4. `## Task별 수행 결과` 주석을 갱신한다. "지표 4종"을 "지표 5종"으로 고치고, `수행 effort` 항목 설명(도구 표기 그대로, ` / ` 나열은 `수행 모델`과 같은 순서, `-`는 확인 불가 시 허용)을 추가한다. 두 목록의 위치 대응 규칙(항목 수 동일, 같은 모델이 effort를 바꿔 다시 수행했으면 모델도 그 자리에 반복, 확인 불가 값은 그 자리에 `-`, 같은 effort는 그대로 반복)과 예시(모델 `A / A / B`에 effort `high / low / high`, 모델 `A / B`에 effort `high / -`)를 `수행 effort` 설명에 넣고, `수행 모델` 항목 설명에도 "같은 모델이 effort를 바꿔 다시 수행했으면 그 자리에 반복해 적는다"를 더한다(계획 감사 F-2). 모델별 집계 grep 스니펫의 필드 목록에 `수행 effort`를 넣는다. `계획 감사` 줄 주석의 "지표 4종"도 같이 고친다.
  5. 이 이슈의 선반영 summary([issue-0102-summary.md](./issue-0102-summary.md), 작성 시점 경로는 `.ai/90_issues/active/issue-0102/issue-0102-summary.md`, --clear로 이관)의 `## Task별 수행 결과` 주석을 4의 템플릿 문장과 같게 맞춘다.
- **완료 기준**:
  - [D] spec R1 [D] 항목의 표 검사 통과  (검증: spec R1 검증 명령 실행, 출력 0건)
  - [D] spec R2 [D] 항목 3건 통과  (검증: spec R2 검증 명령 실행. 블록 검사 0, 기본값 3건, 템플릿 파일 한정으로 `grep -c '지표 4종' issue-work/templates/issue-summary-template.md`가 0)

### Task 2: SKILL.md 갱신 절차에 effort 기록 규칙과 읽는 위치 기재

- [x] 완료
- **목표**: 구현 AI가 Task 완료 시 `수행 effort`를 어디서 읽어 어떻게 적는지 SKILL.md만 보고 알 수 있다.
- **대상 요구사항**: R4
- **작업 내용**:
  1. `## 작업 진행 중`의 Task 완료 시 summary 갱신 항목에서 "지표 4종(`수행 모델`·`audit 발견`·`보정 반영`·`재시도`)"을 "지표 5종(`수행 모델`·`수행 effort`·`audit 발견`·`보정 반영`·`재시도`)"으로 고친다. 같은 항목의 헬퍼 설명 문장("표기가 깨진 필드(`-`·비수치·필드 누락·Task N 블록의 지표)")에 검사 대상이 수치 3종(`audit 발견`·`보정 반영`·`재시도`)뿐임을 명시해, `수행 effort`의 `-`가 위반으로 읽히지 않게 한다(계획 감사 F-3).
  2. 같은 항목 아래에 `수행 effort` 기록 규칙 소절을 더한다. 값은 도구가 기록한 표기 그대로, 구현 AI가 자기 세션 값을 읽어 채움, 읽는 위치는 실행 기록 우선(Claude Code: `~/.claude/projects/<repo>/*.jsonl`의 assistant 항목 `model`·`effort` 또는 셸 환경변수 `CLAUDE_EFFORT`. Codex: `~/.codex/sessions/<년>/<월>/<일>/rollout-*.jsonl`의 `turn_context` 레코드 `payload.model`·`payload.effort`), 설정 파일(`~/.claude/settings.json`의 `effortLevel`·`modelSettings.<모델>.effortLevel`, `~/.codex/config.toml`의 `model_reasoning_effort`)은 모델별 재정의로 실제 적용값과 다를 수 있어 보조로만 씀, 로컬 기록이 없는 도구(ChatGPT 웹·앱)는 화면에서 고른 값을 사람이 적음, 확인할 수 없으면 `-`, audit 모델의 effort(표의 계획 audit·최종 audit 행)는 사용자가 적음. 도구 이름과 경로는 기록 위치 안내이며 특정 모델·벤더를 절차 조건에 넣는 것이 아니다.
  3. 표 행을 채우는 시점 문장 3곳에 effort 병기를 더한다. 3-2(`계획 모델` 행), "새 이슈 시작 시" 5단계 수행 분기(`계획 audit 모델` 행), `## 작업 진행 중`·`## 이슈 완료 시`의 Task N 문장(`최종 audit 모델` 행). Task N 완료 조건은 모델 행 기록으로 유지하고 effort를 조건에 넣지 않는다.
  4. `## 관련 skill`의 issue-audit 항목 문장에서 summary 반영 대상에 effort를 병기한다.
- **완료 기준**:
  - [D] spec R4 [D] 항목 통과  (검증: spec R4 검증 명령 실행, 출력 0건)
  - [QD] spec R4 [QD] 항목(규칙 6가지)  (검증: 감사 모델이 채점)  ← 강등 사유: 규칙의 의미 충족은 명령으로 환원 불가
