- **영향 축**: 스펙·기능 달성 차단 — R6이 보장한 두 fixture의 각 Task 필드 존재를 완료 검사로 보장하지 못한다.

- **카테고리**: 테스트
- **관점**: 가짜 `[D]` 사전 판별·누락된 검증
- **계보**: 신규
- **권장 조치**: 두 fixture의 대상 Task를 구분하여 `수행 모델` 다음의 `수행 effort` 존재·개수를 검사하도록 R6 완료 기준을 보완한다. 실행 중인 스킬의 게이트를 확장할 필요는 없다.
- **완료 기준**:

#### F-2: effort 변경 이력과 모델 목록의 대응 단위가 정해지지 않았다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단 — 사후에 어떤 모델이 어떤 설정으로 수행했는지 복원할 수 없는 기록을 허용한다.
- **발생확률 축**: 특수 조건·엣지 — 한 Task에서 동일 모델의 effort 변경과 다른 모델로의 전환이 함께 발생할 때 드러난다.
- **카테고리**: 기능
- **관점**: 모호성
- **계보**: 신규
- **권장 조치**: R3·Task 1에 모델 목록과 effort 목록의 대응 단위를 명시한다. 각 모델 항목의 `벤더, 모델명` 형식은 유지하면서 반복 모델·동일 effort·확인 불가 값을 어떻게 기록할지 예시로 고정한다.
- **완료 기준**:
  - 동일 모델 `high → low` 수행의 두 기록이 어느 모델에 속하는지 유일하게 해석된다.
  - `A/high → A/low → B/high`와 `A/high → B/low → B/high`가 서로 다른 기록으로 표현된다.
  - 여러 모델이 같은 effort를 쓰거나 일부 값이 `-`여도 대응 위치가 유지됨을 R3의 검증 기준에 넣는다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- spec:15·102와 plan:65는 `수행 모델`과 같은 순서로 ` / ` 나열만 요구한다. 기존 summary 템플릿:53~56은 관여한 모델 전부를 나열하도록 할 뿐, 동일 모델을 effort 변경마다 반복할지 정하지 않는다.
- 모델을 `A / B`, effort를 변경 이력인 `high / low / high`로 기록하면 위 두 수행 이력이 같은 결과가 된다. 반대로 모델까지 수행 구간마다 반복하는 해석도 가능하지만 spec·plan은 그 규칙을 선택하지 않았다.
- 이슈 원문의 문장은 R3에 빠짐없이 옮겨졌으므로 1단계 I4는 충족이다. 원문에서 이어진 모호성을 2단계에서 별도로 기록한다.

</details>
