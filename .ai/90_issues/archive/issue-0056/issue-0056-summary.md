`audit 발견`·`보정 반영` 모두 그 주 Task에서 1회만 세고 관련된 다른 Task에는 세지 않는다.
Task 축에서도 이슈 단위 합계가 중복으로 부풀지 않게 하기 위함이다(아래 회차 축 중복 제외와 같은 취지).

1건으로 세고(중복 제외), 새 회차 값으로 덮어쓰지 않는다. 보정률 사후 집계의 분모·분자가 회차 반복으로 부풀지 않게 하기 위함이다.

합계에서 조용히 빠지고, 전부 `-`면 합계 자체가 빈 문자열이 된다. `-` 허용은 비수치 필드(`수행 모델`)에만 둔다.

### Task 1: 판단 로직·제약 검증 개편 — 구현 난이도 평가 도입, 캐시 우선 규칙 제거

- **결과**: 완료
- **수행 모델**: Anthropic, Claude Opus 5 (claude-opus-5)
- **audit 발견**: 4건
- **보정 반영**: 4건
- **재시도**: 0회
- **수행 내용 요약**: `issue-model-triage/SKILL.md`의 `## 판단 로직`을 두 축(설계 판단 필요 여부 → 플랜 / 구현 난이도 → 구현) 구조로 개편. (1) 절 도입부에 두 축의 독립성을 명시, (2) `### 분류 기준`을 플랜 배정 전용으로 좁히고 구현 배정 분리를 안내, (3) `### 구현 난이도 평가` 절 신설 — 신호 3종(변경 범위·맥락 의존도·로직 복잡도) 표와 등급 3단계(낮음(LOW)/보통(MEDIUM)/높음(HIGH))별 배정 표, 최소 역량 배정 원칙·판정 보류·하드코딩 금지 승계, (4) `### 제약 검증`의 플랜·구현 항목을 "제약 없음"으로 교체하고 캐시 근거를 삭제. 검증 역할 제약(다른 모델 + 다른 벤더)은 그대로 유지.
- **특이 사항**: 역량 등급화 안내문의 등급 표기를 "최상위/하위"에서 "최상위/중위/하위"로 확장 — 난이도 3단계에 대응하는 중위 등급이 필요했다.
- **audit 보정 (1차, `--response`)**: 1단계 발견 1건 반영(F-3 제외, 요구사항 R1·DoD D4 부분 충족 근거이자 2단계 F-1, 같은 결함이라 1단계로 병합해 1건 집계, 중간(MEDIUM)) — 배정 원칙이 후보 풀 안의 상대 등급만 다뤄 "후보 전체가 요구 난이도에 미달"인 절대 판정 경로가 없었다. `### 구현 난이도 평가` 배정 원칙에 "후보 전체가 난이도를 감당하지 못하면 상대적 최상위를 억지 배정하지 않고 부족한 조건을 안내"와 등급화(상대 순위) ≠ 감당 여부(별개 판정) 구분을 추가했다. audit 권장의 실패 경로 절 신설 대신 원칙 한 줄 + 출력 분기 한 항목의 경량안을 택했다(경량 스킬 취지). 출력 분기 추가는 Task 2 산출물이지만 근본 수정이 배정 원칙이라 이 Task에 귀속한다.
- **audit 보정 (3차, `--response`)**: 2단계 발견 1건 반영(F-1, 중간(MEDIUM)) — 검증 역할에만 역량 축이 없어, 예시 1의 구현 중위 + 검증 하위 조합이 `issue-work/templates/issue-plan-template.md:106`의 audit 모델 조건(다른 벤더 + 최소 동급 이상 역량)과 충돌했다. **spec 범위를 확장해**(비포함(Out)의 검증 제약 변경 금지를 "완화·삭제 금지"로 좁히고 역량 하한 추가를 포함(In)으로 이동) `### 제약 검증`의 검증 항목에 "구현에 배정한 모델과 최소 동급 이상, 조건 만족 후보 중 최소"를 추가하고, 만족 불가 시 상위 대체 없이 실패로 안내함을 명시했다. `## 판단 로직` 도입부의 "검증은 두 축과 무관" 서술과 `## 관련 skill`의 issue-audit 근거 문구, `## 출력`의 제약 미충족 분기도 함께 정합화했다. spec DoD와 plan Task 1에 검증 행 총개수 + 3조건 포함을 함께 보는 `[D]` 항목을 추가했다. 예시 1 검증 행 교체(Opus 4.8 → Fable 5, Opus 4.8은 미선정으로 이동)와 예시 3 사유 보강은 Task 2 산출물이지만 근본 수정이 제약 규칙이라 이 Task에 귀속한다.
- **범위 확장 판단 근거**: `origin/main`의 예시 1도 같은 하한 위반이라 이번 이슈의 회귀는 아니었으나, 구현 축을 신설한 이슈가 검증 축의 공백을 남기고 끝나는 것이 어색해 이관 대신 이번 이슈에서 닫기로 사용자가 결정했다. audit 리포트의 권장 조치 (b)안(별도 이슈 이관) 대신 (a)안(범위 확장)을 택한 것이다.
- **audit 보정 (4차, `--response`)**: 발견 2건 반영 — 3차 보정으로 추가한 역량 하한 문구 자체의 결함이다.
  - **F-1 (1단계, 요구사항 R4·DoD D6 부분 충족(PARTIAL) 근거, 중간(MEDIUM))**: `### 제약 검증`의 금지 대상을 "역량 하한 미달은 후보를 **상위로 올려** 대체하지 않는다"로 잘못 적어, 같은 항목의 "조건을 만족하는 후보 중 가장 낮은 역량을 고른다"와 자기모순이 됐다. 예시 1은 구현 GPT-5.6(중위)에 대해 Anthropic 후보 중 동급이 없어 상위 Fable 5를 골랐는데, 잘못된 문장을 그대로 읽으면 이 정상 선택이 실패로 안내되어야 했다. 금지 대상을 **"하한 아래로 내려가 대체하지 않는다"**로 반전하고, 동급이 없어 위에서 최소를 고르는 것은 하한을 지킨 정상 선택임을 명시했다(구현 배정의 "위로 올리되 아래로 내리지 않는다"와 같은 원칙). spec `## 전제 (Assumptions)`의 "만족 불가 시 처리" 문구도 같이 정정했다.
  - **F-3 (2단계, 낮음(LOW))**: `## 관련 skill`에서 "다른 벤더 + 최소 동급 이상" 제약을 통째로 `issue-audit` 근거로 적었으나, `issue-audit/SKILL.md`에는 타벤더 요구만 있고 역량 하한은 `issue-work/templates/issue-plan-template.md`의 Task N에만 있다. 두 근거를 분리해 하한은 `issue-work` 항목으로, 타벤더는 `issue-audit` 항목으로 옮겼다. 이 과정에서 `issue-work` 항목이 중복 생성돼 기존 항목에 병합했다.
