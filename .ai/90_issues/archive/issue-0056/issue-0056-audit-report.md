### 상세 분석

#### F-1: 검증 모델 추천이 연동 워크플로우의 역량 하한을 보장하지 않음

- **위험도**: 중간(MEDIUM)
- **분류**: 부작용 / 암묵적 가정
- **설명**: 대상 스킬은 검증 모델에 구현과 다른 모델·다른 벤더만 요구한다. 예시 1은 GPT-5.6을 중위 구현 모델로, Claude Opus 4.8을 하위 검증 모델로 명시한다. 반면 이 스킬이 연결되는 `issue-work`의 마지막 고정 Task는 audit 모델이 구현 모델과 다른 벤더이면서 **최소 동급 이상 역량**이어야 한다고 규정한다.
- **영향**: 사용자가 추천을 그대로 따르면 모델·벤더 제약은 통과해도 후속 audit의 역량 조건을 위반한다. 더 낮은 역량의 검증 모델이 구현 결함을 놓칠 위험도 있다.
- **권장 조치**: 현재 스펙의 비포함 범위가 검증 역할 제약 변경을 금지하므로 자동 보정하지 않는다. (a) Issue #56 범위를 명시적으로 넓혀 검증 역량 하한·실패 분기를 추가하고 예시 1의 검증을 동급 이상 타벤더 모델로 바꾸거나, (b) 별도 이슈에서 `issue-model-triage`와 `issue-work`의 제약을 통일한다.
