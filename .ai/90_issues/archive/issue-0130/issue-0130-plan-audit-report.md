### 경계 검증

- 이슈 본문의 포함·제외 범위와 spec이 일치한다. R3·R12·R13·R14 및 포함 항목 AC 규칙은 이제 최신 본문 AC12~AC16에도 근거가 있다.
- 일반 Task 8개는 모두 R에 연결된다. Task 0·N은 고정 블록이며 구현 전 명령 판별 대상에서 제외했다.
- 새 `--ac`는 기존 헬퍼에 연결 검사만 추가한다. 의미상 완화·확장 판정은 감사인에게 남겨 과잉 설계로 보지 않았다.

### 도메인/계약 정합성

- GitHub 계약의 저장소 명시·본문 파일 전달·동적 인자 인용을 Task 2·5가 반영한다. 본문 전체 갱신은 초안 직전과 실행 직전 재조회·비교를 거친다.
- ADR 0011·0013·0016과 도메인 요건의 변경은 Task 8에 반영됐다. ADR 0019의 기능 Task별 테스트와 ADR 0025의 시퀀스 규칙을 유지한다.
- 계획 모델은 Anthropic, Claude Opus 5.5 (claude-opus-5-5)로 감사 모델 OpenAI와 벤더가 다르다. summary는 계획 모델 행만 대조했다.

## 검증 실행 기록

- 환경: repo 루트, `bash`. local 테스트 층·실행 셸이 빈 템플릿이므로 spec 전제 1을 적용했다.
- `check-plan.sh --trace <spec> <plan>`: 무출력·종료 코드 0. 번호 계승 헬퍼는 기존 1·2차 리포트로 다음 번호 3을 반환했고 신규 번호를 소비하지 않았다.
- GitHub 조회는 네트워크 제한 환경에서 실패한 뒤 읽기 권한으로 재실행해 성공했다. 최신 본문을 기준으로 판정했으며 조회 실패를 AC 부재로 간주하지 않았다.

- 일반 Task의 `[D]` 9개는 spec 명령 재실행 참조이므로 아래 결과를 공유한다. 고정 Task 0·N은 제외했다.
- 모델·effort는 현재 요청이 포함된 `rollout-2026-11-01T13-23-52-01a19559-7b8e-72e2-b716-4fd36585e72e.jsonl`의 동일 `turn_context`에서 확인했다.
