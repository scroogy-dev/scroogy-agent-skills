### 상세 분석

#### F-1: 첫 문장 제한이 원문 일부를 누락하고 추출 규칙을 이원화한다

- **위험도**: 중간(MEDIUM)
- **영향 축**: 기능 저하
- **발생확률 축**: 통상 사용
- **카테고리**: 기능
- **관점**: 암묵적 가정
- **계보**: F-1 잔여
- **권장 조치**: 설치된 skill 설명은 frontmatter `description` 전량을 원문 그대로 옮기고, 둘째 문장 이후가 모두 트리거라는 사실과 다른 설명을 제거한다.
- **완료 기준**:
  - 템플릿이 frontmatter `description` 전량을 요약·절단 없이 그대로 사용한다.
  - SKILL.md의 설명 추출 규칙과 템플릿의 보고 규칙이 동일하다.
  - 현재 skill들의 둘째 문장에 포함된 기능 설명이 설치 결과에서 누락되지 않는다.

<summary>근거·상세 설명 펼치기</summary>

- **설명**: 1차 보정은 자유 요약을 첫 문장 원문으로 고정했지만, SKILL.md는 한 줄 설명을 `description`에서 가져오도록 한다. 템플릿의 "둘째 문장 이후는 트리거 키워드" 전제와 달리 `install-skills`의 옵션 지원, `readme-sync`의 생성·재작성 분기, `git-pr`의 승인 게이트처럼 둘째 문장에 기능 설명이 있는 skill이 존재한다.
- **영향**: 출력 모양과 문구의 결정성은 개선됐지만, 선택한 skill의 주요 기능이 정상 보고에서 반복적으로 누락된다.
