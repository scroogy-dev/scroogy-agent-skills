- **영향 축**: 기능 저하

- **카테고리**: 기능
- **관점**: 암묵적 가정
- **계보**: 신규
- **권장 조치**: 설치된 skill 목록은 frontmatter `description` 원문을 그대로 옮기도록 템플릿을 수정한다.
- **완료 기준**:
  - 템플릿이 `description`을 요약하지 않고 원문 그대로 사용하도록 명시한다.
  - SKILL.md의 설명 추출 규칙과 템플릿의 보고 규칙이 일치한다.

<summary>근거·상세 설명 펼치기</summary>

- **영향**: 같은 skill 목록을 설치해도 모델별 요약이 달라져 결과 보고의 일관성이 낮아지고 원본 설명과 다른 의미가 전달될 수 있다.

</details>

#### F-2: Antigravity의 PASS와 INFO가 단일 판정값으로 혼합된다

- **위험도**: 중간(MEDIUM)
- **영향 축**: 기능 저하
- **발생확률 축**: 통상 사용
- **카테고리**: 버그
- **관점**: 엣지케이스
- **계보**: 신규
- **권장 조치**: `RESULT`의 `PASS`·`FAIL`과 `INFO` 상세를 별도 필드로 분리하거나 `PASS (INFO)`로 고정한다.
- **완료 기준**:
  - 최종 판정은 헬퍼의 `RESULT: PASS`·`RESULT: FAIL`만 그대로 표시한다.
  - 심링크·부재·빈 디렉토리의 `INFO:` 내용은 판정과 분리해 보존한다.
  - 세 정상 상태는 조치 없음, 비어 있지 않은 실제 디렉토리는 `FAIL`과 7단계 조치 결과로 구분된다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 템플릿은 `PASS·FAIL·INFO`를 하나의 판정 후보로 제시하지만, 헬퍼는 정상 레거시 상태에서 `INFO:`를 출력한 뒤 `RESULT: PASS`를 출력한다. 참조 문서도 이를 `PASS (INFO)`로 정의한다.
- **영향**: 같은 헬퍼 출력이 `PASS`, `INFO`, `PASS (INFO)` 중 다르게 보고될 수 있고 7단계 조치 필요 여부가 불명확해진다.

</details>
