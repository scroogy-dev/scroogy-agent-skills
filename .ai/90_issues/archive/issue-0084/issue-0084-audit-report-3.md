### 상세 분석

#### F-1: 말미 문장 절단이 원문 사용 기준과 기능 설명을 계속 누락한다

- **위험도**: 중간(MEDIUM)
- **영향 축**: 기능 저하
- **발생확률 축**: 통상 사용
- **카테고리**: 기능
- **관점**: 암묵적 가정
- **계보**: F-1 잔여
- **권장 조치**: 설치된 skill 설명은 frontmatter `description` 전량을 그대로 사용한다.
- **완료 기준**:
  - 템플릿이 `description`을 요약·절단 없이 그대로 사용한다.
  - SKILL.md의 설명 추출 규칙과 템플릿의 보고 규칙이 동일하다.
  - 말미 문장에만 있는 현재 기능·옵션 설명도 설치 결과에 보존된다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 둘째 문장 이후의 기능 설명은 보존됐지만 마지막 문장은 여전히 제거된다. `issue-work`의 마지막 문장에는 단순 검색어 외에 `--workflow-only`·`--resume`·`--clear`·`--response` 기능이 들어 있어 "항상 비기능 트리거"라는 전제가 성립하지 않는다.
- **영향**: 설치 결과의 설명이 선택 단계에서 사용한 원본보다 축약되고, 일부 skill은 지원 작업과 옵션이 정상 보고마다 누락된다.

</details>

#### F-3: 경로별 결과 표의 예시값이 실제값처럼 고정돼 있다

- **위험도**: 중간(MEDIUM)
- **영향 축**: 기능 저하
- **발생확률 축**: 통상 사용
- **카테고리**: 버그
- **관점**: 암묵적 가정
- **계보**: 신규
- **권장 조치**: 두 데이터 행을 `<대상 경로>`·`<PASS 또는 FAIL>`·`N개` 자리표시자로 바꾸거나 표 전체가 예시임을 명시한다.
- **완료 기준**:
  - 템플릿 데이터 행이 실제 실행값으로 교체해야 할 자리임을 명확히 표시한다.
  - Claude·Antigravity 외 경로와 3개가 아닌 설치 개수도 같은 형식으로 정확히 보고된다.
  - 예시의 `FAIL`이 정상 실행 결과로 복사되지 않는다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 표는 `~/.claude/skills/ | PASS | 3개`, `~/.gemini/config/skills/ | FAIL | 3개`를 구체값으로 담지만 예시라는 표기나 교체 지시가 없다. 같은 파일의 나머지 항목은 `<...>` 자리표시자를 사용해 이 두 행만 실제 고정값처럼 읽힌다.
- **영향**: 대상 경로·설치 개수·검증 결과가 다른 정상 실행에서 샘플값을 그대로 보고할 수 있어, 형식은 일정해도 내용이 사실과 달라진다.

</details>

#### F-4: 배포 제외 패턴이 5단계 외에 다시 고정됐다

- **위험도**: 낮음(LOW)
- **영향 축**: 기능 저하
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 아키텍처
- **관점**: 부작용
- **계보**: 신규
- **권장 조치**: 템플릿은 5단계에서 실제 적용한 `--exclude` 패턴을 옮기도록 지시하고 패턴 리터럴을 보유하지 않는다.
- **완료 기준**:
  - 제외 패턴 리터럴의 단일 출처가 SKILL.md 5단계로 유지된다.
  - 템플릿 출력은 5단계에서 실제 적용한 패턴 전량을 표시한다.
  - 5단계 패턴 변경 시 템플릿 수정 없이 새 값이 보고된다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: SKILL.md 5단계와 ADR 0001은 제외 패턴 목록·복사 명령의 단일 출처를 5단계로 둔다. 템플릿이 같은 리터럴을 가지면 다음 변경 때 양쪽을 함께 고쳐야 한다.
- **영향**: 현재 값은 일치하지만 패턴 추가·변경 후 템플릿 갱신을 놓치면 실제 배포와 사용자 보고가 달라진다.

</details>
