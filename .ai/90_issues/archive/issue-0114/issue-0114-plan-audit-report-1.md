<details>
<summary>근거·상세 설명 펼치기</summary>

- spec 전제(328행)는 H1과 뒤 빈 줄을 제외하고 **검사기와 같은 계산**이라고 정한다. 실제 검사기는 첫 본문 행을 찾고 그 **바로 다음 물리 행**을 `line2`로 읽는다(`ai-workspace/scripts/check-context.sh` 46~56행).
- R2 명령은 `NF { n++; if (n == 2) ... }`로 **두 번째 비어 있지 않은 행**을 찾는다. 날짜 행과 선언 사이에 빈 줄이 있으면 이 둘은 다르다.
- dev 템플릿의 날짜만 치환한 임시 파일에서 직접 대조했다. 정상 파일은 두 방법 모두 선언을 찾고 검사기는 exit 0이었다. 날짜 뒤에 빈 줄 하나를 넣으면 R2의 선언 추출은 계속 표준 문구를 반환하지만 검사기는 `누락: 본문 두 번째 줄 SSoT 선언 — 실제 []`와 exit 1을 반환했다. 이는 전체 R2 블록의 통과 주장이나 미구현 doc 검사기의 실행 결과가 아니라, **행 선택 알고리즘의 반례**다.
- Task 2·4·5에 적힌 최종 문구는 `AI-CONTEXT.md 2번째 줄`만 언급한다. 실제 템플릿의 물리적 2행은 빈 줄, 선언은 4행이므로 spec의 계산 설명을 배포 파일에도 전달해야 한다. 이슈 spec은 개별 스킬 설치본에 배포되지 않는다.
- 선언을 옳게 읽는다는 R1 보장은 경계 입력에서 검사 주체에 따라 달라진다. 정상 템플릿에서는 재현되지 않으므로 발생확률은 특수 조건·엣지로 분류했다.

</details>

  - [ ] 선언 범위를 축소한 경우에도 범위 밖 기존 행의 처리 기준을 정하고, 반영을 마친 뒤에만 메타데이터를 갱신한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- Task 4의 sync 입력은 `git diff <source_hash>..HEAD --name-only` 중 **현재 ssot_dir 아래 파일만**이다. stale 판정도 같은 범위의 변경 파일만 본다. 선언 파일 자체의 변경이나 frontmatter 루트와의 비교는 계획에 없다.
- 임시 Git 저장소에 `docs/a.md`, `guides/b.md`를 먼저 커밋하고, 선언을 `docs/`에서 `docs/, guides/`로 바꾸는 커밋만 추가했다. 실행 결과는 아래와 같다.

```text
git diff <baseline>..HEAD --name-only
.ai/AI-CONTEXT.md

현재 ssot_dir(docs/, guides/) 아래 변경 파일: 0개
새 범위에서 색인해야 할 기존 문서: guides/b.md
```

- 계획대로라면 새 문서 행을 만드는 1단계의 입력이 비어 있고, 기존 행의 파일 존재를 확인하는 3단계도 누락된 새 행을 찾지 못한다. 루트 축소 때는 실제 파일이 남아 있으면 기존 행도 제거되지 않는다.
- R9의 지정 디렉토리 문서 지도 보장이 루트 변경 경계에서 성립하지 않는다. 파일 내용이 바뀌는 보통 sync는 이 반례에 해당하지 않아 발생확률을 특수 조건·엣지로 분류했다.
- 필요한 보완은 루트 변경 시 재생성한다는 절차·검증 기준이며, 새 CLI 옵션이나 별도 헬퍼를 요구하지 않는다.

</details>
