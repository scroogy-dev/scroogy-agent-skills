# Issue #76 스펙 issue-audit 리포트 역피라미드 구조 재배치

## 목표 (Goal)

issue-audit 감사 리포트를 "종합 의견 → 요약 → 상세" 역피라미드 구조로 재배치하고, 2단계 발견에 git-review(#75)와 동일한 카테고리 축을 도입해 영역별 집계가 가능하게 한다.

---

## 범위 (Scope)

**포함 (In)**

- `issue-audit/templates/issue-audit-report-template.md`
  - 종합 의견·요약(대시보드) 섹션을 상단으로 재배치
  - 발견 사항 표의 `분류` 열을 `카테고리` 열로 교체하고, 관점(현행 분류 값 5종)은 상세 블록 필드로 이동
  - 기등재 참조 항목·이전 발견 추적 표 전체 접기 — 건수·잔여 번호는 요약에 노출
- `issue-audit/SKILL.md`
  - 2단계에 카테고리 체계 표 추가 — git-review 원본 복사 + 동기화 주석
  - 출력 요약 형식에 카테고리별 건수 반영 (대화 출력에는 접기를 쓰지 않음)
  - 템플릿 재배치로 무효가 되는 본문 참조(줄 번호 앵커 등) 정합

**비포함 (Out)**

- `git-review/` 하위 변경 — 원본 표시·동기화 주석은 #75에서 이미 기재됨
- 위험도 매트릭스·등급별 처리 기준·발견 기록 규칙(번호 계승·계보·기등재 대조) 변경
- issue-work `--response` 등 인접 스킬 변경

## 완료의 정의 (Definition of Done)

> **검증 레벨** — 낮을수록 좋다(자동 검증에 가까움). 기본은 L1, 한 레벨 내릴 때마다 강등 사유를 함께 적는다.
>
> - `[D]`  L1 결정적   — 명령이 합/불을 판정, 사람 판단 없음
> - `[QD]` L2 준결정적 — 다른 AI·기준 체크리스트가 채점
> - `[ND]` L3 비결정적 — 사람이 직접 읽고 판단

## 전제 (Assumptions)

- 대시보드 섹션명은 `## 요약` — 이슈 본문의 "요약 대시보드"는 역할 서술이며, 섹션명은 git-review 템플릿(`## 요약`)과 맞춘다. 상단 종합 판단 섹션명은 현행 `## 종합 의견` 유지 — git-review의 `## 최종 의견`과 명칭을 통일하지 않는다 (#75는 git-review 내부 용어 통일이었고, 감사 산출물의 기존 명칭을 바꿀 이유가 없음).
- 표에서 상세 블록으로 이동하는 축의 필드명은 `관점` — SKILL.md 2단계 "검증 관점"과 용어를 맞추고 새 `카테고리` 축과의 혼동을 막는다. 값 5종(엣지케이스/암묵적 가정/부작용/스펙 모호성/누락된 검증)은 변경 없음.
- 기등재 참조 항목·이전 발견 추적은 `##`로 승격하지 않고 2단계 하위 `###`를 유지한 채 상세 분석 뒤로 이동한다 — 두 표 모두 2단계 발견 기록의 일부다.
- 카테고리 표는 `검증 내용` 문구까지 git-review 원본 그대로 복사한다 — 문구가 갈리면 동기화 diff 검증(`[D]`)이 성립하지 않는다.
- 요약의 카테고리 집계는 발견 0건 행도 유지(git-review의 "검증 수행의 증거" 관례)하되 `상태` 열은 두지 않는다 — 상태 산출은 git-review 고유 체계라 복사 범위 밖.
- SKILL.md 3단계의 "'감사 모델' 줄(#26)" 줄 번호 앵커는 재배치로 무효가 되므로 줄 번호 없는 서술로 교체한다.
