### 상세 분석

#### F-8: 퀴즈 러너가 호출자의 Git 인덱스를 덮어쓴다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 부작용
- **계보**: 신규
- **권장 조치**: 브랜치 수집 fixture 전용 프로세스에서 저장소를 지정하는 Git 환경 변수를 비운 뒤 임시 저장소를 초기화하고 실행한다.
- **완료 기준**:
  1. 별도 저장소의 인덱스를 절대 경로 `GIT_INDEX_FILE`로 지정하고 러너를 실행해도 그 인덱스의 바이트와 스테이징 목록이 유지된다.
  2. 상속된 `GIT_DIR`과 `GIT_WORK_TREE`가 있어도 fixture 초기화와 Git 쓰기가 임시 저장소 내부에서만 실행된다.
  3. 기본 실행과 위 환경을 포함한 실행에서 브랜치 수집의 기대 목록·patch 검사가 통과한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 러너는 전역·시스템 설정과 상위 저장소 탐색을 제어한다. `newrepo`·`g`가 호출하는 Git은 `GIT_INDEX_FILE`을 상속하고, `git -C`는 작업 디렉토리만 바꾼다. fixture의 `git add -A`가 상속된 인덱스에 기록한다. [환경 설정](../../../../git-review-quiz/tests/run-tests.sh#L780) · [스테이징](../../../../git-review-quiz/tests/run-tests.sh#L811)
- **실패 시나리오**: 별도 임시 저장소에서 `user-staged.txt`를 스테이징하고 그 인덱스의 절대 경로를 `GIT_INDEX_FILE`로 넘겨 실제 퀴즈 러너를 실행하니, 해당 인덱스의 경로가 `.gitignore`와 `base.txt`로 바뀌었지만 러너는 종료 코드 0과 `passed: 144, failed: 0`을 냈다.
- **영향**: 사용자가 선택해 스테이징한 변경이 인덱스에서 사라진다. 부분 스테이징한 경우에는 선택 범위까지 복구해야 한다. 재현에는 폐기 가능한 별도 저장소를 사용했다.

</details>
