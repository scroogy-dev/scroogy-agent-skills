### 상세 분석

#### F-1: 대소문자를 구분하지 않는 볼륨에서 같은 작업공간의 이전 퀴즈를 수집한다

- **위험도**: 🟡 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스
- **계보**: 신규
- **권장 조치**: 퀴즈 산출 경로가 가리키는 디렉터리와 수집 헬퍼의 제외 경로를 일치시키고 원본·사본에 같은 변경을 적용한다.
- **완료 기준**:
  1. 대소문자를 구분하지 않는 볼륨에서 실제 디렉터리가 `.ai/99_WORKSPACE`일 때, 퀴즈가 `.ai/99_workspace/`로 쓴 미추적 파일이 목록과 patch에서 빠진다.
  2. 같은 실행에서 작업공간 밖의 미추적 파일이 남고, 대소문자를 구분하는 볼륨에서는 별개 디렉터리까지 제외하지 않는다.
  3. 기존 제외 테스트와 사본 대조가 통과한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 헬퍼의 `git add -A`가 `:(top,exclude).ai/99_workspace`로 경로를 제한한다. Apple Git 2.50.1의 임시 저장소에서 `.ai/99_WORKSPACE`를 만든 뒤 스킬이 정한 소문자 경로로 파일을 썼다. 두 디렉터리의 inode는 같았고 Git은 실제 대문자 디렉터리 표기를 출력했다.
- **실패 시나리오**: 같은 작업공간의 디스크 표기가 `.ai/99_WORKSPACE`이면 `--base` 수집 결과에 `A<TAB>.ai/99_WORKSPACE/temp_review_quiz_branch-main.md`와 patch의 `+previous quiz output`이 들어간다. 함께 둔 일반 `feature.txt`도 수집됐다.
- **영향**: 이전 퀴즈가 변경 파일 수, 설명, 문항의 입력이 될 수 있다. AC2·D1이 명시한 예외에 해당하며, 원장 K-0031의 일반적인 Git 스테이징 경계와 별개로 헬퍼의 명시적 제외가 성립하지 않는다.

</details>

#### F-2: Task 2의 조항 검사가 수집 규칙의 일부를 건너뛴다

- **위험도**: 🟢 낮음(LOW)
- **영향 축**: 기술 품질 의견
- **발생확률 축**: 통상 사용
- **카테고리**: 테스트
- **관점**: 누락된 검증
- **계보**: 신규
- **권장 조치**: Task 2가 추가한 수집·실패 처리의 핵심 규칙을 검사하고, 각 규칙을 없애거나 뒤집는 변형을 추가한다.
- **완료 기준**:
  1. merge-base 실패 조건을 삭제하거나 성공·빈 출력을 실패로 바꾸면 수집 실패 검사가 각각 실패한다.
  2. 헬퍼의 목록과 patch를 퀴즈 입력으로 사용하는 조항을 삭제하면 브랜치 수집 검사가 실패한다.
  3. 실제 본문과 계획에 지정된 기존 변형 검사가 모두 통과한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 현재 테스트는 헬퍼의 비정상 종료 관련 문장과 빈 출력 조건의 앞부분을 찾는다. 브랜치 수집 검사는 목록과 patch를 쓰는 지시를 검사하지 않는다.
- **검증**: 현재 러너의 동일 검사 함수에 세 가지 임시 문서 변형을 각각 입력했다. merge-base 실패 조건 삭제, 성공·빈 출력의 실패 처리, 목록·patch 조항 삭제 모두 진단 0행이었다. 현재 조항의 동작 평가는 AC4 및 D7의 `[QD]` 근거에 기록했다.

</details>
