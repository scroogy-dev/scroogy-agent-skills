#### F-19: 원격 ref 대조와 push 사이의 검사-사용 시점 경합

- **위험도**: 낮음(LOW)
- **분류**: 엣지케이스
- **계보**: F-13 잔여
- **권장 조치**:
  - 기존 조상 관계 검사와 명시 refspec을 유지하면서, push 수신 시점에 원격 ref가 보관한 `headRefOid`와 같은지를 검증하는 명시적 lease 또는 동등한 원자적 비교-갱신을 사용한다.
  - lease 거부 시 새 head를 수집하고 diff·검증·승인을 다시 수행하며, 기존 승인값으로 재시도하지 않는다.
- **완료 기준**:
  - [ ] push 명령이 `refs/heads/<headRefName>`의 예상 이전 SHA를 `headRefOid`로 고정해 수신 시점 변경을 원자적으로 거부한다.
  - [ ] `ls-remote` 성공 뒤 push 전에 원격 ref가 삭제·rewind·갱신되는 세 경우가 모두 미반영·재승인 경로로 귀결된다.
  - [ ] 원자적 대조 실패를 push 성공이나 PR 반영 완료로 보고하지 않는다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: `git ls-remote` 결과가 일치해도 실제 `git push`가 실행되기 전 원격 ref는 바뀔 수 있다. 격리한 로컬 bare remote 재현에서 대조 직후 ref를 삭제하자 일반 push는 승인 SHA로 ref를 재생성했고, 예상 이전 SHA를 지정한 명시적 lease는 같은 상황을 `stale info`로 거부했다. 일반 non-force push는 원격 전진에는 대체로 실패하지만, 대조 직후 ref가 삭제되거나 승인 시점보다 이전 커밋으로 rewind되면 승인 SHA push가 성공해 삭제·rewind를 되돌릴 수 있다.
- **영향**: 좁은 경합 창에서 대상 PR 브랜치를 의도치 않게 되살리거나 되돌린 커밋을 다시 공개할 수 있다. 스펙 DoD #6의 유한 체크리스트 밖 방어이므로 1단계 판정을 낮추지는 않았다.

</details>
