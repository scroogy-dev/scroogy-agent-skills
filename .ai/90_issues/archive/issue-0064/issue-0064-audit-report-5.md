#### F-13: push 직전 원격 ref 경합 검증 잔여

- **위험도**: 낮음(LOW)
- **분류**: 엣지케이스
- **계보**: 4차 F-2 잔여
- **권장 조치**:
  - push 직전 승인 원격의 `refs/heads/<headRefName>`을 조회해 보관한 `headRefOid`와 대조한다.
  - 예상 이전 SHA와 다르면 중단하고 새 head 기준으로 diff·검증·승인을 다시 수행한다.
- **완료 기준**:
  - [ ] push 직전 원격 ref SHA 대조 규칙과 불일치 시 중단 규칙이 문서에 있다.
  - [ ] 삭제·rewind·동시 갱신 사례가 승인 재수행 경로로 귀결된다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 현재 규칙은 후보 원격 URL과 로컬 승인 SHA의 조상 관계를 확인하지만, 원격 ref의 현재 SHA는 확인하지 않는다. 일반 non-force push가 대부분의 전진·분기 경합을 거부하더라도 원격 삭제나 rewind 뒤에는 승인 당시와 다른 상태로 push가 성공할 수 있다.
- **영향**: DoD #6 유한 체크리스트 밖 개선 사항이므로 1단계 판정을 낮추지 않았다. 드문 동시성 상황에서 삭제·rewind된 head를 의도치 않게 되살릴 수 있다.

</details>

#### F-14: GitHub MCP 스레드 resolve 폴백 메서드가 유효하지 않음

- **위험도**: 중간(MEDIUM)
- **분류**: 암묵적 가정
- **계보**: 신규
- **권장 조치**:
  - 현재 GitHub MCP에서 실제 지원하는 resolve 도구가 있으면 그 도구명·입력으로 교체한다.
  - 지원 도구가 없으면 MCP 폴백에서는 resolve 미지원으로 명시하고, 답글만 게시한 뒤 unresolved 상태를 결과에 남긴다.
- **완료 기준**:
  - [ ] MCP 매핑 표의 메서드가 실제 활성 도구 스키마에 존재한다.
  - [ ] resolve 도구가 없는 구성에서도 허구의 메서드를 호출하지 않고 안전한 미처리 결과를 보고한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- **설명**: 현재 GitHub MCP의 `pull_request_review_write`는 `create`, `submit_pending`, `delete_pending`만 허용한다. 문서의 `method: resolve_thread`는 입력 검증 단계에서 거부되며, 별도 resolve 도구도 현재 활성 스키마에서 확인되지 않았다.
- **영향**: `gh`가 없는 MCP 전용 환경에서 사용자가 resolve를 승인해도 실행할 수 없다. 안전 종료 규칙은 있어 외부 오작동은 막지만, 폴백 기능 설명과 실제 계약이 불일치한다.

</details>
