<details>
<summary>근거·상세 설명 펼치기</summary>

- spec 전제 420행은 전체 문장 대조를 버린 대안으로 명시하고, R6 `[D]`에서 이슈 완료 시점에만 일치 여부를 확인한다. Task 4 작업 3은 라벨·순서·리터럴 포함 여부를 지속 검사의 전부로 정의한다.
- 예를 들어 응답 행을 ``- **응답**: 반환 값과 예외는 `-->>`로 적지 않고 모두 생략합니다.``로 바꿔도, 해당 행의 유일한 `SEQ_ROWS` 리터럴인 `-->>`와 라벨은 유지된다. 원문의 응답 규칙과 의미가 반대지만 계획된 검사 조건을 만족한다.
- code-map의 실제 `SEQ_LABELS`·`SEQ_ROWS`를 읽어 Task 4가 열거한 조건을 독립 모의 평가했다. 기준 사본과 위 변형 모두 위반 0건, 전체 문장 일치 비교는 거짓이었다. 이는 아직 없는 `seq_copy_violations` 구현을 실행한 결과가 아니라, 계획에 적힌 검사 조건의 한계를 확인한 결과다.
- 현재 이슈의 R6 명령은 이 변형을 잡으므로 초기 문장 일치 자체가 막히지는 않는다. 이후 의미 변경에서 리터럴이 남는 조합에만 지속 검사 누락이 생기며, 트리·시퀀스 작성 기능은 남아 표현 품질이 떨어지므로 기능 저하·특수 조건으로 판정했다.
- 이슈 본문이 `SEQ_ROWS` 사용을 요구한다는 점은 반영되어 있다. 이 발견은 R7의 요구사항 이관 판정을 낮추지 않으며, 원장 등재나 계획 보정도 자동으로 실행하지 않는다.
