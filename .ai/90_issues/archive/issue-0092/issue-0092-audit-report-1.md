### 상세 분석

#### F-1: 접기 블록의 경계와 분리를 검증하지 않는다

- **위험도**: 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스, 누락된 검증
- **계보**: 신규
- **권장 조치**: 문항별 접기 깊이의 균형을 검사하고 힌트와 정답이 각각 독립된 접기 블록에 속하도록 판정한다.
- **완료 기준**:
  - 닫히지 않은 `<details>` 입력이 R3 또는 R4 위반·종료 코드 1을 낸다.
  - 힌트와 정답 summary를 한 `<details>`에 둔 입력이 종료 코드 1을 낸다.
  - 각 문항 종료 시 접기 깊이가 0이고 불필요한 닫기 태그도 거부한다.
  - 반례 fixture를 러너에 추가하고 기존 정상 fixture와 템플릿은 계속 통과한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- `check-quiz.sh:147-157`은 태그 개수로 깊이를 증감하지만 `flush_q()`에서 최종 깊이와 블록 소유 관계를 검사하지 않는다.
- 정상 fixture의 `</details>`를 모두 제거한 입력과 힌트·정답 사이의 `</details><details>` 경계를 제거한 입력이 모두 무출력·종료 코드 0이었다.
- 이 상태로 댓글을 게시하면 접기 렌더링이 깨지거나 힌트와 정답이 하나의 블록으로 합쳐져 문항별 정답 비공개 보장이 무너질 수 있다.

</details>

- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스, 암묵적 가정

- **완료 기준**:

  - `(a), (c)` 건너뜀과 `(b), (c)` 시작 입력이 R5 위반·종료 코드 1을 낸다.
  - 2개 이상 연속 라벨인 기존 정상 입력은 계속 통과한다.

- **위험도**: 중간(MEDIUM)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 버그
- **관점**: 엣지케이스, 누락된 검증
- **계보**: 신규
- **권장 조치**: `## 문항` 아래의 모든 `### ` 헤더를 문항 후보로 보고, R1 형식과 맞지 않으면 즉시 위반으로 기록한다.
- **완료 기준**:
  - 마지막 문항의 `Q3`를 `QX`로 바꾼 입력이 R1 위반·종료 코드 1을 낸다.
  - 여는 대괄호 누락, 숫자 누락, 지원하지 않는 형식 어휘 반례를 모두 거부한다.
  - 문항 후보의 본문이 R2~R6 검사에서 조용히 제외되지 않는다.
  - 반례 fixture를 러너에 추가하고 기존 정상 입력은 계속 통과한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- `check-quiz.sh:98-123`은 모든 `### `에서 이전 문항을 닫지만 `^### Q[0-9]+ \[`에 맞을 때만 새 문항을 연다.

</details>

#### F-4: 댓글 permalink 계약을 문항 전수로 검증하지 않는다

- **위험도**: 낮음(LOW)
- **영향 축**: 기능 저하
- **발생확률 축**: 특수 조건·엣지
- **카테고리**: 기능
- **관점**: 암묵적 가정, 누락된 검증
- **계보**: 신규
- **권장 조치**: 댓글 모드 전용 검사를 추가해 모든 위치 행의 permalink와 기준 SHA를 게시 전에 판정한다.
- **완료 기준**:
  - 댓글 모드에서 모든 위치 행에 permalink가 정확히 1개 있어야 한다.
  - URL이 확정 호스트·소유자·저장소, `blob/<40자 SHA>`, 경로, `#L<n>` 또는 `#L<n>-L<m>` 형식을 지켜야 한다.
  - 추가·수정 위치는 `headRefOid`, `(base)` 위치는 `baseRefOid`와 일치해야 한다.
  - 문항 하나의 permalink 누락, `blob/main`, 잘못된 SHA, 줄 앵커 누락 반례를 러너에 추가한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- `check-quiz.sh:132-135`의 permalink는 선택이고 URL은 `https?://[^)]+`만 본다. 대화형과 댓글 모드를 구분하는 인자도 없다.
- 스펙 DoD 5의 `grep -q`는 댓글 파일 전체에서 올바른 permalink 1건만 찾는다. 여러 문항 중 나머지 위치에 permalink가 없어도 통과한다.
- 정상 댓글 fixture에서 Q2 permalink를 제거하고 `(base)`만 남긴 입력은 헬퍼와 DoD의 permalink probe를 모두 통과했다. 모든 SHA를 `main`으로 바꾼 입력도 헬퍼는 통과했다.
- 현재 시험 산출물의 5개 permalink는 모두 올바르므로 이번 시험 결과 자체의 결함은 아니다.

</details>
