- **위험도**: 높음(HIGH)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 통상 사용
- **카테고리**: 기능
- **관점**: 암묵적 가정, 부작용, 누락된 검증

- **완료 기준**:
  - `main`과 `feature/main` ref가 함께 있는 저장소에서 `git ls-remote --heads <repo> refs/heads/main`이 `main` 한 행만 반환한다는 사실을 새 문항·해설과 모순 없이 반영한다.
  - 새 Q1의 정답과 해설을 실제 소스·diff와 실행 가능한 반례가 함께 뒷받침한다.
  - 교체한 Q1에 다시 응답하거나 기존 Q1 응답 행을 제거해 응답 기록이 문항 내용과 일치한다.
  - 두 시험 산출물이 형식 검사를 통과하고, 전체 10문항을 실제 동작과 다시 대조한다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- 시험 Q1은 `main`을 조회하면 `refs/heads/feature/main`도 함께 반환된다고 설명하고 정답을 (b)로 둔다 (`temp_review_quiz.md:20-38`).
- 실제 코드는 짧은 패턴 `main`이 아니라 완전한 패턴 `refs/heads/$branch`를 넘긴다 (`verify-submit.sh:122`).
- 임시 bare 저장소에 `refs/heads/main`과 `refs/heads/feature/main`을 함께 만든 재현에서 완전한 패턴은 `main` 한 행만 반환했다. 짧은 패턴 `main`과 `*/main`만 두 ref를 반환했다.
- 따라서 (b)는 현재 명령에서 실현되지 않는다. (a)는 0행 분기가 이미 막고, (c)는 7자 이상 축약 SHA를 의도적으로 지원하는 동작이라 세 선택지 중 정답이 없다.
- 참조한 소스 주석(`verify-submit.sh:10-11`)도 실제 완전한 ref 인자와 어긋난다. 퀴즈는 주석을 그대로 믿고 실제 명령 동작을 확인하지 않았다.

</details>
