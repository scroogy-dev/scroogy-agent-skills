### 상세 분석

#### F-1: 빈 축 값과 함께 호출한 판정 모드가 사용오류 대신 승인 판정을 낸다

- **위험도**: 중간(MEDIUM). 설치된 issue-audit의 `classify-risk.sh`로 아래 두 축을 조회했다.
- **영향 축**: 스펙·기능 달성 차단. DoD R1-1이 요구하는 모드 혼용 시 exit 2 보장이 성립하지 않는다.
- **발생확률 축**: 특수 조건·엣지. 축 옵션 값이 빈 문자열인 혼합 호출에서 발생한다.
- **카테고리 / 관점 / 계보**: 버그 / 엣지케이스·암묵적 가정 / 신규
- **귀속 Task**: Task 2. 테스트 보강도 같은 발견의 완료 기준으로 묶어 중복 집계하지 않는다.
- **권장 조치**: 축 옵션의 존재 여부를 값과 별도로 추적하거나 빈 축 값을 파싱 단계에서 거부해, 값이 비어도 `--verdict`와의 혼용을 사용오류로 처리한다.
- **완료 기준**:
  - [ ] `--impact ''` 또는 `--likelihood ''`, 두 옵션 모두를 `--verdict`와 함께 넘기면 옵션 순서와 관계없이 exit 2이고 표준 출력에 판정이 없다.
  - [ ] 축 옵션 존재·빈 값·일반 값·배치 순서를 다루는 회귀 검사가 추가되어 이 반례를 잡는다.
  - [ ] 단독 `--verdict`의 상태 최고값·접두 입력 호환과 기존 러너가 계속 통과한다.
- **후속 처리**: 헬퍼의 중간(MEDIUM) 기본값은 `--response` 승인 게이트에서 사용자 판단이다. 동시에 스펙 부분 충족의 근거이므로 해당 게이트의 스펙 미충족 우선 처리 대상이다.
