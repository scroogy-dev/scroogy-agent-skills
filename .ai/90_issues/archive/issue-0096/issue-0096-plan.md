> 이 Task가 spec의 어느 요구사항을 구현하는지 밝힙니다. 여러 개면 `R<n>, R<m>`로 나열합니다.

### Task 1: SKILL.md 규칙 정비 (판정 산출·이모지 대응표·결과 기록 형식)

- [x] 완료
- **목표**: git-review SKILL.md가 판정 산출 규칙, 이모지 대응표, 새 결과 기록 형식·접기 규칙, 대화창 첫 줄 규칙을 담고 옛 항목 형식 문구를 남기지 않는다. 뒤 Task의 헬퍼·러너가 이 표를 SSoT로 읽는다.
- **대상 요구사항**: R5, R1, R2, R3
- **작업 내용**:
  1. `## 상태 산출` 다음에 `## 판정 산출` 섹션을 신설한다. 판정 표(헤더 `| 최고 상태 | 판정 |`, 데이터 3행: 보완 필요(FAIL) → 변경 요청(REQUEST CHANGES), 주의(WARN) → 조건부 승인(CONDITIONAL), 통과(PASS) → 승인(APPROVE)), 산출 규칙(비즈니스·테크 리뷰 상태 2개의 최고값, 리뷰어가 고르지 않음), Self 리뷰에서 승인은 "제출 가능"을 뜻한다는 문장, 판정은 우선순위 신호이며 보정 여부는 작성자 판단(`git-pr-feedback` 영역)이라는 문장, 헬퍼 사용 예(`"$classify" --verdict '통과(PASS)' '주의(WARN)'   # → 🟡 조건부 승인(CONDITIONAL)`)를 둔다.
  2. 같은 섹션 끝에 `**이모지 대응표**` 볼드 행을 앵커로 표(`| 구분 | 값 | 이모지 |`)를 둔다. 데이터 10행: 등급 4(🔴 높음(HIGH) / 🟡 중간(MEDIUM) / 🟢 낮음(LOW) / ⚪ 정보(INFO)), 상태 3(🔴 보완 필요(FAIL) / 🟡 주의(WARN) / 🟢 통과(PASS)), 판정 3(🔴 변경 요청(REQUEST CHANGES) / 🟡 조건부 승인(CONDITIONAL) / 🟢 승인(APPROVE)). 헬퍼가 등급·상태·판정 출력 앞에 이 이모지를 붙이고 리뷰어가 손으로 붙이지 않는다는 점, 항목 색이 그 항목이 만드는 상태 색과 같고 정보(INFO)는 상태에 영향이 없어 무색이라는 점, 요약 표 건수 열은 텍스트 등급만 쓴다는 점, `--status`·`--verdict`가 접두 유무와 무관하게 값을 받는다는 점을 표 아래에 적는다. 매트릭스·상태·판정 표의 셀 값은 텍스트 그대로 둔다.
  3. `## 위험도 분류`·`## 상태 산출`의 헬퍼 예시 출력 주석을 이모지 포함 값으로 바꾼다 (`# → 🟡 중간(MEDIUM)`, `# → 🟡 주의(WARN)`, `# 발견 없음 → 🟢 통과(PASS)`). 표를 고치면 헬퍼와 `tests/`를 함께 갱신한다는 문장에 대응표를 포함시킨다.
  4. `## 결과 기록 형식`을 새 형식으로 다시 쓴다. 순서(판정 한 줄 → 최종 의견 접기 → 요약 → 비즈니스 리뷰 → 테크 리뷰), 판정 한 줄은 `--verdict` 출력을 그대로 적는다는 규칙, 상태 표기 3곳(요약 상태 줄·카테고리 표 상태 열·테크 리뷰 소절 제목)에 `--status` 출력을 그대로 쓴다는 규칙, 리뷰 포인트 블록 형식(볼드 한 줄 `**<이모지> <등급> <제목>**` 다음 일반체 지적·권장 조치 1~3문장, 항목 바로 아래 접기에 영향·발생확률 축·근거·코드 위치·호출 흐름, 항목은 리스트가 아니라 문단으로 두며 리스트 안 접기는 GitHub·IDE 미리보기 렌더링이 깨진다는 이유), 카테고리 단위 접기 없음, 비즈니스 리뷰 동일 형식, 발견 0건 카테고리 처리(현행 유지)를 적는다. 옛 항목 형식 문구(`- <등급> [<영향 축> × <발생확률 축>]: <지적 사항>`)와 그 예시 행을 제거한다. 대화창 보고 규칙(리뷰 결과를 보고하는 대화창 답변은 같은 판정 한 줄로 시작하며 그 밖의 대화창 형식은 정하지 않는다)을 이 섹션에 둔다.

  6. `## 산출물 접기 기준`에 두 항목을 추가한다. 항목별 접기(접기 안은 근거·코드 위치·호출 흐름·축 판정, 밖은 제목·지적·권장 조치, 카테고리 단위 접기 없음)와 최종 의견 접기 해석(판정 한 줄을 뺀 종합 판단·후속 액션은 접으며, 액션 아이템의 실체인 리뷰 포인트 제목이 본문에 보이므로 "액션 아이템 접기 금지"와 충돌하지 않는다).

### Task 2: 헬퍼 확장 (이모지 출력·`--verdict`·입력 호환)

- [x] 완료
- **목표**: `classify-risk.sh`가 등급·상태 출력 앞에 대응표 이모지를 붙이고, `--verdict`로 판정을 산출하며, 이모지 접두가 붙은 입력을 받는다.
- **대상 요구사항**: R1, R2, R4
- **작업 내용**:
  1. `emoji <값>` 함수를 둔다. Task 1 대응표와 같은 10개 매핑(등급 4·상태 3·판정 3)을 `case`로 옮기고 그 밖의 값은 실패를 반환한다.
  2. `strip_emoji <값>` 함수를 둔다. 값이 `🔴 `·`🟡 `·`🟢 `·`⚪ ` 중 하나로 시작하면 그 접두를 떼고, 아니면 그대로 돌려준다. 그 밖의 접두(예: `🔵 `)는 떼지 않아 뒤의 `rank`·상태 검증에서 종료 코드 2가 된다.
  3. `--impact/--likelihood` 출력을 `<이모지> <등급>`으로, `--status` 출력을 `<이모지> <상태>`로 바꾼다. `--status` 인자는 `strip_emoji`를 거친 뒤 `rank`에 넣는다.
  4. `--verdict <상태> <상태>` 모드를 신설한다. 위치 인자 정확히 2개, 각 인자는 `strip_emoji` 후 상태 서열(보완 필요(FAIL) 2 / 주의(WARN) 1 / 통과(PASS) 0)로 변환하며 최고값으로 판정(2 → 변경 요청(REQUEST CHANGES), 1 → 조건부 승인(CONDITIONAL), 0 → 승인(APPROVE))을 내고 `<이모지> <판정>`으로 출력한다. 인자 개수가 2가 아니거나, 상태가 아닌 값이거나, `--impact`·`--likelihood`·`--status`와 섞이면 종료 코드 2다.

    <details>
    <summary>검증 명령 — repo 루트에서 실행, 출력 0이면 통과</summary>

    ```bash
    S=.ai/90_issues/archive/issue-0096/issue-0096-summary.md
    awk '
      /^### Task / { if (o && !n && d && (t != 1 || m != 1)) b++; o = 1; d = 0; t = 0; m = 0; n = ($0 ~ /^### Task N/) }
      o && /^- \*\*결과\*\*: (완료|부분 완료)[[:space:]]*$/ { d = 1 }
      o && /^- \*\*수행 모델\*\*:/ { t++; if ($0 ~ /^- \*\*수행 모델\*\*: [^-[:space:]]/) m++ }
      END { if (o && !n && d && (t != 1 || m != 1)) b++; print b+0 }
    ' "$S"
    ```

    - 설계 주의: 리터럴 `-`만 거부하면 빈 값·행 누락·중복이 통과하므로 "없음"의 세 형태와 중복을 전부 실패로 센다.
    - 의존 근거: 아래 교차 벤더 조건은 비어 있지 않은 `수행 모델` 값에서만 벤더를 뽑아 대조한다.
