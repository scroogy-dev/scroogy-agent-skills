<details>
<summary>근거·재현 절차 펼치기</summary>

- `write_file()`은 142행의 `cat "$2" > "$3"`로 설치본을 먼저 절단한다. 복사 중 오류가 나면 `실패:`만 보고하며 원본을 복구하지 않는다. 임시 결과 생성만으로 최종 쓰기의 실패가 보호되지는 않는다.
- 감사는 임시 `.ai/`에 정상 SSoT 선언, 구버전 `## 에이전트 운영 지침`, 뒤쪽 `## 사용자 메모`와 표식 `USER_CONTENT_MUST_SURVIVE`를 넣었다. 실제 repo 파일은 쓰기 대상에 넣지 않았다.
- `PATH` 앞의 임시 `cat` 래퍼는 최종 결과 파일(`*/out`)을 복사할 때만 자식 프로세스에 `ulimit -f 1`을 적용하고 실제 `/bin/cat`을 실행했다. 나머지 `cat`은 그대로 전달해 최종 반영의 부분 쓰기 오류만 주입했다.

```bash
#!/bin/bash
case "${1:-}" in
  */out) (ulimit -f 1; exec /bin/cat "$@") ;;
  *) exec /bin/cat "$@" ;;
esac
```

- 실행: 래퍼를 앞에 둔 `PATH`로 `sync-owned.sh --context ai-workspace/templates <임시 .ai>` 호출.
- 결과: 종료 코드 `1`, stdout `실패: AI-CONTEXT.md — 쓰기 실패`, stderr 없음. 원본 `220`바이트가 `1024`바이트의 불완전한 결과로 바뀌었고 사용자 메모 표식은 사라졌다.
- 기존 `own_fail()`의 쓰기 오류 검사는 `chmod 444`로 리디렉션 자체가 실패하는 경우만 검사한다. 쓰기가 일부 진행된 뒤 실패하는 경우를 추가해야 한다. 같은 근본 원인은 `write_file()`을 공유하는 다른 모드에도 적용된다.

</details>
