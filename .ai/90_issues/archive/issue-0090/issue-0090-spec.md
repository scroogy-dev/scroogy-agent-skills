# Issue #90 스펙 전체 스킬 결정화 여지 전수 조사 및 개선 + architecture.md 디자인 원칙 섹션 신설

## 목표 (Goal)

`.ai/10_rules/architecture.md`에 결정화 도입 판단 규칙(`## 디자인 원칙`)을 신설하고, 15개 스킬 전부의 결정화 여지를 전수 조사해 실익 있는 지점을 결정적 헬퍼·테스트로 옮긴다.

## 범위 (Scope)

**포함 (In)**

- `.ai/10_rules/architecture.md`에 `## 디자인 원칙` 섹션 신설. 소절 5종(`### 원칙`, `### 역할 분담`, `### 판단 체크리스트`, `### 예외`, `### 기존 체계와의 관계`)으로 구성한다
- 임계값(반복 횟수·분기 개수 등)을 수치로 둘지 여부의 결정과 근거 한 줄 기재
- `.ai/AI-CONTEXT.md` `## 스킬 작성 규칙`에 새 섹션 포인터 한 줄 추가
- 15개 스킬 전수 조사. 판정(`결정화 대상`/`준결정적 유지`/`결정화 불가`)·처리·근거를 이 spec의 `## 조사 결과` 표에 기록

- 실익이 낮은 항목의 원장(`.ai/70_ledger/`) 등재 또는 조사 표 기록 종결

**비포함 (Out)**

- 결정화 여지가 없다고 판정된 스킬의 리팩토링

## 전제 (Assumptions)

- 소절 앵커 5종과 조사 표의 처리 열 어휘 4종(`이번 이슈 반영`/`후속 이슈 #N`/`원장 K-<번호>`/`표 기록 종결`)은 이 spec/plan에서 정한 설계 값이며 이슈 본문에는 없다. `[D]` 검증이 이 앵커에 의존하므로 구현 중 바꾸면 검증 명령을 함께 고친다.
- 실익 판단의 기본값: 발생확률·영향이 낮은 항목은 보정 대신 원장 수용이 이 repo의 합의다 (#61·#62 선례). 조사 판정에도 같은 기준을 쓴다.
- 기대값 15는 `.ai/AI-CONTEXT.md` 스킬 목록의 작성 시점 개수다. 조사 시점에 스킬이 늘거나 줄면 그 수를 기준으로 하고 DoD의 기대값을 함께 갱신한다. Task 0에서 repo 스킬 디렉토리를 세어 15개임을 확인했다.
- 이번 이슈에서 구현할 `결정화 대상` 항목은 Task 2 조사 결과를 사용자에게 제시한 뒤 사용자가 그 시점에 정한다. 조사 자체는 15개 전부 수행한다. 구현 건수 상한을 미리 두지 않는다. (Task 0 질의 답변)
- 후속 GitHub 이슈는 이번 작업에서 만들지 않는다. 사용자가 필요하다고 판단할 때 만들며, AI는 요청받을 때 초안만 제출한다. 이번에 구현하지 않고 후속 이슈도 만들지 않는 `결정화 대상` 항목은 처리 열에 `원장 K-<번호>`를 쓴다. 이 값을 쓸 수 있도록 `완료의 정의` 6번의 허용 어휘를 셋으로 넓혔다. (Task 0 질의 답변)
- `준결정적 유지`·`결정화 불가` 항목의 종결은 `표 기록 종결`이 기본값이다. 조건이 바뀌면 다시 볼 여지가 있는 항목만 `원장 K-<번호>`로 등재한다. (Task 0 질의 답변)
