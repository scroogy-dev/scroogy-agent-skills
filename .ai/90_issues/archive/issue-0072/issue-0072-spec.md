# Issue #72 스펙 — git-review 위험도 등급 체계 도입 (issue-audit 매트릭스 수용)

## 목표 (Goal)

`git-review`의 리뷰 포인트(비즈니스·테크)가 `issue-audit`과 동일한 영향×발생확률 매트릭스로 등급을 산출·표기하게 하여, 등급 산정을 기계적으로 만들고 평가 스킬 간 등급 표기를 일치시킨다.

---

## 범위 (Scope)

**포함 (In)**

- `git-review/SKILL.md`에 위험도 분류 섹션 추가 — 영향 축·발생확률 축·매트릭스·"리뷰어가 등급을 직접 고르지 않는다" 원칙 (`issue-audit`과 동일)
- 영향 축의 리뷰 맥락 보충 — 소프트웨어 계약·도메인 정책 위반도 "스펙·기능 달성 차단"으로 판정함을 명시
- 결과 기록 형식(`temp_review_result.md` 구조)의 리뷰 포인트에 등급·축 병기 형식 반영

**비포함 (Out)**

- 등급별 기본 처리 기준·보정 루프·원장(`.ai/70_ledger/`) 연동 — 보정은 리뷰를 받는 작성자의 몫이며, 작성자 입장의 수용·방어 판단은 `git-pr-feedback` 영역
- 다른 평가 스킬(`git-pr-feedback`·`git-qa`·`pi-scan`) 변경
- `issue-audit` 쪽 변경 (등급 체계 원형 유지)
- 설치 경로 배포 (`install-skills`로 별도 수행)

  <details>
  <summary>검증 명령 — repo 루트에서 실행, 출력 0건이면 통과</summary>

  ```bash
  E='^\| (스펙·기능 달성 차단|기능 저하|기술 품질 의견|통상 사용|특수 조건·엣지|영향 . 확률) \|'
  { grep -qE "$E" issue-audit/SKILL.md && grep -qE "$E" git-review/SKILL.md \
    && diff <(grep -E "$E" issue-audit/SKILL.md) <(grep -E "$E" git-review/SKILL.md) \
    || echo '위반: 표 추출 실패 또는 불일치'; }
  ```

  - 설계 주의: 프로세스 치환 안의 `grep` 실패는 `diff`로 전파되지 않아 양쪽 모두 추출 0건이면 빈 입력끼리 비교해 통과한다 — 선행 `grep -q` 2건으로 표 실재를 먼저 확인하고 실패를 stdout 위반 행으로 환원한다.
  - 설계 주의: 표 행 전체(축 정의 2표 + 매트릭스)를 추출해 순서까지 대조하므로, 축 라벨·등급 병기 어느 한 곳의 변형도 diff 출력으로 드러난다.

## 전제 (Assumptions)

- 등급 용도는 리뷰 포인트의 **우선순위 표시·수용 판단 근거**로 한정한다. 등급별 처리 기준·원장 연동은 도입하지 않는다 — 보정은 리뷰를 받는 작성자의 몫이고, 작성자 입장의 수용·방어 판단은 `git-pr-feedback`에서 수행한다 (사용자 확정, 2026-08-07 대화).
- 다른 평가 스킬은 대상이 아니다 — `git-pr-feedback`은 조치 관점 의견 유형 구분 보유, `git-qa`는 통합 테스트 체크리스트라 불필요, `pi-scan`은 이미 노출된 정보 평가라 발생확률 축이 성립하지 않는다 (이슈 #72 배경).
- 매트릭스·축 정의는 `issue-audit/SKILL.md`에서 **그대로 복사**한다 — 스킬 독립성 규칙(각 스킬 단독 실행 가능) 때문에 파일 참조로 대체할 수 없다. 두 스킬 간 중복은 수용하며 한쪽 변경 시 동기화가 필요하다 (검토 후 버린 대안: `issue-audit` 참조 링크만 두기 — 단독 설치 환경에서 끊어져 배제).
- 리뷰 포인트 항목에 등급과 함께 **축 판정도 병기**한다 — 등급만 적으면 "축 먼저 판정" 원칙의 재현·검증이 불가능해진다.
- frontmatter description·AI-CONTEXT.md 스킬 목록 표는 갱신하지 않는다 — 등급은 출력 형식 상세라 스킬 선택 트리거와 무관 (최소 변경 원칙).
- 표기는 한글 우선 병기 관례를 따른다 — 높음(HIGH) 형식 (#46 선례).
