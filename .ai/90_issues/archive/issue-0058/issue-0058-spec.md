# Issue #58 스펙 git-pr PR 제출까지 확장 — 유형(정식/드래프트) 확인·메시지 승인 게이트 필수화

## 목표 (Goal)

git-pr이 메시지 작성에서 끝나지 않고, PR 유형(정식/드래프트) 확인과 메시지 승인 게이트를 거쳐 해당 유형의 PR 생성까지 수행한다.

---

## 범위 (Scope)

**포함 (In)**

- 기본 동작 확장 — 메시지 작성 절차에 "PR 유형 확인(정식/드래프트(draft)) 질의"를 필수 선행 단계로, "메시지 승인 게이트"를 필수 후행 단계로 추가하고, 승인 후 해당 유형으로 PR을 실제 생성
- 승인 게이트 — 최종 제목·본문을 제시하고 작성자 승인 후에만 제출, 유형과 무관하게 생략 불가
- `--draft` 옵션 — 유형 확인 질의를 생략하고 드래프트로 확정, 이후 절차는 기본 동작과 동일
- description·개요의 "실제 PR 생성·제출이 아니라 메시지 텍스트 작성용" 문구를 새 동작에 맞게 갱신
- `README.md`·`.ai/AI-CONTEXT.md`·`ai-workspace/SKILL.md`의 git-pr 설명 동기화 (`ai-workspace/SKILL.md`는 교차모델 audit F-4로 범위 추가 — 2026-07-29 `--response` 승인)

**비포함 (Out)**

- PR 메시지 구조·정책(비즈니스/테크 관점) 자체의 변경
- 드래프트 → 정식 전환(ready for review) 자동화
- 설치본(`~/.claude/skills/` 등 5개 경로) 갱신 — repo가 SSoT, 배포는 install-skills 재실행으로 별도 수행
- 포크(fork) 기반 PR 제출 경로 — head 저장소가 upstream과 다른 경우의 `<소유자>:<브랜치>` head 지정·포크 생성·게시 절차. 같은 저장소의 브랜치를 소스로 하는 제출만 다룬다 (교차모델 audit F-1 — 2026-07-29 `--response` 사용자 지시로 범위 제외).
  단, 포크에서 실행했을 때의 **비지원 안내와 조기 종료는 포함**한다 — 지원 기능 구현이 아니라 지원 범위를 제출 초기에 드러내는 것이라 제외 결정과 충돌하지 않는다 (3차 audit F-3 — 2026-07-30 `--response` 승인)

## 전제 (Assumptions)

- 기본 동작이 "메시지 텍스트 작성만"에서 "제출까지"로 바뀌는 파괴적 변경은 사용자가 의도한 결정이다 (2026-07-29 대화 합의). 근거: 드래프트만 스킬 안에서 제출하면 정식 PR은 수동 이관으로 남아 동작 간 균형이 맞지 않는다. 유형 확인·승인 게이트 필수화가 그 안전장치다.
- 실제 제출은 외부 공개 행위이므로, 유형·옵션과 무관하게 승인 게이트는 생략할 수 없다 (사용자 합의 값 — "메시지를 반드시 확인하고" 올린다).
- 제출 절차는 `## PR 제출` 섹션으로 신설한다 — DoD의 [D] 앵커가 이 헤더에 의존한다 (plan에서 고정한 설계값).
- 옵션 섹션 구조는 이 repo의 기존 관례를 따른다 — issue-work·install-skills의 `## 옵션` + `### `--<이름>`` 패턴. git-pr에는 현재 옵션 섹션이 없어 신설한다.
- 이슈의 "구현 시 결정할 것" 4건은 Task 0 질의로 확정했다 (2026-07-29 사용자 답변).
  - **생성 수단**: `gh pr create`(gh CLI)를 기본으로 하고, gh가 없거나 인증되지 않았으면 GitHub MCP `create_pull_request`로 폴백한다. 근거: 도구 환경에 따라 제출 절차가 끊기지 않게 한다.
  - **베이스 브랜치**: 원격 기본 브랜치를 자동 감지해 채우고, 최종 승인 단계에서 제목·본문과 함께 베이스도 제시해 작성자가 바꿀 수 있게 한다. 통합 배포처럼 대상이 다른 경우도 이 단계에서 교정한다.
  - **메시지만 작성하는 경로**: 별도 옵션(`--message-only` 등)을 두지 않는다. 근거: 승인 게이트에서 거절하면 최종 제목·본문이 제시된 상태로 남아 기존 "텍스트만" 용도를 대체한다.
  - **정식 확정 옵션**: 두지 않는다. 근거: 유형 확인 질의의 기본값이 정식이라 `--draft`와의 대칭만을 위한 옵션은 신설하지 않는다.
- 드래프트 표기는 첫 언급에 "드래프트(draft)"로 병기한다 (repo 관례: 한글 우선·약어 첫 언급 병기). DoD의 `드래프트` grep이 이 표기에 의존한다.
