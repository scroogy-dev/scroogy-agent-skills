### 상세 분석

#### F-14: D2가 실제 프론트매터 범위를 검증하지 않음

- **위험도**: 낮음(LOW)
- **분류**: 누락된 검증
- **설명**: D2 명령은 `grep`을 파일 전체에 적용한다. `--- / foo: bar / ---` 뒤 본문에 `name:`·`description:`을 둔 반례에서도 두 카운트가 각각 1이라 게이트가 통과했지만, 실제 YAML 프론트매터에는 필수 키가 없었다.
- **영향**: 현재 프론트매터는 정상이나, 후속 편집에서 스킬 발견을 깨뜨리는 잘못된 프론트매터가 D2를 통과할 수 있다.
- **권장 조치**: 첫 `---` 쌍 사이만 추출해 YAML로 파싱하고, `name`·`description` 키·값과 허용 키 집합을 검증한다. 최소한 검사를 프론트매터 범위로 한정한다.

#### F-15: D4가 만족 불가 동작 행의 절 귀속을 검증하지 않음

- **위험도**: 낮음(LOW)
- **분류**: 누락된 검증
- **설명**: `- **만족 불가 시**:` 행을 `### 제약 검증`에서 제거해 `## 예시` 아래로 옮긴 반례에서도 D4의 헤더·전역 행 카운트가 모두 1로 남아 통과했다. 실제 절 내부 카운트는 0이었다.
- **영향**: 제약 검증 로직에서 실패 동작이 빠지는 회귀를 결정적 게이트가 탐지하지 못한다.
- **권장 조치**: D12와 같은 방식으로 `### 제약 검증` 절을 `awk`로 추출한 뒤 그 안에서 `만족 불가 시` 행이 정확히 1건인지 검사한다.

#### F-16: D11이 안내도 행의 핵심 형식을 고정하지 않음

- **위험도**: 낮음(LOW)
- **분류**: 누락된 검증
- **설명**: AI-CONTEXT 정규식의 점(`.`)은 백틱이 아닌 임의 문자와도 일치하고, README 검사는 링크 라벨만 본다. 따라서 `` `issue-model-triage` ``를 `xissue-model-triagex`로 바꾸고 README 링크 대상을 `./wrong/`으로 바꾼 반례에서도 D11의 네 카운트가 모두 기대값을 유지했다.
- **영향**: 현재 안내도는 정상이나, 표기 관례 훼손이나 깨진 README 탐색 링크가 D11을 통과할 수 있다.
- **권장 조치**: AI-CONTEXT의 백틱을 리터럴로 고정하고, README 행은 `[issue-model-triage](./issue-model-triage/)` 링크 전체를 검사한다. 가능하면 두 표 모두 행 끝의 설명 열까지 포함해 정확히 1행을 검증한다.
