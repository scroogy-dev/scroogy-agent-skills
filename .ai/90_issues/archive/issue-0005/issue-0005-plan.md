## Tasks

### Task 1: `.ai/AI-CONTEXT.md` 정적 판정 결과 제거

- [x] 완료
- **목표**: git-tracked 안내도에서 로컬 환경 의존 문구를 제거하고 판정 규칙만 유지한다.
- **작업 내용**:
  1. `## 프로젝트 도메인` 아래 "단독 repo이므로 ... (CoC 자동 판정 — `../.ai/AI-CONTEXT.md` 부재)" 문구를 환경 중립적 표현으로 교체 또는 제거.
  2. `## 에이전트 운영 지침` 아래 "본 repo는 단독 repo다." 문구 제거. 전제 문장은 판정 규칙만 남도록 정리.
- **완료 기준**: 안내도 어느 위치에도 "이 repo는 단독/멀티다"라는 정적 결과 문구가 남아 있지 않다.

### Task 2: `ai-workspace` / `ai-workspace-directory` 스킬 점검

- [x] 완료
- **목표**: 같은 원칙(로컬 상태를 git-tracked 파일에 기록 금지)이 스킬 절차에 반영되어 있는지 확인하고 필요 시 수정한다.
- **작업 내용**:
  1. `ai-workspace/SKILL.md`의 `init-0단계`, `init-2단계`, `update-4단계`에서 자동 판정 결과를 `AI-CONTEXT.md`에 *기록*하라는 지시가 있는지 검토.
  2. 있다면 "결과는 사용자 보고용으로만 노출하고, 안내도 본문에는 규칙만 기재"하도록 수정.
  3. `ai-workspace-directory/SKILL.md`도 동일 원칙으로 점검 (자매 스킬 — 로비는 별도 파일이지만 일관성 유지).
- **완료 기준**: 두 스킬 모두 안내도 본문에 정적 판정 결과를 기재하지 않는다.

### Task 3: 양쪽 환경 진입 절차 동작 검증

- [x] 완료
- **목표**: 단독 repo / 멀티 repo 양쪽 환경에서 동일 안내도로 진입 절차가 모순 없이 동작함을 확인한다.
- **작업 내용**:
  1. 수정된 `AI-CONTEXT.md`의 `## 에이전트 운영 지침` → `### 진입 절차`를 단독/멀티 시나리오에 대입해 흐름이 깨지지 않는지 문서 검증.
  2. 진입 절차에 잔존하는 "본 repo는 ..." 같은 정적 단정이 없는지 최종 확인.
- **완료 기준**: 두 시나리오 모두 안내도 본문만으로 같은 진입 절차가 적용된다.
