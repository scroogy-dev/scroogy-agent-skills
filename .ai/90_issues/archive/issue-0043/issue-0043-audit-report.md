### 상세 분석

#### F-1: 대표 구현 모델만 비교하면 다중 모델 이력을 놓침

- **위험도**: MEDIUM
- **분류**: 암묵적 가정
- **설명**: summary 템플릿은 한 구분에 여러 모델이 관여하면 표에는 대표 모델을 적고 Task별 `수행 모델`을 세부 SSoT로 삼는다. 반면 Task N 완료 기준은 대표 `구현 모델` 행과 `audit 모델` 행 두 개만 비교한다. 예를 들어 Task 1은 Anthropic, Task 2는 OpenAI가 수행하고 대표 구현 모델을 Anthropic으로 적으면, OpenAI audit도 표의 두 행만 보면 다른 벤더로 판정된다.
- **영향**: audit 모델이 실제 구현 일부에 참여했어도 교차모델 독립성 조건을 만족한 것으로 마감할 수 있다.
- **권장 조치**: audit 벤더가 Task 0 및 일반 실행 Task의 모든 비어 있지 않은 `수행 모델` 벤더와 달라야 한다고 완료 기준을 명시한다. 대표값 비교만 유지하려면 다중 구현 모델일 때의 대표 선정 규칙과 허용 범위를 명확히 제한한다.

#### F-2: Task N 및 추가 일반 Task 구조가 검증 밖임

- **위험도**: MEDIUM
- **분류**: 누락된 검증
- **설명**: 현재 awk는 Task 0·1·2 헤더 횟수와 그 블록의 필드만 센다. Task N 헤더를 삭제하거나 복제해도 `PASS`하고, `### Task 3:` 또는 `### Task X:` 블록을 지표 없이 추가해도 `PASS`한다.
- **영향**: 마지막 audit 결과 기록 블록이 유실되거나 일반 실행 Task가 지표 없이 추가되어도 결정적 게이트가 회귀를 놓친다.
- **권장 조치**: 템플릿의 기대 Task 헤더 집합(Task 0·1·2·N)을 각각 정확히 1회로 고정하고, 그 외 Task 헤더는 0건으로 판정한다. 템플릿에 일반 Task를 늘릴 때는 기대 집합과 지표 검사도 함께 갱신한다.

#### F-3: 모델 기록 표의 실제 행 구조가 무방비임

- **위험도**: MEDIUM
- **분류**: 누락된 검증
- **설명**: DoD #5는 SKILL·plan·workflow의 참조 문구 5곳만 확인한다. summary 템플릿의 `설계 모델`·`구현 모델`·`audit 모델` 행 자체는 세지 않아 `audit 모델` 행 삭제 변형에서도 관련 검증이 모두 통과한다.
- **영향**: Task N 완료 조건이 가리키는 기록 행이 사라져도 릴리스 전 검증에서 잡히지 않는다.
- **권장 조치**: summary 템플릿의 세 행을 각각 정확히 1회 확인하고, `모델 기록` 표 밖의 같은 행은 0건인지 판정하는 구조 검사를 DoD #5에 추가한다.
