- 렌더 스크립트는 원문을 `&`·`<`·`>`만 이스케이프해 `<pre id="quiz-source">` 바로 뒤에 쓴다. HTML 파서는 `pre` 시작 태그 직후의 첫 LF를 제거하므로, CDN 스크립트가 실행되기 전부터 원문 DOM이 달라진다.
- 입력은 통과하는 템플릿 md 앞에 `printf '\n'`으로 LF 하나만 더한 파일이다. Playwright에서 CDN을 차단하면 `rendered=false`, `visible=true`이지만 `source.textContent === md`는 false이고, 문자열 길이는 입력 4,224 / 표시 원문 4,223이다.
- 세 라이브러리를 하나씩 차단해도 모두 `rendered=false`, `visible=true`, `contentEmpty=true`, `equal=false`였다. 실행 요소 정화 우회는 발견하지 않았다.
- spec R7 두 번째 항목의 기존 Chrome 명령에서 입력 복사 한 줄만 아래로 바꿔도 `위반: 원문 영역이 md와 다름`이 나온다. 나머지 표시·원문 비교 절차는 그대로다.

```bash
{ printf '\n'; cat git-review-quiz/templates/quiz-template.md; } > "$d/q.md"
```

- 수용 테스트의 기본 템플릿은 `<!--`로 시작하고, 셸 러너의 `source_of()`는 HTML 파일 문자열만 복원하므로 브라우저 파서의 첫 개행 제거를 검출하지 못한다. 이 검증 공백은 같은 원인의 일부로 기록하고 별도 테스트 발견으로 중복 집계하지 않았다.
- 일반적인 생성 md에서는 기본 동작이 통과하므로 정상 경로 차단으로 분류하지 않았다. 특수 입력에서 명시한 원문 일치 보장이 성립하지 않아 매트릭스로 중간(MEDIUM)을 산출했다.

</details>
