#### F-2: 문자열 검색으로는 렌더 완료 속성을 판정할 수 없다

- **위험도**: 🔴 높음(HIGH)
- **영향 축**: 스펙·기능 달성 차단
- **발생확률 축**: 통상 사용
- **카테고리**: 테스트
- **관점**: 가짜 `[D]` 사전 판별·모호성
- **계보**: 신규
- **권장 조치**: dump한 DOM의 `<html>` 시작 태그에서 실제 속성을 읽고, 렌더 명령·Chrome 실패와 CDN 부재를 구분한다.
- **완료 기준**:
  - `<html>`에는 속성이 없고 CSS·JS에만 `data-rendered`가 있는 입력을 미완료로 판정한다.
  - 실제 `<html data-rendered>`는 완료로 판정하며, AC9·AC17 명령의 세 위치가 같은 기준을 쓴다.
  - 원문 폴백의 정상 입력은 통과하고, 원문이 숨겨지거나 바뀐 입력은 실패한다. 렌더 명령 실패는 CDN 판정 불가로 숨기지 않는다.

<details>
<summary>근거·상세 설명 펼치기</summary>

- Task 2는 `[data-rendered] #quiz-source` CSS와 속성을 붙이는 JS를 HTML 안에 두게 한다. 이 문자열들은 라이브러리를 못 불러와도 `--dump-dom` 출력에 남는다.
- 최소 HTML에 CSS 선택자와 JS 문자열만 넣고 `<html>` 속성을 생략했다. HTMLParser는 `actual html data-rendered=False`를 냈지만 spec의 `grep -q 'data-rendered'`는 종료 코드 0이었다.
- AC9와 DOMPurify 실패 검사는 정상 폴백에서도 위반을 출력한다. AC17 첫 검사는 렌더가 안 끝나도 완료 분기로 들어가므로 CDN 전제를 구분하지 못한다.
- 구현 전 위반 여부만으로 명령의 타당성이 보장되지 않는 사례다. 정상적인 완료 검증 실행 자체가 차단되므로 영향·확률을 각각 기능 달성 차단·통상 사용으로 잡았다.

</details>
