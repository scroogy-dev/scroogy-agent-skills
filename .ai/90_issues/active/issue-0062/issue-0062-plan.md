  3. 표 아래 주석에 위험도가 두 축 조합으로 산출됨(SKILL.md 매트릭스 참조)을 안내한다.
- **완료 기준**:
  - [D] 표 헤더와 상세 분석 축 필드 2종이 존재  (검증: spec DoD 두 번째 `[D]` 항목의 검증 명령 실행, 출력 0건이면 통과)
  - [D] 상세 분석 블록에서 `영향 축`·`발생확률 축` 행이 `위험도` 행과 같은 블록 안에 위치
    <details>
    <summary>검증 명령 — repo 루트에서 실행, 출력 0이면 통과</summary>

    ```bash
    T=issue-audit/templates/issue-audit-report-template.md
    awk '
      /^#### F-/ { o = 1; r = 0; i = 0; p = 0 }
      o && /^- \*\*위험도\*\*:/ { r = 1 }
      o && /^- \*\*영향 축\*\*:/ { i = 1 }
      o && /^- \*\*발생확률 축\*\*:/ { p = 1 }
      /^---$/ && o { if (!(r && i && p)) b++; o = 0 }
      END { if (o && !(r && i && p)) b++; print b+0 }
    ' "$T"
    ```

    - 설계 주의: 필드 존재만 세면 블록 밖(주석·안내문)의 등장으로 통과할 수 있어, `#### F-` 블록 단위로 3종 동시 존재를 판정한다. 앵커는 `영향 축`이다 — `영향`만 잡으면 기존 접기 안 영향 서술 필드와 충돌해 가짜 통과가 된다.
    </details>

### Task 3: issue-work `--response` — 승인 게이트에 등급별 기본 제시값 반영

- [ ] 완료
- **목표**: `--response` 처리 방향 표·승인 질의가 등급에서 기본 제시값을 끌어오게 하여, 낮음(LOW)·정보(INFO)가 사용자 명시 승격 없이는 보정 루프에 들어가지 않게 한다.
- **작업 내용**:
  1. `issue-work/SKILL.md` `--response` 동작 3단계(처리 방향 표)에 등급별 기본 제시값 표(4행)를 추가한다 — 높음(HIGH)=반영(보정 후 재검증 대상) / 중간(MEDIUM)=기본값 없음(사용자 판단) / 낮음(LOW)=이관(원장 등재, 수용 사유·재검토 조건 기재) / 정보(INFO)=보류(기록만, 원장 등재는 선택).
  2. 4단계(항목별 승인 질의) 서술에 기본 제시값의 성격을 명시한다 — 등급은 기본 제시값일 뿐이며 사용자가 항목별로 뒤집을 수 있고, 낮음(LOW)은 사용자가 명시 승격하지 않는 한 보정 루프에 넣지 않는다.
  3. 기존 #52 순서 게이트(1단계 발견 우선)와 #31 자동 보정 금지 서술은 변경하지 않는다 — 기본 제시값은 2단계 발견의 처리 방향 열만 채운다.
- **완료 기준**:
  - [D] 등급별 기본 제시값 표(4행)가 존재  (검증: spec DoD 세 번째 `[D]` 항목의 검증 명령 실행, 출력 0건이면 통과)
  - [D] #52 순서 게이트·#31 자동 보정 금지 서술이 잔존 — 이 항목이 무너지면 기본 제시값이 순서 게이트를 우회하는 통로가 되므로, 아래 명령이 기존 서술의 삭제를 잡아낸다
    <details>

    - 설계 주의: 순서 게이트는 현행 4단계·5단계에 각 1회 등장하므로 2회 미만이면 삭제가 발생한 것이다.

    - 설계 주의: 프로세스 치환 안의 `grep` 실패는 `diff` 종료 상태로 전파되지 않아 두 경로가 모두 잘못되면 빈 입력끼리 비교해 통과한다 — 선행 `grep -q`로 두 파일의 Task 헤더 실재를 먼저 확인하고 실패를 stdout 위반 행으로 환원한다.

  - [D] 이 검증 전에 Task 0 및 모든 일반 실행 Task의 summary `결과`가 완료·부분 완료·스킵 중 하나로 확정 — Task N 제외 블록마다 유효 `결과` 행 정확히 1개, 무효·중복 0건이며, 아래 `수행 모델` 게이트의 선행 조건이라 비워 두면 그 게이트의 검사 대상이 공집합이 되어 통과처럼 보인다

    ```bash

    awk '
      /^### Task / { if (o && !n && v != 1) b++; o = 1; v = 0; n = ($0 ~ /^### Task N/) }
      o && /^- \*\*결과\*\*:/ {
        if ($0 ~ /^- \*\*결과\*\*: (완료|부분 완료|스킵)[[:space:]]*$/) v++
        else if (!n) b++
      }
      END { if (o && !n && v != 1) b++; print b+0 }
    ' "$S"
    ```

    - 설계 주의: 총개수 비교는 한 블록의 미확정을 다른 블록의 중복 행으로 상쇄해도 통과하므로 블록 단위로 센다.
    - 의존 근거: 아래 게이트의 "`수행 모델` 값 필수" 조건은 `결과`가 완료·부분 완료인 블록에서만 발동하도록 걸려 있다.

    ```bash
      o && /^- \*\*결과\*\*: (완료|부분 완료)[[:space:]]*$/ { d = 1 }

    ' "$S"
    ```
