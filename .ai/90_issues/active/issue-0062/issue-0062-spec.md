# Issue #62 스펙 issue-audit 심각도 체계 개선 — 영향×발생확률 매트릭스·등급별 처리 기준

> 이슈: [#62](https://github.com/scroogy-dev/scroogy-agent-skills/issues/62)

## 목표 (Goal)

2단계(비판적 검증) 발견의 등급 산정을 영향×발생확률 매트릭스로 기계화하고, 등급이 처리 방식을 결정하게 하여 교차모델 audit 이후 재검증 루프 진입량을 구조적으로 줄인다.

---

## 범위 (Scope)

**포함 (In)**

- `issue-audit/SKILL.md` — 2단계 위험도 분류를 매트릭스 기반으로 개편: 영향 축·발생확률 축 필드 정의, 영향×발생확률 매트릭스, 등급별 기본 처리 기준, 재감사 신규 발견 동일 적용 명시
- `issue-audit/templates/issue-audit-report-template.md` — 발견 사항 표·상세 분석 블록에 영향·발생확률 필드 추가
- `issue-work/SKILL.md` `--response` — 승인 게이트에 등급별 기본 제시값 반영 (낮음(LOW)=원장 이관, 정보(INFO)=기록만이 기본값)

**비포함 (Out)**

- 1단계(적합성 검증) 판정 체계 변경 — 미충족(FAIL)·부분 충족(PARTIAL) 우선 처리(#52 순서 게이트)는 그대로 유지하며, 1단계 발견은 매트릭스 대상이 아님
- 자동 보정 도입 — #31 자동 보정 금지 원칙 유지. 등급은 승인 게이트의 기본 제시값을 정할 뿐, 실행은 항목별 승인 후
- delta 재검증(보정분만 확인) — 배제한 대안. 재검증은 전체 재감사 유지
- 원장(`.ai/70_ledger/`, #61) 구조 자체의 변경 — 낮음(LOW) 등급의 이관 목적지로 사용만 한다
- 설치본 스킬(`~/.claude/skills/` 등) 재배포 — `install-skills`로 사용자가 별도 수행

## 전제 (Assumptions)

- 대상은 repo 소스(`issue-audit/`, `issue-work/`)다. 설치본(`~/.claude/skills/` 등)은 구버전이며 이 이슈에서 갱신하지 않는다 — 머지 후 `install-skills`로 사용자가 재설치한다.
- 분류 값 표기는 한글 우선 병기 관례를 따른다 — `높음(HIGH)` 형식 (#46 선례). 영향·발생확률 축 값은 한국어 단독 표기다(영문 대응어를 만들지 않는다).
- 매트릭스·처리 기준의 값은 이슈 본문에 "확정"으로 명시된 값을 그대로 옮긴다 — 이 이슈에서 재설계하지 않는다.
- 검토 후 버린 대안(감사인 재량 유지, delta 재검증)과 그 이유는 이슈 본문의 "배제한 대안" 접기에 있다 — 여기서는 포인터만 남긴다.
- 발견 사항 표의 열 순서와 상세 분석 필드명(`- **영향 축**:`, `- **발생확률 축**:`)은 plan에서 정한 값이며 DoD 검증 명령의 앵커다 — 구현에서 임의로 바꾸지 않는다. 축 필드에 `축`을 붙인 이유는 기존 접기 안 영향 서술 필드(`- **영향**:`)와의 이름 충돌 회피다 — 표의 열 이름은 행 전체 앵커라 충돌이 없어 `영향`·`발생확률` 그대로 둔다.
- 기존 `#### 위험도 분류`의 등급 의미 표(높음=장애·데이터 손실… 서술)는 매트릭스가 대체한다 — 의미 표와 매트릭스가 병존하면 산정 기준이 두 개가 되어 이슈 목표(기계적 산정)와 어긋난다.
- 보안·데이터 손실 결함은 영향 축 `스펙·기능 달성 차단`에 넣는다 — 그 축 값 정의에 "데이터 손실·보안 침해처럼 결과가 기능 달성을 무효화하는 결함을 포함한다"를 부기한다 (Task 0 질의로 확정). 등급은 발생확률 축과의 조합으로 갈리며(통상 사용=높음(HIGH), 특수 조건·엣지=중간(MEDIUM)), 1단계 판정 기준 소절의 "1단계 충족(PASS)과 2단계 높음(HIGH) 병존" 예시 문장은 변경하지 않는다. 부기가 없으면 옛 의미 표 삭제 후 보안 결함의 축 매핑이 감사인 재량으로 남아 기계적 산정이 그 지점에서 무너진다.
- 발생확률 축 값은 축약형 `통상 사용`·`특수 조건·엣지`로 통일한다 — 이슈 본문의 완전형 서술("통상 사용에서 발생" 등)은 매트릭스 헤더·축 정의·템플릿 허용 값 안내 모두에서 축약형으로 옮긴다.
- 리포트 템플릿의 축 필드 추가는 발견 사항 표와 `#### F-` 상세 분석 블록에 한정한다 — `기등재 참조 항목`·`이전 발견 추적` 표는 변경하지 않는다.
- `issue-audit/SKILL.md` `## 출력 요약 형식`의 2단계 집계 서술은 변경하지 않는다 — 등급별 처리 방향 집계 추가는 이 이슈 범위 밖이다.
- `--response`의 처리 방향 `이관`은 repo 소스에서 이미 목적지가 원장 `.ai/70_ledger/`로 고정되어 있다 (#61 반영본) — 이번 이슈는 그 위에 등급별 기본 제시값 표만 얹는다.
