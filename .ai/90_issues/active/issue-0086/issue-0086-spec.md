# Issue #86 스펙 writing-principles 템플릿에 한국어 작성 규칙(번역투 금지) 섹션 신설

## 목표 (Goal)

`ai-workspace`의 writing-principles 템플릿에 한국어 작성 규칙 섹션이 신설되어, 한국어 산출물의 번역투 패턴(영어권 AI 문체)이 규칙으로 차단된다.

---

## 범위 (Scope)

**포함 (In)**

- `ai-workspace/templates/shared/.ai/10_rules/writing-principles.md` (동기화 원본)
  - `## 한국어 작성 규칙` 섹션 신설: 금지 패턴 6종을 대체 표현과 쌍으로 기재
    1. "A가 아니라 B" 대조 구문 남용 → 대조 없이 단언. 실제 오해를 바로잡을 때만 대조 사용
    2. em dash(`—`) 삽입구·절 연결 → 쉼표·마침표로 문장 분리 또는 괄호 사용
    3. 수사적 콜론("핵심은 하나다: ~") → 자연스러운 문장으로 풀어쓰기
    4. 3항 병렬 나열 습관("빠르고, 안전하며, 확장 가능한") → 실제 필요한 항목만 기재
    5. 영어식 하이픈 합성("고품질-저비용") → 조사·어미로 연결
    6. 은유·의인화 장식 → 직서로 표현. 영어 관용 은유의 직역("북극성 지표", "낮게 매달린 과일" 등) 포함 금지, 사용자가 명시적으로 요청할 때만 사용. 구체 예시 제시는 은유와 다른 것이므로 제한하지 않음을 함께 명시
  - 분류 5종(규범·문장·표현·용어·일관성)으로 섹션을 구조화하고, 아래 사용자 제공 항목 11건을 **문구 그대로** 추가. 기존 패턴 6종은 표현 분류로 편입하고, 중복 표현은 사용자 제공 문구 우선. 분류별 근거 출처는 접기로 병기 (원문은 이슈 #86 본문 변경 범위 6·참고 섹션)
    - [규범] 한글 맞춤법·띄어쓰기·외래어 표기법을 따르고, 애매하면 표준국어대사전을 기준으로 한다.
    - [문장] 한 문장에 한 가지만 담는다. 길어지면 끊는다.
    - [문장] 주어와 서술어가 호응하는지 확인한다.
    - [문장] 능동으로 쓴다. 이중 피동(보여지다, 되어지다)은 쓰지 않는다.
    - [문장] 명사를 셋 이상 이어 붙이지 않고 서술어로 푼다.
    - [표현] 번역 투를 피한다: ~에 대한, ~에 있어서, ~을 통하여, ~에 의해, ~을 가진다.
    - [표현] '~적', '~들', '및', '등'을 습관적으로 붙이지 않는다.
    - [표현] 어려운 한자어·외래어는 쉬운 말로 바꾸되, 뜻이 달라질 우려가 있으면 원어를 괄호로 병기한다.
    - [용어] 전문 용어는 처음 나올 때 한 번 풀어 주고, 이후 같은 용어로만 지칭한다.
    - [용어] 코드·API·기술 용어는 원문 표기를 유지한다. 번역이 관례로 굳은 경우(배포, 저장소, 의존성)에만 우리말을 쓴다.
    - [일관성] 한 문서 안에서 종결 어미와 높임 수준을 섞지 않는다.
  - 콜론 허용 범위 명시: 리스트 항목의 `**용어**: 설명` 형식은 "리스트형 우선" 규칙이 요구하는 형식이므로 금지 대상에서 제외
  - 기존 "한글 표현 우선" 항목을 신설 섹션으로 이동 (Task 0 질의로 확정됨)
  - 버전 주석 갱신: 1.0.0 → 1.1.0 (추적용)
  - 규칙 파일 자체의 문체를 신설 규칙에 맞게 정비 (의미·구조 불변)
- `.ai/10_rules/writing-principles.md` (이 repo의 동기화 사본): 원본과 동일하게 갱신

## 전제 (Assumptions)

- 브랜치명은 repo 관례 `issue-<4자리 0패딩>`을 따라 `issue-0086`으로 한다 (#84의 `issue-0084` 선례).
- 신설 섹션의 배치는 `## 제약 규칙` 섹션과 `## 구조 기본값` 섹션 사이로 한다. 언어별 규칙이 구조 기본값보다 제약 규칙에 가까운 층위라 이 위치로 정했다.
- em dash의 결정적 검증은 공백으로 둘러싼 절 연결 용법(` — `)만 검사한다. 문자 자체를 언급할 때는 코드 스팬으로 표기해 오탐을 막는다. 파일 상단 SYNCED 주석의 ` — `는 렌더링되지 않는 이력 표기라 검사에서 제외하고 변경하지 않는다.
- repo 사본 갱신은 이 PR에서 수동으로 수행한다. 사본은 버전 고정 파일이라 `ai-workspace` update가 항상 최신본으로 덮어쓰지만, 이 repo에서는 원본과 사본을 같은 PR에서 함께 리뷰하기 위해 직접 맞춘다 (#84까지의 관례).
- 검토 후 버린 대안: 기존 `## 제약 규칙` 절 안에 패턴을 추가하는 방식. 한국어로 문서를 작성할 때만 적용되는 규칙이라 언어 무관 규칙과 층위가 달라, 사용자가 별도 섹션 신설로 방향을 지시했다 (2026-08-10 대화, 이슈 본문에 반영됨).
- "한글 표현 우선" 항목은 신설 `## 한국어 작성 규칙` 섹션으로 이동한다 (Task 0 질의에서 사용자가 확정, 2026-08-10). 한국어로 문서를 작성할 때의 규칙이라 신설 섹션과 같은 층위다.
- 금지 패턴 6번(은유·의인화 장식)은 Task 1~3 구현 후 사용자 지시로 추가한 범위 확장이다 (2026-08-10 대화, 이슈 본문도 함께 갱신). 사용자가 "은유와 예시는 명백히 다른 것"을 강조해, 구체 예시 제시는 제한하지 않는다는 문구를 규칙에 함께 명시한다.
- 분류 5종 체계와 항목 11건, 분류별 근거 출처는 사용자가 직접 제공했다 (2026-08-10 대화, 두 번째 범위 확장). 근거 표에는 사용자 지시로 "표현(AI 문체)" 행을 추가해, 기존 패턴 6종이 문헌과 별개로 생성형 AI 사용 경험에서 나온 출처임을 표기했다. 중복 시 사용자 문구 우선 원칙에 따라 기존 "한글 표현 우선"의 예외 문구(코드 식별자·도구명·정착 기술 용어)를 삭제하고 용어 분류 참조로 대체했다. 근거 출처 표는 배경(Why)이라 접기로 병기한다.
- 기존 패턴 6종은 분류 편입 시 굵은 이름 라벨을 떼고 평문 항목으로 통일했다. 이름 라벨을 유지하면 사용자 제공 항목(이름 없는 평문)과 형식이 갈라진다.
