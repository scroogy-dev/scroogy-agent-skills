### Task 2: HTML 템플릿과 렌더 스크립트

- [x] 완료
- **목표**: md 하나로 같은 이름의 HTML을 결정적으로 만들고, 브라우저에서 목차·문항 조작·도식이 동작하며 변환 결과의 실행 요소를 걸러 내고, 라이브러리 중 하나라도 못 불러오면 원문을 보인다.
- **대상 요구사항**: R7, R8, R14
- **작업 내용**:
  1. 외부 라이브러리 버전을 정한다. marked·mermaid·DOMPurify를 `cdn.jsdelivr.net/npm/<이름>@<주>.<부>.<수>/…` 경로로 쓰고, 공개된 지 2주 넘은 정확한 버전을 고른다. 고른 버전과 확인 방법을 summary에 적는다.
  2. `templates/quiz-template.html`을 만든다(CSS·JS 포함 단일 파일).
     - 원문 자리 행은 정확히 `<pre id="quiz-source">@@QUIZ_SOURCE@@</pre>`이다. `<pre>`에 다른 속성을 두지 않는다.
     - 렌더 영역은 `<main id="quiz-content"></main>`(처음에는 비어 있음)이다. spec R14 첫 항목이 이 id로 렌더 영역을 찾는다.
     - CSS: 색 변수와 `@media (prefers-color-scheme: dark)`, 좁은 화면에서 목차를 본문 위로 내리는 배치, 가로 스크롤 없음. `#quiz-source`를 숨기는 규칙은 `[data-rendered]` 선택자 아래에만 둔다.
     - JS: `marked`·`mermaid`·`DOMPurify` 중 하나라도 없으면 아무것도 바꾸지 않고 끝낸다(AC9, AC17). 셋 다 있으면 원문 영역의 `textContent`를 marked로 변환하고, 그 결과를 `DOMPurify.sanitize`로 거른 뒤에만 `main#quiz-content`에 넣는다. 거르기 전의 변환 결과를 DOM에 넣는 경로는 두지 않는다. 이어서 h2·h3에 id를 달아 목차를 만들고, mermaid를 `startOnLoad: false`·`securityLevel: 'strict'`로 초기화해 `language-mermaid` 코드 블록을 도식으로 바꾼다. `## 문항` 아래 문항마다 객관식은 보기를 눌러 정답 여부를 표시하고 `정답·해설` 접기를 열며, 주관식은 입력란과 `모범 답안 보기` 버튼을 둔다. 마지막에 `<html>`에 `data-rendered`를 단다. 중간에 예외가 나면 바꾼 내용을 되돌리고 `data-rendered`를 달지 않는다. 단, mermaid가 도식 하나를 문법 오류로 그리지 못하면 예외로 보지 않고 그 자리의 코드 블록을 그대로 둔 채 계속한다(spec 전제 "mermaid 도식 문법 오류").
     - mermaid는 정화가 끝난 뒤 SVG를 넣으므로 `securityLevel`을 `strict`보다 느슨하게 두지 않는다.
  3. `scripts/render-quiz-html.sh <md 파일>`을 만든다(실행 권한 포함).
     - 인자가 1개가 아니거나, 파일을 읽을 수 없거나, 확장자가 `.md`가 아니면 종료 코드 2.
     - md를 `&`·`<`·`>` 순서로 이스케이프해 자리 표시자에 넣는다. md 바이트를 그대로 보존한다(앞뒤 개행 추가·삭제 없음).
     - 결과는 md와 같은 디렉토리의 `<md 이름에서 .md를 뺀 것>.html`에 임시 파일을 거쳐 쓰고, 그 경로 1행을 출력하고 종료 코드 0.
  4. `tests/run-tests.sh`에 렌더 케이스를 더한다. 입력 md는 러너가 임시 디렉토리에 만들며 `&`·`<`·`>`·`</pre>`·`<script>`를 담는다(fixture 접두어 규칙을 건드리지 않는다). 원문 영역 왕복 일치가 이스케이프를 덮으므로 md 안의 `<script>`가 원문 영역 밖으로 나가지 않는다는 것도 함께 확인된다.
     - 라벨: `렌더: 같은 이름 .html 생성 통과`, `렌더: 두 번 렌더 결과 동일 통과`, `렌더: 원문 영역 왕복 일치 통과`, `렌더: 대상별 이름 유지 통과`(같은 디렉토리 `a.md`·`b.md`가 각각 `.html`을 남김), `렌더: 외부 라이브러리 버전 고정 통과`, `렌더: 버전 미고정 템플릿 격추`, `렌더: 정화 라이브러리 누락 템플릿 격추`, `렌더: 원문 영역 기본 표시 통과`, `렌더: 원문 영역 숨김 속성 격추`, 사용오류 `렌더 사용오류: 인자 없음`, `렌더 사용오류: 없는 파일`, `렌더 사용오류: .md 아닌 파일`.
     - 버전 고정 검사는 외부 `<script src>`가 모두 정확한 버전으로 고정됐고 marked·mermaid·DOMPurify가 하나씩 있는지 본다. 이 검사와 기본 표시 검사는 템플릿 파일을 인자로 받는 함수로 두고, 격추 케이스는 임시 사본을 변형(버전 지우기, DOMPurify `<script>` 행 지우기, 숨김 속성 더하기)해 같은 함수에 넣는다.
  5. 헤드리스 Chrome으로 spec R7의 AC9 두 항목과 R14 두 항목을 실행하고, 원문 표시 판정의 반례 검증(아래 완료 기준 셋째 항목)을 실행한다. Playwright MCP로 렌더한 템플릿 HTML을 열어 목차·객관식 클릭·주관식 모범 답안 보기·접기·mermaid·다크 모드·너비 390px를 확인한다. 문법 오류 도식 1개를 더한 md의 HTML도 열어, 그 도식 자리만 코드 블록으로 남고 나머지가 렌더되는지 확인한다. 확인 결과를 summary에 적는다.
- **완료 기준**:
