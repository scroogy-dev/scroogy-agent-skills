### Task 3: `init` 모드 명세 작성

- [ ] 완료
- **목표**: building 이름과 floor 목록만으로 로비 `.ai/AI-CONTEXT.md`를 생성하는 절차를 SKILL.md에 명세한다.
- **작업 내용**:
  1. 입력 파라미터(필수/선택), 출력 형식 정의.
  2. 대상 경로 명시: `<워크스페이스 루트>/.ai/AI-CONTEXT.md` (`.ai/` 부재 시 함께 생성).
  3. 표준 섹션 구조(본문 첫 줄 `> last updated: YYYY-MM-DD`, 정체성, Floors 디렉터리, 라우팅 규칙, 공통 규약, Why 진입점, 에이전트 운영 지침) 강제 규칙 작성. YAML frontmatter는 사용하지 않는다.
  4. floor `status` 결정 규칙: 안내도 존재 → `active`, 안내도 부재 → `placeholder`(+ 경고), 사용자가 보존 지시한 floor → `archived`.
  5. 분량 가드레일(150~250줄) 검증 절차 추가.
- **완료 기준**: `init` 모드 입력만 보고 AI가 동일 산출물을 재현할 수 있다.

### Task 4: `update` 모드 명세 작성

- [ ] 완료
- **목표**: 기존 로비 `.ai/AI-CONTEXT.md`를 진단·재구성하고 floor 이동 목록을 산출하는 3단계 절차를 명세한다.
- **작업 내용**:
  1. SSoT 위배 패턴 진단 체크리스트 정의 (도메인 본문, 코드 스니펫, floor 상세 목차, 비대화 등).
  2. 디스크 floor 상태(`<repo>/.ai/AI-CONTEXT.md` 존재 여부)와의 drift 진단 — `active` ↔ `placeholder` 전환, 로비에는 있는데 디스크엔 없는 floor / 반대 케이스 모두 포함. `archived`로 표시된 floor는 drift 검사 대상에서 제외.
  3. 1단계 진단 리포트 출력 형식 정의.
  4. 2단계 재구성된 로비 `.ai/AI-CONTEXT.md` 전문 출력 규약 정의.
  5. 3단계 floor 이동 후보 콘텐츠 목록 출력 형식 정의 (대상 floor 추정 포함, 후속 스킬이 받기 좋은 구조).
- **완료 기준**: 임의의 기존 로비 입력에 대해 3단계 출력이 일관되게 생성된다.

### Task 5: 모드 자동 판정 + 비-VCS 환경 안전성

- [ ] 완료
- **목표**: 사용자가 모드를 명시하지 않은 경우 워크스페이스 루트의 `.ai/AI-CONTEXT.md` 존재 여부로 자동 분기하고, git 명령 없이 동작하도록 보장한다.
- **작업 내용**:
  1. 대상 경로 결정: `./.ai/AI-CONTEXT.md` (워크스페이스 루트 기준, 프로젝트 루트가 아니라 `.ai/` 하위).
  2. 자동 판정 규칙: 파일 없으면 `init`, 있으면 `update`.
  3. 사용자 확인 절차(덮어쓰기 위험 회피) 작성.
  4. git 명령 의존 금지 — 본문 첫 줄 `> last updated: YYYY-MM-DD`는 스킬 실행 시점으로 자동 기록 (`update` 모드에서도 매번 갱신).
- **완료 기준**: 모드 미지정 시 AI 동작이 일관되게 정의되고, git 환경 부재에서도 안전.
