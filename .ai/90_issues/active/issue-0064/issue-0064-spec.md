# Issue #64 스펙 git-pr 이후 PR 리뷰 코멘트 검토·대응 스킬 신규 작성

## 목표 (Goal)

PR 리뷰 코멘트를 수집·분류하고 항목별 의견을 제시한 뒤, 사용자 선택에 따라 답글 게시 또는 코드 변경으로 대응하는 신규 스킬이 repo에 추가된다.

## 완료의 정의 (Definition of Done)

> **검증 레벨** — 낮을수록 좋다(자동 검증에 가까움). 기본은 L1, 한 레벨 내릴 때마다 강등 사유를 함께 적는다.
>
> - `[D]`  L1 결정적   — 명령이 합/불을 판정, 사람 판단 없음
> - `[QD]` L2 준결정적 — 다른 AI·기준 체크리스트가 채점
> - `[ND]` L3 비결정적 — 사람이 직접 읽고 판단
>
> 아래 `$S`는 Task 1에서 확정하는 스킬명이다. 확정 후 검증 명령은 repo 루트에서 `S=<확정 스킬명>`으로 치환해 실행한다.

- [x] [D] `$S/SKILL.md`가 존재하고 frontmatter `name`이 디렉토리명과 일치한다  (검증: repo 루트에서 `test -f "$S/SKILL.md" && grep -cE "^name: $S$" "$S/SKILL.md"` 출력 1)
- [x] [D] `$S/SKILL.md`에 `## 산출물 접기 기준` 섹션이 정확히 1개 있고 writing-principles 참조가 있다  (검증: `grep -cE '^## 산출물 접기 기준$' "$S/SKILL.md"` 출력 1 그리고 `grep -c 'writing-principles' "$S/SKILL.md"` ≥ 1)
- [x] [D] `git-pr/SKILL.md`의 `## 관련 skill` 절에 신규 스킬 행이 정확히 1개 있다  (검증: `grep -cE "^- $S" git-pr/SKILL.md` 출력 1)
- [x] [D] README.md와 `.ai/AI-CONTEXT.md` 스킬 목록에 신규 스킬 행이 있다  (검증: `grep -c "\[$S\]" README.md` ≥ 1 그리고 `grep -c "\`$S\`" .ai/AI-CONTEXT.md` ≥ 1. README는 기존 행 전부가 링크 형식 `[스킬명](./스킬명/)`이라 링크 텍스트를 검사한다 — Task 3에서 백틱 검사를 관례에 맞게 보정)
- [x] [D] 스킬명 확정이 이슈 #64 댓글로 기록되어 있다  (검증: `gh issue view 64 --repo scroogy-dev/scroogy-agent-skills --json comments --jq '[.comments[].body] | join("\n")' | grep -c '스킬명 확정'` ≥ 1)
- [ ] [QD] 절차 5단계(수집 → 분류·의견 → 선택·승인 → 조치 → 결과 요약)·의견 유형 4종·외부 공개 행위(답글 게시·resolve·push) 승인 게이트가 SKILL.md에 정의되어 있다. push 승인 게이트의 완전성은 아래 체크리스트 6항목으로만 채점하며, 체크리스트 밖 신규 방어 제안은 이 항목의 미충족 사유가 아니라 별도 개선 사항으로 분리한다  (검증: 교차모델 audit 채점, 별도 세션. 종료 기준을 유한 체크리스트로 고정 — 4차 audit `--response` 사용자 승인, 2026-07-31)  ← 강등 사유: 정의의 완전성·적절성은 의미 판단이라 명령으로 환원 불가
  - push 대상 원격이 보관한 PR head 저장소(호스트/소유자/저장소)와 일치한다
  - push ref가 보관한 `headRefName`과 일치한다
  - 승인 SHA가 보관한 `headRefOid`를 기반(조상)으로 한다
  - 승인 전에 커밋 범위(`headRefOid`..승인 SHA)의 커밋 목록·diffstat·최종 diff를 제시한다
  - 기존 작업트리 변경은 분리하거나 포함 여부를 사용자에게 확인받는다
  - push 후 대상 PR head SHA가 승인 SHA와 일치할 때만 반영 완료로 보고한다
- [x] [ND] 스킬명이 후보 중에서 사용자에 의해 확정되었다  (검증: 사람 — 사용자 선택, 2026-07-31 `git-pr-feedback` 확정)  ← 강등 사유: 이름 선호는 사용자 주관 판단

## 전제 (Assumptions)

- 스킬명 결정 기준은 대칭·메타포가 아니라 **사용자가 이 기능을 부를 때의 의도**다. 확정은 사용자가 하며, 확정 즉시 이슈 #64에 댓글로 기록한다.
- 진행 순서는 #64 → #61 → #62로 확정됐다 (#64·#61 이슈의 2026-07-31 결정 댓글). 원장 연계는 범위 외이며, #61 완료 전까지 보류·조치 불필요 항목은 답글로만 기록하는 임시 상태를 SKILL.md에 명시하지 않는다 (원장 도입 시 #61에서 일괄 반영).
- git 계열 관례: 생명주기 단계마다 별도 스킬로 분리한다 (git-review-context 선례). git-pr `--response` 옵션안은 검토 후 배제 — 근거는 이슈 #64 본문의 접기 블록 참조.
- 스킬 독립성 원칙(AI-CONTEXT)에 따라 승인 게이트 규칙은 git-pr을 링크로 참조하지 않고 신규 SKILL.md 본문에 자체 기재한다 (패턴만 git-pr 선례를 따름).
- 코멘트 조회·답글 게시 수단은 `gh` CLI 기본 + GitHub MCP 폴백 (git-pr 선례).
- 산출 문서 표기 제약 (사용자 선호, repo 문서에 없음): 문서 본문 이모지 금지, 한국어 문장에 영어 표현 혼용 최소화 (코드 식별자·도구명 예외), "박다" 표현 금지, 약어 첫 등장 시 전체 명칭 병기.
