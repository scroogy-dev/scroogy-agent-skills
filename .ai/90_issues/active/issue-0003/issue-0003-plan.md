### Task 1: 현재 상태 진단

- [ ] 완료
- **목표**: `ai-workspace-directory`와 `ai-workspace`의 현재 산출물에서 에이전트 탐색에 부족한 요소를 식별한다.
- **작업 내용**:
  1. 두 스킬의 `SKILL.md`와 템플릿을 정독하여 현재 생성되는 안내판(로비/빌딩) 항목을 표로 정리한다.
  2. "임의의 에이전트가 루트 로비만 보고 repo를 고를 수 있는가" 시나리오로 갭 분석한다 (라우팅 단서, repo 요약, 진입점 명시 여부 등).
  3. 진단 결과를 `.ai/99_workspace/notes/`에 임시 노트로 남긴다.
- **완료 기준**: 보강해야 할 항목 목록과 각 항목이 어느 스킬·파일에 들어가야 하는지 1:1 매핑이 정리됨.

### Task 2: 루트 로비(`ai-workspace-directory`) 보강 설계

- [ ] 완료
- **목표**: 멀티 repo 환경에서 에이전트가 루트 안내판만으로 repo를 라우팅할 수 있도록 로비 구조를 설계한다.
- **작업 내용**:
  1. 로비에 들어갈 라우팅 신호(예: repo 목록 + 한 줄 역할 + 대표 키워드/도메인 태그 + 진입 경로)를 정의한다.
  2. SSOT는 소스코드라는 원칙을 어떻게 로비에 명시할지 문구·위치를 정한다.
  3. 기존 워크스페이스 재실행(재구성/갱신) 시 보강 항목이 멱등하게 반영되도록 모드별 동작을 정리한다.
- **완료 기준**: 보강된 로비의 섹션 구성·필수 항목·재실행 동작이 텍스트로 합의 가능한 수준으로 기술됨.

---

### Task 3: 빌딩(`ai-workspace`) 보강 설계

- [ ] 완료
- **목표**: 로비에서 진입한 에이전트가 repo 내부의 코드와 문서를 빠르게 찾을 수 있도록 빌딩 안내판 구조를 설계한다.
- **작업 내용**:
  1. 빌딩 안내판에서 코드 진입점·도메인 문서·정책·ADR로 가는 경로를 정의한다 (기존 `.ai/` 구조와 정합).
  2. dev/doc 프로파일별 템플릿 차이를 식별하고 보강 포인트를 분리한다.
  3. 로비의 라우팅 신호와 1:1로 맞물리는 항목(역할 문장, 태그 등)을 빌딩 측에 어디에 둘지 결정한다.
- **완료 기준**: 빌딩 측 보강 항목과 프로파일별 템플릿 반영 위치가 명시됨.
