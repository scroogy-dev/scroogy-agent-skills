## Tasks

> AI가 순서대로 실행할 작업 단위를 정의합니다.
> 각 작업은 독립적으로 검증 가능해야 하며, **완료 기준은 자연어 대신 실행 명령 + 임계값**으로 적습니다.
> 명령으로 환원이 어려운 항목만 판정 주체(다른 AI / 사람)를 적고 강등 사유를 남깁니다.
> 마지막 고정 Task(교차모델 issue-audit)는 삭제하지 말고 그대로 둡니다.

### Task 1: 리포트 템플릿 상단 메타에 '감사 모델' 줄 추가

- [x] 완료
- **목표**: 감사 리포트가 어느 모델로 감사됐는지 자기기술하도록 메타에 한 줄을 추가한다.
- **작업 내용**:
  1. `issue-audit/templates/issue-audit-report-template.md` 상단 메타 블록(`> 감사 일시` / `> 감사 대상 브랜치` / `> 스펙 출처`)을 확인한다.
  2. 같은 `> 키: 값` 형식으로 `> 감사 모델: <벤더, 모델명>` 줄을 추가한다 (예: `> 감사 모델: <벤더, 모델명 — 예: OpenAI, GPT-5>`). summary의 audit 모델 칸과 교차 대조가 목적이므로 벤더+모델명을 함께 적도록 플레이스홀더를 둔다.
- **완료 기준**: `grep -i '감사 모델' issue-audit/templates/issue-audit-report-template.md` 출력 ≥ 1줄.

### Task 2: (선택) SKILL.md에 감사 모델 기재 안내 포인터 추가

- [x] 완료
- **목표**: 감사 수행 시 모델 기재를 빠뜨리지 않도록 SKILL.md에 안내 1줄을 둔다.
- **작업 내용**:
  1. `issue-audit/SKILL.md`에서 리포트 작성을 안내하는 위치를 찾는다.
  2. 리포트 상단 메타의 '감사 모델' 칸을 채우라는 안내 1줄(포인터)을 추가한다. 기존 본문 톤·길이를 따른다.
- **완료 기준**: `issue-audit/SKILL.md`에 감사 모델 기재를 안내하는 줄이 존재한다 (선택 항목 — 본문 흐름상 불필요하다고 판단되면 스킵하고 그 사유를 summary에 기록).

### Task N (고정): 교차모델 issue-audit 검증

- [ ] 완료
- **목표**: 스펙 위반·누락·소스코드와의 모순을 구현 모델과 다른 시각으로 잡는다.
- **작업 내용**:
  1. spec `완료의 정의`의 `[D]` 항목 검증 명령을 전부 재실행해 통과를 확인한다.
  2. 계획·구현을 수행한 모델과 **다른 모델**(최소 동급 이상 역량)로 `issue-audit`를 실행한다. 방향은 칭찬이 아니라 허점 탐색("스펙 위반·누락·소스코드와의 모순을 찾아라").
  3. 지적 사항을 summary에 반영하고 필요 시 앞 Task를 보정한다.
- **완료 기준**: `[D]` 검증 명령 전부 통과 + 구현 모델 ≠ audit 모델 기록이 summary 모델 칸에 남는다. 이 Task는 사용자가 직접 수행한 audit 결과와 audit 모델("벤더, 모델명")이 summary에 기록된 경우에만 완료로 간주한다.
