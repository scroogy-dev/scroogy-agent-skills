> 이 Task가 spec의 어느 요구사항을 구현하는지 밝힙니다. 여러 개면 `R<n>, R<m>`로 나열합니다.

>
> **완료 기준 형식** — 본문(접기 금지)에는 레벨 태그 + 무엇이 보장되는지 한 문장(+ 강등 사유)만 두고,
> 검증 명령·테스트케이스·기대 출력·명령 설계 주의점은 접기로 내립니다. 접기 제목에 기대 출력을 함께 적습니다

> 다른 게이트의 선행 조건이 되는 항목은 의존 관계와 **선행 조건이 무너졌을 때의 결과**를 본문 문장에 남기고, 메커니즘만 접기에 둡니다.

### Task 1: SKILL.md 규칙 정비 (상태 산출·판정 산출·이모지 대응표·결과 기록)

- [x] 완료
- **목표**: issue-audit SKILL.md가 1단계·2단계 상태 규칙, 판정 규칙과 의미, 이모지 대응표, 갱신된 헬퍼 예시 출력, 결과 기록의 판정 한 줄·접기 해석·표기 위치, 출력 요약 형식의 첫 줄 판정을 담는다. 뒤 Task의 헬퍼·러너가 이 표를 SSoT로 읽는다.
- **대상 요구사항**: R6, R1, R2, R3
- **작업 내용**:
  1. `### 3단계: 결과 기록`의 번호 목록을 갱신한다. 1번(템플릿 참조) 아래에 하위 항목으로 기록 규칙을 둔다. `## 종합 의견` 첫 줄은 `--verdict` 출력을 그대로 적고 판정을 뺀 종합 판단·후속 액션은 `종합 의견 펼치기` 접기로 내린다는 규칙, 상태·등급 표기 위치 4곳(요약 1단계·2단계 줄은 `--compliance`·`--status` 출력 + ` · ` + 텍스트 건수, 1단계 표 판정 열은 값 하나를 넘긴 `--compliance` 출력, 발견 사항 표 위험도 열과 상세 분석 위험도 필드는 매트릭스 헬퍼 출력)에 헬퍼 출력을 그대로 쓴다는 규칙, 요약 건수와 카테고리 표 건수는 텍스트 등급만 쓴다는 규칙, `#### F-<번호>: <제목>` 헤더는 바꾸지 않는다는 규칙. 3번(요약 보고)에 대화창 보고가 같은 판정 한 줄로 시작하고 그 밖의 대화창 형식은 정하지 않는다는 문장을 넣는다. 상태·판정 산출은 아래 소절을 참조한다고 적는다.
  2. 번호 목록 뒤에 `#### 상태 산출`을 신설한다. 1단계 상태는 항목 판정 값을 그대로 상태 값으로 쓰며 서열은 미충족(FAIL) > 부분 충족(PARTIAL) > 충족(PASS)이고, 판정 불가(N/A)는 상태를 올리지 않아 항목 전부가 판정 불가일 때만 판정 불가(N/A)가 나온다는 규칙과 헬퍼 사용 예 2개(`"$classify" --compliance '부분 충족(PARTIAL)'   # → 🟡 부분 충족(PARTIAL) (항목 라벨)`, `"$classify" --compliance '충족(PASS)' '부분 충족(PARTIAL)' '충족(PASS)'   # → 🟡 부분 충족(PARTIAL) (1단계 상태)`), 인자 0개는 사용오류라는 문장을 둔다. 2단계 상태는 표 `| 최고 위험도 | 상태 |`(데이터 3행: 높음(HIGH) → 보완 필요(FAIL), 중간(MEDIUM) → 주의(WARN), 낮음(LOW) 이하 또는 발견 없음 → 통과(PASS))와 헬퍼 사용 예 2개(`"$classify" --status '🟡 중간(MEDIUM)' '낮음(LOW)'   # → 🟡 주의(WARN)`, `"$classify" --status   # 발견 없음 → 🟢 통과(PASS)`), 낮음(LOW)·정보(INFO)는 상태를 낮추지 않고 건수는 요약에 드러난다는 문장을 둔다. 감사인이 상태를 직접 고르지 않는다는 문장을 소절 머리에 둔다.
  3. 이어서 `#### 판정 산출`을 신설한다. 판정은 감사인이 고르지 않고 1단계 상태와 2단계 상태의 최고값에서 산출한다는 규칙, 판정 표(헤더 `| 최고 상태 | 판정 |`, 데이터 3행: `미충족(FAIL) · 보완 필요(FAIL)` → 부적합(FAIL), `부분 충족(PARTIAL) · 주의(WARN)` → 조건부 적합(CONDITIONAL), `충족(PASS) · 판정 불가(N/A) · 통과(PASS)` → 적합(PASS)), 판정 불가(N/A)는 판정에 영향을 주지 않는다는 문장, 판정 3종의 의미(부적합은 스펙 미충족 또는 보정 필수 발견이 있음, 조건부 적합은 `--response` 승인 게이트에서 사용자 판단이 필요한 항목이 있음, 적합은 보정 대상이 없어 Task N을 닫을 수 있으며 낮음(LOW)·정보(INFO)는 원장 이관·기록), 판정은 우선순위 신호이고 실제 처리는 현행대로 issue-work `--response`의 항목별 승인이 정한다는 문장, 헬퍼 사용 예(`"$classify" --verdict '🟡 부분 충족(PARTIAL)' '🟡 주의(WARN)'   # → 🟡 조건부 적합(CONDITIONAL)`, 위치 인자 2개·순서 무관)를 둔다.
  4. 같은 소절 끝에 `**이모지 대응표**` 볼드 행을 앵커로 표(`| 구분 | 값 | 이모지 |`)를 둔다. 데이터 14행: 적합성 4(🟢 충족(PASS) / 🔴 미충족(FAIL) / 🟡 부분 충족(PARTIAL) / ⚪ 판정 불가(N/A)), 등급 4(🔴 높음(HIGH) / 🟡 중간(MEDIUM) / 🟢 낮음(LOW) / ⚪ 정보(INFO)), 상태 3(🔴 보완 필요(FAIL) / 🟡 주의(WARN) / 🟢 통과(PASS)), 판정 3(🔴 부적합(FAIL) / 🟡 조건부 적합(CONDITIONAL) / 🟢 적합(PASS)). 표 아래에 적는다. 이모지는 헬퍼가 출력 앞에 붙이며 감사인이 손으로 붙이지 않는다, 항목 색은 그 항목이 만드는 상태 색과 같다, 부분 충족(PARTIAL)은 🟡이며 `--response` 순서 게이트가 미충족과 부분 충족을 함께 선처리하는 것은 처리 순서 규칙이라 색과 무관하다, 정보(INFO)·판정 불가(N/A)는 상태를 올리지 않아 무색(⚪)이다, 요약 건수와 카테고리 표 건수는 텍스트 등급만 쓴다, 값 모드 4종(`--treatment`·`--compliance`·`--status`·`--verdict`)은 대응표 접두 4종이 붙은 값과 붙지 않은 값을 모두 받고 그 밖의 접두는 종료 코드 2다, 위험도 매트릭스·등급별 처리·2단계 상태·판정 표의 셀 값은 텍스트로 유지해 이모지의 SSoT를 이 대응표 한 곳에 둔다.
  5. `#### 위험도 분류`의 헬퍼 예시 출력 주석을 `# → 🟡 중간(MEDIUM)`으로 바꾸고, SSoT 문장("위 표가 SSoT이며…")에 "판정 산출"의 이모지 대응표를 포함시킨다. `#### 등급별 기본 처리 기준`의 `--treatment` 예시를 접두 입력(`"$classify" --treatment '🟢 낮음(LOW)'`)으로 바꾸고 출력은 처리 문구 그대로임을 적는다.
  6. `## 산출물 접기 기준`에 종합 의견 접기 해석을 추가한다. 판정 한 줄을 뺀 종합 판단·후속 액션은 접으며, 판정 한 줄이 밖에 있고 발견 제목·권장 조치가 본문에 남으므로 "액션 아이템 접기 금지"와 충돌하지 않는다.
  7. `## 출력 요약 형식`의 코드 블록에서 `## Issue #<번호> 감사 결과 요약` 다음 줄에 `<판정>` 한 줄을 두고, 판정은 `--verdict` 출력 그대로라는 안내를 블록 앞 문장에 넣는다. 그 밖은 현행을 유지한다.
- **완료 기준**:
  - [D] 상태 산출·판정 산출 소절 배치, 2단계 상태 표 3행, 판정 표 3행, 대응표 14행(값 14종 상이, 판정 표 값 전부 포함), 이모지 포함 예시 출력, 출력 요약 형식 첫 줄 판정이 실재한다. 이 표가 Task 2 헬퍼 매핑과 Task 4 러너 기대값의 원천이라, 표가 없거나 행 수가 다르면 Task 4 러너의 대응표 추출이 실패로 멈춘다  (검증: spec DoD R6 `[D]` 명령 재실행)
