## Tasks

> AI가 순서대로 실행할 작업 단위를 정의합니다.
> **작성 원칙**: 구현자에게 이 문서 외 컨텍스트가 없다고 가정하고, Task별 완료 기준을 결정적으로 씁니다.
> 각 작업은 독립적으로 검증 가능해야 하며, 완료 기준은 **항목별 리스트로 쪼개 레벨 태그 + 검증 수단**을 적습니다.
> 명령으로 환원이 어려운 항목만 판정 주체(다른 AI / 사람)를 적고 강등 사유를 남깁니다.
>
> **대상 요구사항 필드** — 일반 Task에는 `- **대상 요구사항**: R<n>` 필드를 `목표` 다음 행에 두어
> 이 Task가 spec의 어느 요구사항을 구현하는지 밝힙니다. 여러 개면 `R<n>, R<m>`로 나열합니다.
> 고정 Task(Task 0·Task N)는 특정 요구사항에 속하지 않으므로 이 필드를 두지 않습니다.
>
> **완료 기준 형식** — 본문(접기 금지)에는 레벨 태그 + 무엇이 보장되는지 한 문장(+ 강등 사유)만 두고,
> 검증 명령·테스트케이스·기대 출력·명령 설계 주의점은 접기로 내립니다. 접기 제목에 기대 출력을 함께 적습니다
> (기본형: "검증 명령 — 출력 0건이면 통과"). 접을 상세가 없는 항목은 접기 없이 본문 한 줄로 둡니다.
> 다른 게이트의 선행 조건이 되는 항목은 의존 관계와 **선행 조건이 무너졌을 때의 결과**를 본문 문장에 남기고, 메커니즘만 접기에 둡니다.
> 첫 고정 Task(Task 0 구현 시작 게이트)와 마지막 고정 Task(교차모델 issue-audit)는 삭제하지 말고 그대로 둡니다.
>
> **테스트 배치** — 구현 테스트(단위·회귀)는 그 기능을 만드는 Task 안에 둡니다. 테스트 작성(fixture·기대 출력)을
> `작업 내용`의 단계로 넣고 테스트 파일을 그 Task의 산출물로 삼으며, `완료 기준`에는 "이 Task의 테스트 0 실패" `[D]`를 둡니다.
> 별도 테스트 Task는 fixture 일괄 갱신처럼 테스트 자체가 작업 대상일 때만 둡니다.
> 전체 테스트 통과는 spec `### 공통`의 회귀 방지 항목으로 유지합니다.
> `.ai/10_rules/testing-principles-local.md`가 있으면 테스트 `[D]`의 러너 호출·출력 판독·실행 셸은 그 파일의 테스트 층 표를 따릅니다.
>
> **검증 레벨** — 낮을수록 좋다(자동 검증에 가까움). 기본은 L1, 한 레벨 내릴 때마다 강등 사유를 함께 적는다.
>
> - `[D]`  L1 결정적   — 명령이 합/불을 판정, 사람 판단 없음
> - `[QD]` L2 준결정적 — 다른 AI·기준 체크리스트가 채점
> - `[ND]` L3 비결정적 — 사람이 직접 읽고 판단
>
> **문서를 대상으로 검증할 때는 문구가 아니라 행 구조를 셉니다**. 같은 문구가 주석·안내문에도 등장하므로
> `grep -c '<문구>'`는 실제 구조가 없어도 통과합니다. 헤더는 `^## `, Task는 `^### Task `,
> 필드는 `^- \*\*…\*\*:`로 앵커를 고정하고, 명령은 작업 디렉토리에 의존하지 않게 repo 루트 기준 경로로 적습니다.
> **검증 명령 보정은 반례 격추가 아니라 불변식 전수 명세로 합니다**. 지적된 변형 하나만 막으면 이웃 변형이
> 다음 감사에서 재발하므로, 기대 구조를 열거하고 "그 외 0건"까지 판정에 넣습니다.
>
> **이 이슈의 완료 기준 작성 방식** — 결과 판정은 spec 완료의 정의가 맡고, 아래 Task 완료 기준은 해당 R 그룹의 `[D]` 명령이 통과했는지(진행)만 판정합니다.
> 이 이슈 R4가 skill에 넣을 규칙("plan Task 완료 기준은 진행만 판정하고 spec에 없는 결과를 더하지 않는다")을 먼저 적용합니다.
> 러너 케이스는 기존 절과 같은 형식(`check_<이름>` 함수 + `drop_literal` 등으로 만든 사본 + `assert_structure`)으로 쓰고, 케이스 설명은 spec 전제 3의 라벨로 시작하며 `통과`·`격추` 중 한 낱말로 끝냅니다.

### Task 2: `--create` 옵션

- [x] 완료
- **목표**: 대화에서 정한 작업을 승인 게이트를 거쳐 이슈로 등록하고, 이어서 시작할지 묻는 흐름을 만든다.
- **대상 요구사항**: R2, R3, R11
- **작업 내용**:
  1. `issue-work/SKILL.md` `## 옵션`의 `### \`--workflow-only\`` 앞에 `### \`--create\`` 절을 둔다. `용도`·`경계`·`동작` 항목은 `--clear` 절의 형식을 따르고, `동작` 아래 단계는 `  <번호>. **<이름>**:` 형식으로 6개를 둔다.
     - **초안 작성**: 대화에서 정한 내용을 이 skill 디렉토리의 `templates/issue-body-template.md` 구조로 `.ai/99_workspace/issue-create-body.md`에 1회 쓴다. 디렉토리가 없으면 만들고, 파일이 이미 있으면 덮어쓸지 묻는다. 수정 요청은 같은 파일을 갱신한다.
     - **요약 제시**: 파일 경로, 제목 전문, 목표 한 줄, 포함·제외 목록, 완료의 정의 항목 수, 검토 필요를 제시하고 전문은 대화에 출력하지 않는다(ADR 0013). 같은 단계에 분할 권고 조항(spec R3 첫 항목 검증 문구 4개)과, 템플릿 기준으로 AC가 대응하지 않는 포함 항목을 보고하는 조항(spec R3 둘째 항목 문구 `AC가 대응하지 않는 포함 항목`)을 둔다. 보고할 항목이 없으면 `없음`을 적고, AC를 더할지는 사용자가 정한다.
     - **승인**: 승인 대상은 제목, 초안 파일, 대상 저장소다. 문장 "승인 전에는 `gh issue create`를 실행하지 않는다"를 둔다. 거절하면 파일을 남기고 경로를 안내한 뒤 끝낸다.
     - **등록**: 대상 저장소 확정 규칙(spec 전제 5)과 명령 `gh issue create --repo '<대상 저장소>' --title '<제목>' --body-file '.ai/99_workspace/issue-create-body.md'`를 둔다. 동적 값 인용 규칙(spec 전제 4)과 MCP 폴백 시 owner·repo 필수 입력을 적는다. 실패하면 다시 시도하지 않고 오류를 보고하며 파일은 남긴다.
     - **번호 보고**: 만든 이슈 번호와 URL을 보고한다.
     - **시작 질의**: "새 이슈 시작 시"를 진행할지 묻고, 승인하면 그 절차 1단계부터 진행한다.
     - `경계`에 문장 "active 작업 파일을 옮기거나 지우지 않는다"를 두고, `--create`가 등록까지만 하며 시작은 시작 질의 승인 뒤의 "새 이슈 시작 시"가 맡는다고 적는다.
  2. `issue-work/tests/run-tests.sh`에 `# --- --create 절 (issue #130)` 절을 더한다. 실제 SKILL.md 통과 1건과 격추 사본(절 삭제, 단계 순서 바꿈, 단계 추가, 승인 전 미실행 문장 삭제, active 무변경 문장 삭제, `--repo` 없는 명령 행, 두 번째 작업 파일 경로 추가, 분할 권고 문구 삭제, AC 미대응 포함 항목 보고 문구 삭제, 그 문구를 승인 단계로 이동, 절을 `## 옵션` 앞으로 이동)을 둔다.
- **완료 기준**:
  - [D] spec 완료의 정의 `### R2`·`### R3`의 `[D]` 항목 검증 명령이 모두 무출력이다 (러너 `--create 절:` 케이스 포함)  (검증: spec 접기의 명령 재실행)

    <details>
    <summary>검증 명령 — repo 루트에서 실행, 출력 0이면 통과</summary>

    ```bash
    S=.ai/90_issues/active/issue-0130/issue-0130-summary.md
    awk '
      /^### Task / { if (o && !n && d && (t != 1 || m != 1)) b++; o = 1; d = 0; t = 0; m = 0; n = ($0 ~ /^### Task N/) }
      o && /^- \*\*결과\*\*: (완료|부분 완료)[[:space:]]*$/ { d = 1 }
      o && /^- \*\*수행 모델\*\*:/ { t++; if ($0 ~ /^- \*\*수행 모델\*\*: [^-[:space:]]/) m++ }
      END { if (o && !n && d && (t != 1 || m != 1)) b++; print b+0 }
    ' "$S"
    ```

    - 설계 주의: 리터럴 `-`만 거부하면 빈 값·행 누락·중복이 통과하므로 "없음"의 세 형태와 중복을 전부 실패로 센다.
