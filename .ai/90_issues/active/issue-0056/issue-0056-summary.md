한 발견이 여러 Task 산출물에 걸쳐도 가장 직접 수정된 주 Task 하나에만 귀속한다 —
`audit 발견`·`보정 반영` 모두 그 주 Task에서 1회만 세고 관련된 다른 Task에는 세지 않는다.
Task 축에서도 이슈 단위 합계가 중복으로 부풀지 않게 하기 위함이다(아래 회차 축 중복 제외와 같은 취지).

1건으로 세고(중복 제외), 새 회차 값으로 덮어쓰지 않는다. 보정률 사후 집계의 분모·분자가 회차 반복으로 부풀지 않게 하기 위함이다.

합계에서 조용히 빠지고, 전부 `-`면 합계 자체가 빈 문자열이 된다. `-` 허용은 비수치 필드(`수행 모델`)에만 둔다.

### Task 1: 판단 로직·제약 검증 개편 — 구현 난이도 평가 도입, 캐시 우선 규칙 제거

- **결과**: 완료
- **수행 모델**: Anthropic, Claude Opus 5 (claude-opus-5)
- **audit 발견**: 1건
- **보정 반영**: 1건
- **재시도**: 0회
- **수행 내용 요약**: `issue-model-triage/SKILL.md`의 `## 판단 로직`을 두 축(설계 판단 필요 여부 → 플랜 / 구현 난이도 → 구현) 구조로 개편. (1) 절 도입부에 두 축의 독립성을 명시, (2) `### 분류 기준`을 플랜 배정 전용으로 좁히고 구현 배정 분리를 안내, (3) `### 구현 난이도 평가` 절 신설 — 신호 3종(변경 범위·맥락 의존도·로직 복잡도) 표와 등급 3단계(낮음(LOW)/보통(MEDIUM)/높음(HIGH))별 배정 표, 최소 역량 배정 원칙·판정 보류·하드코딩 금지 승계, (4) `### 제약 검증`의 플랜·구현 항목을 "제약 없음"으로 교체하고 캐시 근거를 삭제. 검증 역할 제약(다른 모델 + 다른 벤더)은 그대로 유지.
- **특이 사항**: 역량 등급화 안내문의 등급 표기를 "최상위/하위"에서 "최상위/중위/하위"로 확장 — 난이도 3단계에 대응하는 중위 등급이 필요했다.
- **audit 보정 (1차, `--response`)**: 1단계 발견 1건 반영(F-3 제외, 요구사항 R1·DoD D4 부분 충족 근거이자 2단계 F-1, 같은 결함이라 1단계로 병합해 1건 집계, 중간(MEDIUM)) — 배정 원칙이 후보 풀 안의 상대 등급만 다뤄 "후보 전체가 요구 난이도에 미달"인 절대 판정 경로가 없었다. `### 구현 난이도 평가` 배정 원칙에 "후보 전체가 난이도를 감당하지 못하면 상대적 최상위를 억지 배정하지 않고 부족한 조건을 안내"와 등급화(상대 순위) ≠ 감당 여부(별개 판정) 구분을 추가했다. audit 권장의 실패 경로 절 신설 대신 원칙 한 줄 + 출력 분기 한 항목의 경량안을 택했다(경량 스킬 취지). 출력 분기 추가는 Task 2 산출물이지만 근본 수정이 배정 원칙이라 이 Task에 귀속한다.

### Task 2: 출력·예시 정합 갱신

- **결과**: 완료
- **수행 모델**: Anthropic, Claude Opus 5 (claude-opus-5)
- **audit 발견**: 1건
- **보정 반영**: 1건
- **재시도**: 0회
- **수행 내용 요약**: `## 출력`의 분류·근거 요약 항목에 구현 난이도 등급·근거 신호를 함께 밝히도록 갱신하고, 판정 보류 항목의 근거 절을 `### 분류 기준`·`### 구현 난이도 평가` 양쪽으로 확장(한 축만 가려도 표 전체 보류). 예시 안내문의 흐름을 "분류 → 구현 난이도 평가 → 제약 검증"으로 교체. 예시 1은 이슈 소재를 재시도·백오프 정책으로 바꿔 설계 판단 필요 + 난이도 보통(MEDIUM)으로 조정, 플랜(최상위)과 구현(중위)이 갈리는 모습을 표에 반영. 예시 3은 난이도 낮음(LOW) 판정을 추가하고 구현 행 선정 사유를 난이도 기준으로 교체. 예시 4는 난이도 축 보류를 함께 서술. 예시 개수는 4개 유지(추가·삭제 없음).
- **특이 사항**: 예시 1의 이슈 소재를 바꾼 이유는 DoD의 `캐시` 문자열 grep 때문 — 기존 소재("새 캐시 계층")가 규칙 잔존과 무관한 예시 서술인데도 잔존 0건 판정에 걸렸다. 예시 1에서 GPT-5.6을 중위로 등급화해 후보 3개가 최상위·중위·하위를 모두 채우게 했다 — 기존 문서가 명시한 등급 사실(Fable 5=최상위, Opus 4.8=하위)과 충돌하지 않는 유일한 배치이며, 예시 안내문이 고정 등급표가 아님을 이미 밝히고 있다. 결과적으로 예시 1은 플랜·구현의 벤더가 달라도 무방함(벤더 제약 삭제)을 함께 보여준다.
- **audit 보정 (1차, `--response`)**: 1단계 발견 1건 반영(요구사항 R3·DoD D5 부분 충족 근거이자 2단계 F-2, 같은 결함이라 1단계로 병합해 1건 집계, 중간(MEDIUM)) — 예시 2가 `## 입력`이 요구한 이슈 내용 없이 분류·난이도 평가를 생략하고 제약 실패로 종료하는데, 그 단축 흐름의 근거가 문서에 없었다. audit 권장 (a)안(예시 2에 이슈 내용·두 축 판정 추가) 대신 (b)안을 택했다 — 후보 벤더 단일은 이슈 내용과 무관하게 판정되므로 불필요한 판정을 강요하지 않기 위함이다. `### 제약 검증`에 "사전 판정 가능" 항목을 추가하고 예시 2에 그 근거를 한 줄 달았다.
