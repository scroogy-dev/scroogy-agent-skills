### Task 2: 라이선스·개인 저작물 고지 옵션 정책 정리

- [ ] 완료
- **목표**: 라이선스 표시와 개인 저작물 고지를 두 개의 독립 옵션으로 다루기 위한 분기와 표기 방식을 정리한다. 양쪽 모두 "표시하지 않음"이 정상 경로다.
- **배경**:
  - 본 repo와 사용자의 다른 공개 repo는 README 말미에 라이선스 + 개인 저작물 고지 + Copyright를 둔다.
  - `ai-onboarding` repo는 "개인 저작물·본인만 사용 가능"을 원했지만 표기를 몰라 블록을 비워둔 상태다.
  - 이 스킬은 회사 업무에서도 쓰일 수 있는데, 회사 업무는 README에 라이선스 표시를 두지 않는 것이 관례여서 **양쪽 모두 "표시하지 않음"이 자연스러운 선택지**여야 한다.
- **작업 내용**:
  1. **라이선스 표시 옵션** 세 분기를 정의한다.
     - (a) **오픈소스**: 본 repo(Apache 2.0)를 기준 사례로 — LICENSE/NOTICE/LICENSE-HEADER.txt 연결, README 라이선스 섹션 표준 문구.
     - (b) **개인 저작물·비공개**: 후보 예 `All Rights Reserved` (LICENSE 파일 없이 README에만 명시), `UNLICENSED` (npm 진영 관례), 짧은 자체 문구. 각 후보의 의미·관행을 한 줄로 정리하고 권장 표기 1~2개를 정한다.
     - (c) **표시하지 않음 (none)**: 회사 업무 등 관례적으로 미표시인 경우. README에서 라이선스 섹션 자체를 생략한다.
  2. **개인 저작물 고지 옵션**을 라이선스와 별개의 토글로 정의한다 (포함 / 미포함). 회사 업무 컨텍스트에서는 미포함을 권장하는 안내를 둔다.
  3. 라이선스 분기와 개인 저작물 고지 토글의 조합표를 정리한다 (각 조합에서 README 말미 블록이 어떻게 구성되는지: 섹션 유무, 포함 라인).
  4. `init` 모드에서 두 항목을 사용자에게 물을 때의 질문 문구 초안을 작성한다.
- **완료 기준**: 옵션 세 분기와 별도 토글, 조합표, 질문 문구 초안이 summary에 기록되어 후속 Task에서 그대로 활용 가능하다.

### Task 3: 모드·프로파일 정의 (`--mode` / `--profile`)

- [ ] 완료
- **목표**: 스킬의 두 동작 모드와 프로파일 인자를 정의하고, 모드/프로파일 선택 규칙과 모드별 대화형 질문 흐름을 확정한다.
- **작업 내용**:
  1. **`--mode=init|update`**:
     - **`init`**: 새 README.md를 만든다. 입력=프로젝트 디렉토리. 출력=신규 `README.md`. 이미 README가 있으면 사용자 확인 후 덮어쓸지 결정.
     - **`update`**: 기존 README.md를 프로젝트 재분석 결과로 갱신. 사용자 작성 콘텐츠 보존 우선. 라이선스·개인 저작물 고지 블록은 **있음/없음·분기를 그대로 유지** (회사에서 일부러 비워둔 케이스 보호). 변경은 사용자 명시 요청 시에만 적용.
     - 선택 규칙: 인자 우선, 미지정 시 `README.md` 존재 여부로 기본 추정(없으면 `init`, 있으면 `update`). 추정과 사용자 의도가 어긋날 가능성이 있으면 1회 확인.
  2. **`--profile=individual|business`** (모드와 독립):
     - **`business`** (회사 업무 컨텍스트): 라이선스 표시 기본값 = "표시하지 않음(none)", 개인 저작물 고지 기본값 = "미포함".
     - **`individual`** (개인 작업 컨텍스트): 라이선스 표시 기본값 = "오픈소스 또는 개인 저작물·비공개 중 사용자 선택", 개인 저작물 고지 기본값 = "포함".
     - 미지정 시: `init`에서는 두 질문을 그대로 진행 (기본값 추정 없이 묻는다). `update`에서는 사용되지 않음 (보존 우선).
     - 프로파일은 어디까지나 **기본값 프리셋**이며, 사용자는 개별 질문에서 다른 값을 선택할 수 있다.
  3. **`init` 모드 대화형 질문 흐름**:
     - ① 라이선스 표시 (오픈소스 / 개인 저작물·비공개 / 표시하지 않음) — 프로파일 기본값을 제시하고 확인 받음.
     - ② 개인 저작물 고지 (포함 / 미포함) — 프로파일 기본값을 제시하고 확인 받음.
     - 두 항목 모두 "표시하지 않음 / 미포함"이 정상 경로임을 안내.
  4. **`update` 모드 흐름**: 기존 README 분석 → 사용자 콘텐츠 보존 → 프로젝트 변화 반영 → 라이선스·고지 블록은 기본 보존. `--profile`이 들어와도 기존 블록을 덮어쓰지 않음.
  5. 각 흐름을 단계 목록으로 작성한다 (Task 5 SKILL.md 본문 작성에 그대로 옮길 수 있는 형태).
- **완료 기준**: 두 모드 + 프로파일의 입력·출력·대화형 질문·기본값 프리셋·선택 규칙이 summary에 정리되어 있으며, Task 5에서 그대로 SKILL.md에 반영 가능하다.

  8. **라이선스·개인 저작물 고지 옵션 가이드**: Task 2의 분기/조합표/권장 표기를 본문에 정리한다.
  9. 다른 스킬과의 관계(`ai-workspace`, `code-map` 등)에서 참조 가능한 항목만 간결히 기재한다.
