# ADR: 테스트 관점 구분과 Task 단위 테스트 배치

## 결정

- 테스트를 두 관점으로 나눈다. 계획 관점 테스트는 spec 완료의 정의 `[D]`가 맡는 인수 테스트이며 외부 경계(명령 인자·종료 코드·출력 행·파일 내용)를 검증한다. 구현 관점 테스트(단위·회귀)는 그 기능을 만드는 plan Task가 맡는다.
- 외부 경계가 spec에 고정되는 작업은 DoD `[D]`를 테스트 러너 호출로 적을 수 있다. 경계가 구현 중에 정해지는 작업은 명령 수준으로 둔다.
- 구현 테스트는 각 Task의 `작업 내용`과 `완료 기준`에 둔다. `작업 내용`에는 테스트 작성(fixture·기대 출력) 단계를 넣고 테스트 파일을 그 Task의 산출물로 삼으며, `완료 기준`에는 "이 Task의 테스트 0 실패" `[D]`를 둔다.
  - 별도 테스트 Task는 fixture 일괄 갱신처럼 테스트 자체가 작업 대상일 때만 둔다.
  - 전체 테스트 통과는 spec `### 공통` 회귀 방지 항목으로 유지한다.
- Task의 테스트 `[D]`는 러너를 1회 실행해 종료 코드 0과 출력의 케이스 행(정상 통과·반례 격추 한 쌍 이상)을 함께 본다. 케이스 행은 `통과`·`격추` 낱말별로 따로 센다. 러너만 실행하는 명령은 케이스를 넣기 전에도 통과하는 가짜 `[D]`라 쓰지 않는다.
- issue-audit 최종 감사 2단계 관점 5 "누락된 검증"은 기능을 바꾸는 구현 Task마다 테스트 `[D]`가 있는지와 그 테스트가 Task의 변경을 덮는지로 판정한다. 덮는다는 것은 변경을 되돌리면 실패하는 케이스가 있다는 뜻이다. 공통 전체 테스트 통과만 있는 Task는 Task별 테스트가 없는 것으로 본다. 카테고리 표의 "테스트" 정의 문구는 바꾸지 않는다.
- 최종 감사 1단계 DoD 대조는 `[D]` 명령을 구현 후 트리에서 실제로 실행해 판정 근거로 삼는다. 구현 전 실행으로 가짜 `[D]`를 거르는 일은 `--plan` 관점 2가 그대로 맡는다.
- ADR 0003의 검증 레벨·완료 기준 접기 형식·결정화 판단은 그대로 둔다. 이 ADR은 테스트를 어느 문서·Task에 두는지와 감사가 그 배치를 어떻게 판정하는지만 정한다.

## 근거

<details>
<summary>상세 펼치기</summary>

- issue-work는 완료 기준을 결정적 검증으로 내리라고만 하고 구현의 일부인 테스트 작성은 지시하지 않았다. 이 repo에서 새 헬퍼에 테스트가 따라붙은 것은 `architecture.md` 결정화 체크리스트와 ADR 0001 때문이라, 다른 repo에서 issue-work를 쓰면 작동하지 않는다.
- 계획 단계에서는 구현 내부(함수 경계·모듈 구조·구현 중 드러나는 엣지케이스)를 알 수 없다. 계획 단계에 쓸 수 있는 것은 spec이 정한 외부 경계의 입력과 기대 출력뿐이고, DoD `[D]`가 이미 그 역할을 한다. `--plan` 관점 2가 구현 전에 실패를 확인하는 것은 인수 테스트의 미통과 상태 확인과 같다.
- 별도 테스트 Task 방식(#94·#102)은 앞 Task의 완료 기준이 뒤 Task에 의존해 "각 작업은 독립적으로 검증 가능해야 한다"는 plan 원칙과 어긋났다. 구현 Task를 체크한 시점에 그 구현이 검증되지 않은 상태로 남고, 구현 중 발견한 엣지케이스가 테스트로 남지 않았다. Task별 배치(#66·#108)는 이 문제가 없었다.
- 최종 감사의 관점 5와 "테스트" 카테고리에는 판단 기준이 없었고, 스펙에 결속되지 않은 발견은 1단계 판정을 낮추지 못한다. plan의 Task별 테스트 `[D]`를 기준으로 삼으면 감사인이 plan과 테스트 파일만 읽고 판정할 수 있다.
- 최종 감사에는 DoD `[D]` 실행 지시가 없어 체크박스나 summary 기록만 보고 충족으로 판정할 여지가 있었다. 이슈 본문은 이 지시를 둘지 검토로 남겼고, #112 요구사항 승인에서 포함으로 확정했다.
- 카테고리 표는 git-review 원본의 사본이라([ADR 0002](./0002-skill-independence-intentional-duplication.md)·[ADR 0014](./0014-inverted-pyramid-and-verdict-derivation.md)) 정의 문구를 바꾸면 양쪽 동기화 의무가 생긴다. 판단 기준은 issue-audit 절차 쪽에만 둔다.
- ADR 0003은 레벨 체계와 결정화 판단을 정한 결정이고 테스트의 관점 구분·배치는 다루지 않았다. 0003의 결정이 바뀌지 않아 보강·대체 대신 별도 ADR로 남겼다.

</details>

## 대안

<details>
<summary>상세 펼치기</summary>

- 테스트 작성 Task를 고정 블록으로 추가: Task 독립 검증 원칙과 어긋나고 테스트가 구현을 사후 추인하는 형태가 되어 기각.
- DoD 전체를 테스트 파일로 결정화: 경계가 구현 중 정해지는 작업에서는 계획 단계에 쓸 수 없어, 경계가 spec에 고정된 경우의 러너 호출 허용으로 좁혔다.
- 카테고리 표 "테스트" 정의에 기준 추가: git-review 동기화 의무가 생겨 기각.
- ADR 0003 보강: 레벨·형식 결정과 배치 결정이 섞이고 대안 비교를 남길 자리가 없어 배제.
- 가짜 `[D]` 사전 판별 헬퍼 결정화(K-0009)와 ai-workspace dev 프로파일의 테스트 작성 가이드: 이슈 #112 범위에서 제외(보류).

</details>
