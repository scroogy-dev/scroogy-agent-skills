# ADR: 평가 결과의 역피라미드 구조와 판정·상태 산출

## 결정

- git-review 결과와 issue-audit 리포트는 "판정 한 줄 → 최종 의견/종합 의견(접기) → 요약 대시보드 → 상세" 역피라미드다.
- 테크 리뷰 카테고리 7종(기능, 아키텍처, 버그, 보안, 코드품질, 성능, 테스트)의 원본은 git-review이고 issue-audit이 복사·동기화한다. 카테고리 검증은 상호 독립(순서 무관)이며 실행 방식(서브에이전트 병렬 등)은 스킬에 지시하지 않는다.
- 상태는 재량 없이 산출한다. 카테고리·리뷰 상태는 최고 위험도로(높음→보완 필요(FAIL), 중간→주의(WARN), 낮음 이하·발견 없음→통과(PASS)). issue-audit 1단계 상태는 항목 판정의 최고값(미충족 > 부분 충족 > 충족, 판정 불가는 올리지 않음).
- 판정은 두 상태의 최고값이다. git-review는 승인(APPROVE) / 조건부 승인(CONDITIONAL) / 변경 요청(REQUEST CHANGES), issue-audit은 적합(PASS) / 조건부 적합(CONDITIONAL) / 부적합(FAIL). 판정은 우선순위 신호이며 보정 여부는 작성자·`--response` 승인이 정한다. Self 리뷰의 승인은 "제출 가능"을 뜻한다.
- 신호등 이모지(빨강·노랑·초록·흰색)는 헬퍼 `classify-risk.sh`가 출력하며 손으로 붙이지 않는다. 이모지 리터럴은 헬퍼의 두 함수와 SKILL.md 대응표에만 두고, 러너는 표에서 기대값을 합성한다. 값 입력 모드는 이모지 접두가 붙은 값과 안 붙은 값을 모두 받는다.
- 이모지 표기 위치는 요약 상태 줄·표 상태(판정) 열·소절 제목이며, 건수 열은 텍스트 등급만 쓴다. 위험도 매트릭스·등급별 처리 표 셀은 텍스트로 유지한다.
- 리뷰 포인트는 볼드 한 줄 `**<이모지> <등급> <제목>**` + 일반체 지적·권장 조치, 근거·축 판정은 항목별 접기다. 항목은 문단으로 둔다(리스트 안 접기는 렌더링이 깨진다). 카테고리 단위 접기는 없앴다.
- 기등재 참조·이전 발견 추적 표는 접되 잔여·재제기 건수와 번호를 요약에 노출한다.
- 이모지 정책: SKILL.md 설명 본문에는 쓰지 않고 산출물 값 명세에만 쓴다.

## 근거

<details>
<summary>상세 펼치기</summary>

- 결론이 문서 맨 아래에 있어 상세를 지나야 종합 판단을 알 수 있었다. writing-principles의 "중요한 것 먼저"가 있어도 "템플릿 우선" 규칙 때문에 템플릿이 원칙을 따라가지 못했다 (#75, #76).
- 테크 리뷰 절차가 2단계로 굵어 버그·보안·성능 관점이 드러나지 않고 카테고리별 건수·상태를 알 수 없었다. 기존 분류 축(엣지케이스·암묵적 가정 등)은 "어떻게 찾았나"의 관점 축이라 영역 집계를 대신하지 못했다.
- 리뷰마다 판정이 갈리면 신호로 기능하지 못한다. 위험도 매트릭스와 같은 철학으로 상태를 산출한다.
- #75 역피라미드 도입 후에도 최종 의견이 3문장 서술이라 승인 여부가 한눈에 안 읽혔고, 상태·등급이 문자열뿐이라 심각도가 구분되지 않았으며, 근거가 카테고리 접기 하나에 뭉쳐 특정 항목만 펼칠 수 없었다 (#96).
- 리스트 안 접기는 GitHub·IDE 미리보기 렌더링이 깨진다.
- 판정 줄을 뺀 최종 의견을 접어도 액션 아이템의 실체인 리뷰 포인트 제목이 본문에 보이므로 "액션 아이템 접기 금지"와 충돌하지 않는 것으로 해석했다.
- 이모지 대응표를 매트릭스와 분리한 것은 issue-audit과 공유하는 매트릭스(원장 K-0002 재검토 조건)를 건드리지 않기 위함이다.
- 헬퍼의 모드 혼용 검사가 축 옵션 값만 봐서 빈 축 값이 우회했다. 등장 여부 플래그로 바꾸고 사용오류는 종료 코드 2와 빈 표준 출력을 함께 보장한다 (#96 F-1, #98).
- 대시보드 섹션명은 `## 요약`으로 통일했고, 상단 종합 판단 명칭(`최종 의견` / `종합 의견`)은 스킬별 현행을 유지했다.

</details>

## 대안

<details>
<summary>상세 펼치기</summary>

- 카테고리 상태를 리뷰어가 직접 선택: 재량 배제 원칙으로 기각.
- 카테고리 7종 확장 금지(PR #77 리뷰 제안): 확장 여지를 없애면 프로젝트 고유 관점을 임의 카테고리에 끼워 넣어 집계가 흐려져 채택하지 않았다. 확장 시 동기화 비용은 주석으로 경고한다.
- 리뷰 포인트 식별자(R-1 등) 부여, 요약 카테고리 표 상태 열, `#### F-` 헤더 이모지: 범위 밖으로 미뤘다.

</details>
