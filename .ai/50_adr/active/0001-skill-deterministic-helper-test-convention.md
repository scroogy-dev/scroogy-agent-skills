# ADR: 스킬 결정적 헬퍼의 테스트 동일 위치 배치 규칙

## 결정

스킬에 결정적 헬퍼(`scripts/`)가 도입될 때 다음 규칙을 따른다.

- **헬퍼 위치**: 헬퍼 스크립트는 `<skill>/scripts/`에 둔다.
- **테스트 위치**: 테스트는 `<skill>/tests/`에 함께 둔다. 테스트 데이터는 별도 최상위 디렉토리를 만들지 않고 `tests/` 안에 중첩한다.
- **러너**: 스크립트 언어에 맞춘 경량 러너를 쓰며 외부 의존성이 없도록 지향한다(예: 셸 스크립트면 셸 기반 러너, 파이썬이면 표준 라이브러리 `unittest`).
- **테스트 방식**: 기대 출력과 고정 입력 데이터를 비교하는 방식을 기본으로 한다.
- **배포 제외**: 설치 결과물에는 `tests/` 등 개발 전용 경로를 포함하지 않는다. **무엇을 어떻게 제외하는지(제외 패턴 목록·복사 명령)의 단일 출처는 [`install-skills/SKILL.md`](../../../install-skills/SKILL.md) 설치 절차이며, 이 ADR은 그 목록을 복제하지 않고 참조만 한다**(불일치 방지).

## 근거

세 축의 관심사를 분리하면 위 배치가 자연스럽게 도출된다.

1. **스킬 독립성** — 각 스킬은 단독 실행·단독 설치 가능해야 한다(AI-CONTEXT 의존 금지). 테스트를 스킬 디렉토리 안에 함께 둬야 스킬 단위로 자족적이며, 루트 중앙 집중 시 이 원칙이 깨진다.
2. **점진적 공개** — 번들 리소스(`scripts/`, `tests/`)는 에이전트가 실제로 읽기 전까지 컨텍스트 비용이 0이다. 따라서 같은 디렉토리에 두어도 평상시 추론 비용을 늘리지 않는다.
3. **배포 용량** — 설치는 디렉토리를 통째 복사하므로(`install-skills`), 테스트를 배포에 포함하면 설치 결과물이 불필요하게 커진다. 배포 시 개발 전용 경로를 제거해 용량을 줄인다.

## 대안

- **루트 중앙집중 `tests/`** — 모든 스킬 테스트를 저장소 루트 한 곳에 모으는 방식. 스킬 독립성이 깨지고 설치 시 테스트가 따라오지 않아 채택하지 않았다.
- **제거 단계 생략(테스트를 아예 두지 않거나 전부 배포)** — 전부 배포하면 용량 부담이 커지고, 테스트를 두지 않으면 결정적 헬퍼의 회귀 검증 수단이 사라진다. 배포 시 제거로 두 목표를 동시에 달성한다.
- **JUnit/maven 등 본격 테스트 프레임워크 도입** — 헬퍼 규모(소형 결정적 스크립트) 대비 과한 빌드·의존성 부담이라 채택하지 않았다. 외부 의존성 없는 경량 러너로 충분하다.
