# --local 원본 문서 색인 실행 절차

> `code-map` 스킬의 참조 문서입니다. `--local` 모드에서 SSoT 선언이 원본 문서일 때만 읽습니다.
> 공통 원칙(SSoT, What/How/Why, 태그 체계, 문서 메타데이터)은 [SKILL.md](../SKILL.md)를 따릅니다. 소스 코드 색인 절차([local.md](local.md))는 읽지 않아도 됩니다.

## 트리거 조건

- `--local`로 실행했고, `AI-CONTEXT.md` 본문 2번째 줄(H1 제목과 그 뒤 빈 줄 제외)의 `> SSoT: <값>.` 선언 값이 `원본 문서`일 때
- 선언 값이 `소스 코드`이거나 선언을 찾지 못하면 이 파일 대신 [local.md](local.md)를 따른다

## 파일 구조

```
.ai/60_codebase/
└── index.md    # 원본 문서 파일 지도 (진입점)
```

- 색인 파일은 `index.md` 하나다. 코드의 호출 흐름에 대응하는 구조가 문서에는 없으므로 상세 흐름 파일(`<feature>/<action>-call-flow.md`)은 두지 않는다.
- 색인 대상은 안내도 `## 프로젝트 도메인` 표 `ssot_dir` 행에 적힌 디렉토리(repo 루트 기준 상대 경로, 콤마 나열 가능) 아래 `.md` 파일이다.
- 다른 확장자와 첨부(이미지·PDF 등)의 분류는 repo 문서 규약 파일(`.ai/10_rules/document-convention.md`)이 정한다.
- 첨부는 색인 행을 따로 만들지 않고, 그 첨부를 참조하는 `.md` 파일의 색인 행에 딸린다.
- 퍼블리싱 사본(SSoT를 위키·블로그 등으로 내보낸 사본)과 그 URL은 색인하지 않는다.

frontmatter는 코드 색인의 3키에 색인한 루트 경로 `ssot_dir`을 더한 4키다.

```yaml
---
last_synced: 2026-04-08          # 마지막 동기화 일시
source_hash: a1b2c3d             # 이 색인이 반영한 마지막 커밋 해시
ssot_dir: docs/                  # 색인한 루트 경로 (안내도 ssot_dir 값을 그대로 기록)
status: current | stale | draft  # 문서 상태
---
```

## 실행 절차

### 0단계: 모드 결정

`.ai/60_codebase/index.md`의 색인 생성 여부에 따라 모드를 결정한다.
(ai-workspace init이 템플릿 골격을 index.md로 복사하므로 골격만 있는 파일도 미생성으로 판정한다.)

- **미생성** → `build`(최초 생성) 실행. 파일이 비어 있거나 템플릿 골격만 있는 상태다. 템플릿 골격은 frontmatter가 없고 `## 파일 목록` 표의 행이 자리표시자 `(문서를 추가하면 이 목록에 함께 기재하세요)` 하나뿐인 상태다.
- **생성됨**(미생성이 아닌 모든 상태) → 사용자에게 선택 요청
  - `sync`: 원본 문서 변경분을 색인에 반영
  - `check`: 색인의 정합성 점검
  - `rebuild`: 전체 재생성 (기존 색인 덮어씀, Why 태깅은 보존)

**루트 대조**: `sync`·`check`를 고르면 진입 시 안내도 `## 프로젝트 도메인` 표의 `ssot_dir` 값과 색인 frontmatter의 `ssot_dir` 값을 먼저 대조한다.

- 두 값이 같으면 고른 모드를 그대로 진행한다.
- 안내도 `ssot_dir`이 frontmatter `ssot_dir`과 다르면 루트 불일치다.
  - `sync`는 `rebuild`로 전환한다. Why 태깅은 보존하고, 전환 사실을 사용자에게 알린다.
  - `check`는 3단계의 루트 불일치 판정으로 넘긴다.
- 루트 불일치를 diff로 처리하지 않는 이유: 선언만 바꾼 커밋은 `source_hash` 기준 diff에 안내도 파일만 잡힌다. 새 루트에 원래 있던 문서와 범위에서 빠진 기존 행을 diff로는 찾지 못한다.

---

### 1단계: 원본 문서 색인

`ssot_dir` 아래 `.md` 파일을 읽고 `.ai/60_codebase/index.md`를 생성/업데이트한다.

**1-1. 스캔 범위 결정**

- build / rebuild: 안내도 `ssot_dir` 아래 `.md` 파일 전체
  - 안내도에 `ssot_dir` 행이 없거나 값이 자리표시자(`<...>`)이면 사용자에게 묻는다. 답을 frontmatter `ssot_dir`에 기록하고, 안내도 표에도 같은 값을 채우라고 안내한다.
- sync: 0단계 루트 대조에서 두 값이 같을 때만 수행한다. `git diff <source_hash>..HEAD --name-status -M`으로 변경 유형과 경로를 받는다. 이름 변경(`R`) 행은 이전 경로와 새 경로 중 하나라도 `ssot_dir` 아래 `.md` 파일이면 대상이고, 그 밖의 행은 `ssot_dir` 아래 `.md` 파일만 대상이다.
  - 경로만 출력하는 `--name-only`는 이름 변경의 새 경로만 내준다. 이전 경로를 모르면 옛 행이 3단계 파일 유효성 점검에서 Why 태깅과 함께 지워진다.
- frontmatter의 `ssot_dir`·`source_hash`는 색인 반영을 마친 뒤에만 갱신한다. 중간에 멈춘 실행이 값을 먼저 바꾸면 다음 실행이 반영되지 않은 변경을 놓친다.

**1-2. 색인 단위 식별**

- `.md` 파일 1개가 색인 행 1개다.
- 하위 디렉토리는 행을 묶는 절 제목으로만 쓴다.
- sync 시 변경 목록에서 **삭제된 파일**(`D`)은 해당 행을 index.md에서 제거한다.
- **이름이 바뀐 파일**(`R`)은 이전 경로와 새 경로를 각각 `ssot_dir`과 대조해 처리한다. 확장자가 `.md`가 아닌 경로는 `ssot_dir` 밖과 같게 본다.
  - 두 경로 모두 `ssot_dir` 아래: 새 행을 만들고 옛 행의 Why 태깅을 새 행으로 옮긴 뒤 옛 행을 지운다.
  - 이전 경로만 `ssot_dir` 아래(루트 밖으로 이동): 옛 행을 지운다.
  - 새 경로만 `ssot_dir` 아래(루트 안으로 이동): 새 행을 만든다.

**1-3. index.md 작성**

index.md 머리에 색인 루트를 적고, 문서 파일을 디렉토리별 표로 색인한다:

```markdown
---
last_synced: <동기화 일시>
source_hash: <커밋 해시>
ssot_dir: docs/
status: current
---

# 원본 문서 색인

> 색인 루트: `docs/` (안내도 `## 프로젝트 도메인` 표의 `ssot_dir`)

## docs/policies

| 파일 경로 | 다루는 주제 | 관련 문서 |
|-----------|-------------|-----------|
| `docs/policies/retention.md` | 개인정보 보관 기간과 파기 절차 | [정책](../40_domain/policies/local/retention.md), [ADR-004](../50_adr/active/004-retention-period.md) |
| `docs/policies/refund.md` | 환불 승인 기준 | [WHY-NEEDED] 승인 한도를 정한 근거가 문서화되지 않았습니다. |
```

- `파일 경로`는 repo 루트 기준 경로다.
- `다루는 주제`는 문서의 H1 제목·머리 요약·헤더에서 뽑아 한 줄로 쓴다. 원문을 옮겨 적지 않는다.
- `관련 문서`에는 2단계 기준으로 찾은 `.ai/` 내부 문서만 링크한다. 관련 문서가 없으면 링크 없이 비워둔다(없는 문서를 가리키는 링크를 만들지 않는다).
- 근거 없이 규칙·결정만 적힌 문서는 `관련 문서` 칸에 `[WHY-NEEDED]`로 표시해 사람에게 요청한다. 에이전트는 Why를 자의적으로 생성하지 않는다.

---

### 2단계: 교차 참조 연결

색인에서 `.ai/` 내 다른 디렉토리의 문서를 교차 참조로 연결한다.

| 참조 대상 | 연결 기준 |
|-----------|-----------|
| `30_contract/` | 문서가 외부 API·연동 규약을 다루면, 해당 계약 문서를 링크 |
| `40_domain/specs/` | 문서가 특정 도메인 기능 명세와 관련되면, 해당 문서를 링크 |
| `40_domain/policies/` | 문서가 공통 정책(`common/`) 또는 로컬 정책(`local/`)과 관련되면, 해당 문서를 링크 |
| `50_adr/` | 문서가 담은 결정에 관련 ADR이 있으면, 해당 문서를 링크 |

- **존재하는 문서만 링크한다**. 문서가 없는데 링크를 만들지 않는다.
- 관련 문서가 존재할 것으로 판단되나 아직 작성되지 않은 경우, `[DOC-NEEDED: 40_domain/policies/local/refund.md]` 태그로 표시한다.
- **외부 URL은 교차 참조 대상이 아니다**. 법령·표준 같은 외부 자료는 `40_domain/` 문서의 `근거 출처`·`원본 출처` 섹션에 기재하며, 색인 문서에서 직접 링크하지 않는다.
- 퍼블리싱 URL(안내도 `publish` 행의 위치 포함)도 색인에 두지 않는다.

> 이 단계의 표와 규칙은 [local.md](local.md) 2단계와 같은 내용을 복제해 두었다. 한쪽을 바꾸면 다른 쪽도 맞춘다.

---

### 3단계: 정합성 점검

색인의 정합성을 점검한다. (`check` 모드 선택 시 1~2단계를 건너뛰고 이 단계만 실행한다.)

| 점검 | 설명 |
|------|------|
| 루트 불일치 | 안내도 `ssot_dir`이 frontmatter `ssot_dir`과 다르면 색인 전체를 `[UPDATE-NEEDED]`로 보고하고 rebuild를 권고한다. 색인을 최신으로 보고하지 않는다. |
| stale 탐지 | `source_hash` 이후 `ssot_dir` 아래에서 변경된 `.md` 파일 목록을 조회하여, 해당 파일의 행이 미반영이면 → `[UPDATE-NEEDED]` |
| 파일 유효성 | 색인 행의 파일이 실제로 존재하는지. build·sync·rebuild는 1~2단계에서 삭제·이름 변경을 반영한 뒤이므로 **존재하지 않는 행을 색인에서 자동 제거한다.** `check`는 **행을 지우지 않고 `[UPDATE-NEEDED]`로 보고한다.** 이름 변경 전 행을 먼저 지우면 이어지는 `sync`가 그 행의 Why 태깅을 새 행으로 옮기지 못한다. |
| 범위 밖 행 | 색인 행의 파일 확장자가 `.md`인지. 색인 대상을 `.md`로 좁히기 전 버전이 만든 다른 확장자 행은 sync 변경 목록에 잡히지 않아 남는다. build·sync·rebuild는 1~2단계 반영 뒤 **`.md`가 아닌 행을 색인에서 자동 제거한다.** `check`는 **행을 지우지 않고 `[UPDATE-NEEDED]`로 보고한다.** |
| 교차참조 유효성 | `30_contract`, `40_domain`, `50_adr`로의 링크가 실제로 존재하는지 |
| Why 미태깅 | `[WHY-NEEDED]` 태그가 있는 항목 목록 |
| 문서 누락 | `[DOC-NEEDED]` 태그가 있는 항목 목록 |

---

### 4단계: 결과 보고

사용자에게 요약을 보고한다.

   ```
   ## code-map --local 실행 결과 (원본 문서)

   - 모드: build | sync | check | rebuild (루트 불일치로 전환했으면 sync → rebuild)
   - 색인 루트: <ssot_dir>
   - 문서 색인: N건 (신규 N / 갱신 N / 삭제 N)
   - 교차 참조: 30_contract N건, 40_domain N건, 50_adr N건
   - [WHY-NEEDED]: N건
   - [DOC-NEEDED]: N건
   - [UPDATE-NEEDED]: N건

   > 진입점: .ai/60_codebase/index.md
   ```
