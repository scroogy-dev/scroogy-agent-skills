# 70_ledger 인덱스

이 디렉토리는 수용한 기술부채·known issue를 항목 단위로 보관합니다.
AI는 작업 시 이 파일을 먼저 읽고, 관련된 항목만 선택적으로 읽어옵니다.

등재 주체는 issue-work `--response`(감사 리포트에서 이관으로 정한 발견)와 git-pr-feedback(수용 — 원장 등재)입니다.
항목 파일 형식은 같은 디렉토리의 `ledger-entry-template.md`를 따릅니다. 등재 주체가 둘이라 어느 스킬에도 두지 않고 원장 골격과 함께 배포합니다.

## 수명 주기

등재(수용) → 재검토 → 종결(승격 또는 해소)의 한 방향으로 흐릅니다.

| 단계 | 상태 값 | 위치 | 계기와 수행 주체 |
|------|---------|------|------|
| 등재 | `수용` | `active/` | issue-work `--response`의 이관, git-pr-feedback의 수용 — 원장 등재 |
| 재검토 | `수용` 유지 | `active/` | 항목의 `재검토 조건` 충족 — issue-audit이 `기등재 K-<번호> 재제기`로 올리거나 git-pr-feedback이 같은 지적을 다시 받을 때. 재제기를 받은 스킬이 판단 결과를 항목의 `재검토 이력` 표에 남긴다 |
| 종결(승격) | `승격(이슈 #N)` | `archive/` | 재검토 결과 지금 고쳐야 한다고 판단 — 재제기를 처리한 스킬(issue-work `--response` / git-pr-feedback)이 이슈를 만들고 그 번호를 상태에 적는다 |
| 종결(해소) | `해소(PR #N)` | `archive/` | 원인이 사라짐 — 원인을 고친 작업의 스킬이 해소한 PR 번호를 상태에 적는다 |

- 상태가 `승격`·`해소`로 바뀐 항목은 `active/`에서 `archive/`로 옮기고 위 항목 목록을 함께 갱신합니다.
- 재검토·종결은 **새 항목을 만들지 않고 기존 항목을 갱신**합니다. 같은 결함에 새 `K` 번호를 따면 원장이 중복 보고를 막지 못하고, 갱신을 빠뜨리면 이미 해결된 항목이 `active/`에 남아 이후 감사의 억제 기준이 됩니다.
- 번호는 `active/`·`archive/`를 합쳐 가장 큰 번호 + 1로 채번합니다. archive를 빼고 세면 청산된 항목의 번호를 재사용하게 되어 출처 추적이 깨집니다.
- `active/`의 `수용` 항목만 issue-audit의 기등재 대조 대상입니다. 재검토 조건이 충족되지 않은 항목은 감사에서 신규 발견으로 다시 보고되지 않습니다. 이 대조가 같은 발견의 반복 보고를 막는 지점입니다.

### 상태별 처리 (같은 결함이 다시 올라왔을 때)

원장의 소비자(issue-audit·git-pr-feedback)는 일치 항목의 상태에 따라 아래와 같이 갈라 처리합니다. 상태를 보지 않고 "원장에 이미 있음"으로만 판단하면, 한쪽은 회귀를 억제하고 다른 쪽은 종결한 항목을 다시 손대 원장 상태가 어긋납니다.

| 일치 항목의 상태·위치 | issue-audit | git-pr-feedback |
|------|------|------|
| `수용` (`active/`) · 재검토 조건 미충족 | 기등재 참조로만 적고 위험도 집계에서 제외 | 새로 등재하지 않고 기존 항목의 `재검토 이력`에 재확인 기록 (원인이 사라졌으면 아래 종결이 우선) |
| `수용` (`active/`) · 재검토 조건 충족 | `기등재 K-<번호> 재제기` 계보의 신규 발견 | 기존 항목을 갱신 — 계속 수용이면 이력·조건 갱신, 종결이면 상태 변경 + `archive/` 이관 |
| `승격(이슈 #N)` (`archive/`) · 연결 이슈가 열려 있음 | 기등재 참조로만 적고 집계에서 제외 (추적처가 이슈로 옮겨진 상태) | 등재하지 않고 연결된 이슈로 안내 |
| `승격(이슈 #N)` (`archive/`) · 연결 이슈가 닫힘 | `K-<번호> 재발` 계보의 신규 발견 | 새 번호로 등재하고 `출처`에 `K-<번호> 재발` 병기 |
| `해소(PR #N)` (`archive/`) · 결함 재등장 | `K-<번호> 재발` 계보의 신규 발견 | 새 번호로 등재하고 `출처`에 `K-<번호> 재발` 병기 |

- 억제 범위를 `active/수용`과 추적 중인 `승격`으로 한정해야 회귀가 집계에서 사라지지 않습니다. `해소` 항목의 재발은 이미 청산한 결함의 회귀이므로 억제 대상이 아닙니다.
- 연결 이슈의 개폐를 확인할 수단이 없으면 `승격` 항목은 참조 처리를 유지합니다. 확인 실패를 재발 판정으로 바꾸지 않습니다.
- 재발로 판정한 항목은 종결된 항목을 되살리지 않고 **새 번호로 등재**합니다. 되살리면 청산 이력이 흐려지고, 회귀는 이번 판단으로 새로 안고 가는 부채라 수용 사유·재검토 조건을 다시 정해야 합니다.
- 종결(`해소`)은 **재검토 조건 충족 여부와 독립**입니다. 원인이 사라진 항목은 조건이 미충족이어도 `해소(PR #N)`으로 종결해 `archive/`로 옮깁니다. 재검토 조건은 계속 수용할지 다시 볼 시점의 기준이지 종결의 전제가 아닙니다. 종결 주체는 원인을 고친 작업의 스킬이며, 그 스킬에서 원장 등재를 함께 선택했는지와 무관합니다.
