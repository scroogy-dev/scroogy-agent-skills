# 70_ledger 인덱스

이 디렉토리는 수용한 기술부채·known issue를 항목 단위로 보관합니다.
AI는 작업 시 이 파일을 먼저 읽고, 관련된 항목만 선택적으로 읽어옵니다.

등재 주체는 issue-work `--response`(감사 리포트에서 이관으로 정한 발견)와 git-pr-feedback(수용 — 원장 등재)입니다.
항목 파일 형식은 issue-work `templates/ledger-entry-template.md`를 따릅니다.

## 파일 목록

| 파일 | 설명 |
|------|------|
| `active/` | 살아 있는 부채 — 아직 수용 상태인 항목 |
| `archive/` | 청산한 부채 — 승격 또는 해소로 종결된 항목 |

## 항목 목록

| 번호 | 제목 | 유형 | 위험도 | 상태 | 재검토 조건 |
|------|------|------|--------|------|-------------|
| (항목을 등재하면 이 목록에 함께 기재하세요) | | | | | |

## 수명 주기

등재(수용) → 재검토 → 종결(승격 또는 해소)의 한 방향으로 흐릅니다.

| 단계 | 상태 값 | 위치 | 계기 |
|------|---------|------|------|
| 등재 | `수용` | `active/` | issue-work `--response`의 이관, git-pr-feedback의 수용 — 원장 등재 |
| 재검토 | `수용` 유지 | `active/` | 항목의 `재검토 조건` 충족 — 판단 결과를 항목의 `재검토 이력` 표에 남긴다 |
| 종결(승격) | `승격(이슈 #N)` | `archive/` | 재검토 결과 지금 고쳐야 한다고 판단 — 이슈를 만들고 그 번호를 상태에 적는다 |
| 종결(해소) | `해소(PR #N)` | `archive/` | 다른 작업으로 원인이 사라짐 — 해소한 PR 번호를 상태에 적는다 |

- 상태가 `승격`·`해소`로 바뀐 항목은 `active/`에서 `archive/`로 옮기고 위 항목 목록을 함께 갱신합니다.
- 번호는 `active/`·`archive/`를 합쳐 가장 큰 번호 + 1로 채번합니다 — archive를 빼고 세면 청산된 항목의 번호를 재사용하게 되어 출처 추적이 깨집니다.
- `active/` 항목은 issue-audit의 기등재 대조 대상입니다. 재검토 조건이 충족되지 않은 항목은 감사에서 신규 발견으로 다시 보고되지 않습니다 — 이 대조가 같은 발견의 반복 보고를 막는 지점입니다.
